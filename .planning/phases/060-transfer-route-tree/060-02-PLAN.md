<architecture_decision>
**D-07 horizon lift (RESEARCH.md Open Question 1, Pitfall 4, A2; CONTEXT.md D-07):**

CONTEXT.md D-07 locks horizon state at the Plan section level: "shared with the section-level `HorizonSelector` in `page.tsx`. Changing the horizon in any Plan sub-tab affects all of them including Route Tree." Today, PlannerTab and ManualPlanTab each manage their own local horizon state — this plan implements D-07 fully by lifting horizon to `page.tsx`.

**Implementation:**
1. `page.tsx` adds `[planHorizon, setPlanHorizon] = useState<PlannerHorizon>(3)` state.
2. `page.tsx` renders a section-level `<HorizonSelector>` immediately above the Plan sub-tab nav (only when `activeSection === 'plan'`).
3. `PlannerTab` accepts a `horizon: PlannerHorizon` prop, drops its `useState<PlannerHorizon>` and the local `<HorizonSelector>` render at line 341.
4. `ManualPlanTab` accepts a `horizon: PlannerHorizon` prop, removes the local `<HorizonSelector>` at line 327, and adds a `useEffect` that syncs `plan.horizon` to the prop whenever the prop changes (preserving Phase 59's localStorage persistence semantics — the prop is the new source of truth, but the persisted plan still tracks it).
5. `RouteTreeTab` accepts a `horizon: PlannerHorizon` prop and consumes it directly in the `useMemo` for `buildTransferRouteTree` — no local horizon state, no local HorizonSelector. UI-SPEC §Reused Components is HONORED (not overridden).

This is the path the user explicitly chose in CONTEXT.md D-07. It satisfies TRT-07 across all three sub-tabs simultaneously. Document this in `060-02-SUMMARY.md`.

**chipMode (Pitfall 5, A3, TRT-06):** RouteTreeTab passes `chipMode: null` to the engine (constant — no UI ChipToggle in this tab per UI-SPEC §Reused Components; section-level chip lift is deferred to a future phase per RESEARCH Open Question 2). TRT-06 is satisfied at the engine level (Plan 01 Tests E1–E4); UI exposure is deferred per RESEARCH.md A3.

**ManualPlanTab horizon sync semantics:** Phase 59 persists `plan.horizon` to `fplx_manual_plan` localStorage. With D-07 lifting horizon to page.tsx, the prop becomes the source of truth and `plan.horizon` is a downstream mirror. The sync effect runs `if (plan.horizon !== horizonProp) updatePlan(draft => { draft.horizon = horizonProp; draft.steps = truncateOrExtendSteps(...) })` so persisted plans still reflect the active horizon. On mount, page.tsx initialises `planHorizon` from `loadManualPlan()?.horizon ?? 3` so a previously-saved plan's horizon survives a page reload.
