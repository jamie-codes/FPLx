# Phase 48 — UI Design Contract: Explainable xPts Breakdown

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope

This contract covers the single new UI element introduced in Phase 48: the **xPts hover card** rendered inside `XPtsCell` in GemTable's `xPts_1gw` column. No other views are in scope (PlayerComparisonModal is explicitly deferred — see CONTEXT.md §Deferred).

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Tailwind class | px value | Usage in this phase |
|-------|---------------|----------|---------------------|
| xs | p-1 / gap-1 | 4px | Icon gaps, inline badge padding |
| sm | p-2 / gap-2 | 8px | Hover card internal padding; row gap between breakdown rows |
| md | p-4 | 16px | Not used in hover card (too wide for cell-anchored panel) |
| lg | p-6 | 24px | Not used in this phase |
| xl | — | 32px | Not used in this phase |

**Hover card specific:**
- Internal padding: `p-2` (8px all sides)
- Row spacing: single `flex justify-between` rows — no extra margin between rows
- Divider margin: `my-1` (4px top + 4px bottom)
- MinsRiskBadge top margin: `mt-1` (4px)
- Card offset from trigger cell: `mb-1` (4px) — gap between bottom of card and top of cell

**Exceptions:**
- Touch target minimum 44px applies to the cell wrapper on mobile (`min-h-[44px]` is already the existing table row pattern). The hover card wrapper itself does not need a 44px minimum — it is a display panel, not a tap target.

|------|------|--------|------|-------------|-------|

| Hover card label | 12px (text-xs) | 400 (normal) | Geist Sans | 1.5 | Left column labels ("Appearance", "Goals", etc.) |

**Tailwind classes:**

- Value: `text-xs font-mono`

**Constraint:** Do not introduce any font size below 12px (text-xs) — existing smallest token. Do not add a third font weight; the two declared weights (400, 600) cover all hover card needs.

## Color

| Role | Light mode | Dark mode | Usage |
|------|-----------|-----------|-------|
| Dominant surface (60%) | `#ffffff` (bg-white) | `bg-zinc-900` (#18181b) | Page background, table rows, sticky web_name column |
| Secondary surface (30%) | `bg-zinc-100` / `bg-gray-50` | `bg-zinc-800` (#27272a) | Even table rows, badge backgrounds, hover card panel background |
| Hover card border | `border-zinc-200` | `border-zinc-700` | 1px border around hover card panel |
| Hover card divider | `border-zinc-200` | `border-zinc-600` | `<hr>` separator above Total row |
| Accent — muted label text (10%) | `text-zinc-500` | `text-zinc-400` | Hover card row labels (non-total) |
| Accent — body text | `text-zinc-900` / `#171717` | `text-zinc-100` | Cell values, Total row text |
| Destructive | `text-red-600` | (not applicable in hover card) | Not used in this phase |

**Accent reserved for:** The hover card introduces no new accent colour. Muted label text (`text-zinc-500 dark:text-zinc-400`) is purely a de-emphasis token, not an interactive accent. The existing MinsRiskBadge carries its own semantic colour per badge variant (green/blue/amber/zinc) — these are pre-existing and not extended in this phase.

**Hover card panel exact class string:**
```
bg-white dark:bg-zinc-800 border border-zinc-200 dark:border-zinc-700 rounded shadow-lg
```
This matches the existing PlayerComparisonModal panel pattern (`bg-white dark:bg-zinc-900 border border-zinc-200 dark:border-zinc-700 shadow-lg`) exactly, except the hover card uses `bg-zinc-800` (not `bg-zinc-900`) in dark mode for a slight elevation contrast against the table row (`bg-zinc-800` even rows, `bg-zinc-900` base).

## Component Anatomy: xPts Hover Card

### Trigger wrapper
```
div.relative.group/xpts.inline-block.cursor-help
  onClick → toggles open state (mobile touch)
```

### Visible cell content (always shown)
```
span
  {xPts_1gw.toFixed(1)}
  <VarianceBadge ceiling={ceiling} />   ← existing, unchanged
```

### Hover card panel (conditionally visible)
Visibility rule:
- Default: `invisible opacity-0`
- Desktop hover: `group-hover/xpts:visible group-hover/xpts:opacity-100 transition-opacity`
- Mobile tap (open state true): `visible opacity-100` (class appended conditionally)
- BGW (components === null): panel is not rendered at all

Position:
```
absolute bottom-full left-0 mb-1 w-44 z-50
```
- `bottom-full` — card appears above the cell (avoids table overflow-x cutting off a card positioned to the right)
- `left-0` — aligns card left edge with cell left edge
- `w-44` — 176px fixed width; wide enough for 5-char labels + 4-char values (e.g. "Clean sheet 2.34")
- `z-50` — floats above sticky `web_name` column (`z-10`) and table header (`z-20`/`z-30`)

**Known limitation (accepted):** Rows near the top of the visible viewport may clip the card above the fold. Floating UI is excluded by D-04. This is acceptable for the initial implementation.

### Panel internal layout

```
div (flex flex-col, p-2, text-xs)
  ├── Row: Appearance    | {appearance_pts.toFixed(2)}
  ├── Row: Goals         | {goal_pts.toFixed(2)}
  ├── Row: Assists       | {assist_pts.toFixed(2)}
  ├── Row: Clean sheet   | {cs_pts.toFixed(2)}
  ├── Row: Bonus         | {bonus_pts.toFixed(2)}
  ├── hr (divider)
  ├── Row: Total         | {(sum of 5 components).toFixed(2)}  [semibold]
  └── MinsRiskBadge      (self-suppresses for null/injured; mt-1)
```

Each data row: `div.flex.justify-between`
- Left: `span.text-zinc-500.dark:text-zinc-400` — label
- Right: `span.font-mono` — value

Total row: `div.flex.justify-between.font-semibold`
- Left: `span` — "Total"
- Right: `span.font-mono` — computed sum

**Critical:** The Total row value is `(appearance_pts + goal_pts + assist_pts + cs_pts + bonus_pts).toFixed(2)` computed in the render function — NOT `xPts_1gw.toFixed(2)` (which is already `.toFixed(1)` in the cell). This satisfies XPT-02: the hover card is self-consistent regardless of any floating-point rounding at the pipeline boundary.

### MinsRiskBadge placement
Rendered as a `div.mt-1` child below the Total row, inside the panel `div`. The badge component is stateless and self-suppresses (returns null) for `minsRisk === 'injured'` or `minsRisk === null/undefined`. No conditional check needed at the call site.

## Interaction States

| State | Trigger | Visual |
|-------|---------|--------|
| Default | — | Cell shows `{xPts.toFixed(1)}` + VarianceBadge. Hover card invisible. |
| Hover (desktop) | `mouseover` on cell wrapper | Hover card fades in via `group-hover/xpts:opacity-100 group-hover/xpts:visible`. Cursor: `cursor-help`. |
| Open (mobile) | `tap` on cell wrapper | `open` state flips to true; `visible opacity-100` class applied imperatively. |
| Close (mobile) | `tap` on cell wrapper again | `open` state flips to false; card reverts to invisible. |
| BGW (no card) | `xPts_components_1gw === null` | No hover card rendered. Cell shows "0.0" per existing short-circuit. Cursor: default. |
| 3GW/5GW window | `window !== 1` | No hover card rendered even if components passed. Existing `showBreakdown` guard. |

**Touch close-on-outside-click:** Not implemented in this phase. Users tap another row naturally. This is a UX polish item, not a Phase 48 requirement.

**Transition:** `transition-opacity` duration uses Tailwind default (150ms). No additional animation.
