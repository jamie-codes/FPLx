## Component Specifications

### WHY-01-A: TransferPanel — "Why isn't X recommended?" Search Field + Callout

**Trigger:** Always rendered when `TransferPanel` mounts, independent of squad load state.

**Placement:** Above the OCS section. The render order in `TransferPanel` JSX is:
1. Load Squad form card (existing)
2. Loading / error states (existing, conditional)
3. Squad display (existing, conditional on squadData)
4. CaptaincyPanel (existing, conditional)
5. **[NEW] `RejectionSearchCallout` — always visible above OCS**
6. HighOwnershipCallout (existing, conditional)
7. OCS section card (existing, conditional)

Note: per CONTEXT.md D-08, the callout appears between the search field and the OCS — the OCS is never hidden. The search + callout are wrapped together as one unit (`RejectionSearchCallout`).

**Component name (Claude's discretion):** `RejectionSearchCallout` — describes the trigger action and output type. Lives at `src/components/transfers/RejectionSearchCallout.tsx`.

**Search field container:**
```
<div className="rounded border border-zinc-200 dark:border-zinc-700 p-4 space-y-4">
  <label className="text-sm font-medium text-zinc-700 dark:text-zinc-300">
    Why isn't a player recommended?
  </label>
  <input
    type="text"
    placeholder="Search player name…"
    className="border border-zinc-300 dark:border-zinc-600 rounded px-4 py-2 text-sm
               text-zinc-900 dark:text-zinc-100 bg-white dark:bg-zinc-800
               focus:outline-none focus:ring-1 focus:ring-zinc-400 w-full"
  />
  {/* Dropdown suggestion list — rendered below input when query.length >= 2 */}
  {/* Callout result — rendered below input after selection */}
</div>
```

**Autocomplete dropdown:**
- Renders only when query length >= 2 characters (debounce: 150ms — Claude's discretion)
- Background: `bg-white dark:bg-zinc-800 border border-zinc-200 dark:border-zinc-700 rounded shadow-sm`
- Each suggestion: `px-4 py-2 text-sm text-zinc-700 dark:text-zinc-300 hover:bg-zinc-100 dark:hover:bg-zinc-700 cursor-pointer`
- Match on `web_name` and full name; show `web_name` in list items
- Maximum 6 suggestions visible (scroll if more)
- Scope: all `scoredPlayers` passed as prop (full ~750 player list; no new fetch)

**Explanation callout (after player selected):**

Renders between the search input and the OCS — reuses the `RejectionPanelInline` structure from Phase 65:

```
<div className="rounded border border-zinc-200 dark:border-zinc-700 bg-zinc-50 dark:bg-zinc-800 p-4 space-y-1">
  <p className="text-sm font-medium text-zinc-700 dark:text-zinc-300">
    ℹ️ Why isn't [web_name] recommended?
  </p>
  {/* reasons.length === 0 — positive framing */}
  <p className="text-xs text-green-700 dark:text-green-400">
    No rejection signals — ranked #X at [POS] by xPts (Y.Y pts projected)
  </p>
  {/* reasons.length > 0 — rejection list */}
  <p className="text-xs font-medium text-zinc-500 dark:text-zinc-400">Why not recommended:</p>
  <ul className="space-y-1">
    <li className="text-xs text-zinc-600 dark:text-zinc-400">[reason line]</li>
  </ul>
</div>
```

**Dismissal:** An `×` dismiss button (top-right of callout or end of header line) clears the selected player and hides the callout. No dismiss needed for the search field itself — it persists.

Dismiss button: `text-xs text-zinc-400 dark:text-zinc-500 cursor-pointer` matching existing GemTable action-sheet dismiss style (line 324–328).

### WHY-01-B: GemTable — "Compare with…" Head-to-Head Inside Row Expand

**Placement:** Inside the existing row-expand panel, below the existing `RejectionPanelInline` and `FragilityBadge`. Applies to both the desktop expand row and mobile expand row.

**Component name (Claude's discretion):** `ComparisonSearch` — inline sub-component within `GemTable.tsx` or extracted to `src/components/gem-table/ComparisonSearch.tsx`. Shared `PlayerSearchInput` base component is acceptable if builder chooses to unify with TransferPanel's search (Claude's discretion per CONTEXT.md).

**Search field:**
```
<div className="mt-2 space-y-1">
  <p className="text-xs font-medium text-zinc-500 dark:text-zinc-400">Compare with…</p>
  <input
    type="text"
    placeholder="Search player name…"
    className="border border-zinc-300 dark:border-zinc-600 rounded px-4 py-2 text-xs
               text-zinc-900 dark:text-zinc-100 bg-white dark:bg-zinc-800
               focus:outline-none focus:ring-1 focus:ring-zinc-400 w-full"
  />
</div>
```

Note: uses `text-xs` (12px) to match the surrounding expand panel typography, not `text-sm`.

**Autocomplete dropdown:** Same behavior as WHY-01-A but rendered inline within the expand row. Background: `bg-white dark:bg-zinc-800 border border-zinc-200 dark:border-zinc-700 rounded shadow-sm`.

**Head-to-head output (after comparison player selected):**

Shows only predicates where X (the row player) beats Y (the comparison player). Narrative sentence style matching ROADMAP example:

```
<div className="mt-2 space-y-1">
  <p className="text-xs font-medium text-zinc-500 dark:text-zinc-400">
    Why [X.web_name] ranks above [Y.web_name]:
  </p>
  {/* If X beats Y on >= 1 predicate — narrative sentence */}
  <p className="text-xs text-zinc-600 dark:text-zinc-400">
    [X.web_name] is ranked higher because: [delta list].
  </p>
  {/* If X beats Y on 0 predicates */}
  <p className="text-xs text-zinc-600 dark:text-zinc-400">
    No predicates where [X.web_name] ranks above [Y.web_name].
  </p>
</div>
```

Delta list is comma-separated inline (narrative prose), not a `<ul>`. This matches the ROADMAP example style: "higher xPts (+1.2), better fixture (easy vs medium), lower fragility tier".

## Accessibility

- Search inputs: `<label>` elements or `aria-label` on `<input>` — both entry points require a programmatic label
- WHY-01-A search: `<label htmlFor="rejection-search">` or `aria-label="Search player for rejection explanation"`
- WHY-01-B search: `aria-label="Search comparison player"` (inline label `<p>` is not a programmatic label — must supplement with aria-label)
- Dismiss button: `aria-label="Dismiss explanation"` (× is not screen-reader safe without label)
- Autocomplete dropdown: role `listbox` + `option` per ARIA combobox pattern, or `role="list"` + `role="listitem"` for simple list; builder chooses simpler pattern
- All result text is plain text in `<p>` / `<li>` — screen-reader accessible without additional ARIA
- Touch targets: search inputs exceed 44px height when combining `py-2` + `text-sm` line height; dismiss × button must be at minimum `24px × 24px` clickable area
