## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`, `px-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `px-2`, `py-2`) |
| md | 16px | Default element spacing (`gap-4`, `p-4`, `space-y-4`) |
| lg | 24px | Section padding (`space-y-6`, `mt-6`) |
| xl | 32px | Layout gaps (`space-y-8`) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (carried forward + new):

- **Touch targets:** `min-h-[44px]` on all interactive buttons (sell/buy dropdown triggers, "Compare" button, tab pills). Satisfies WCAG 2.5.5 (≥44px). Matches all prior Plan sub-tab phases.
- **Chart container:** fixed height `h-64` (256px = 64 × 4) on mobile, `h-72` (288px = 72 × 4) on `sm:` and above. Height is always a multiple of 4. Applied via Tailwind class (static value); dynamic chart content uses inline styles where Tailwind dynamic classes would not work (established pattern — Tailwind dynamic classes forbidden, Phase 58 Pitfall 4).
- **Dropdown select inputs:** `px-3 py-2` (12px / 8px) for compact selects — matches input pattern from `TransferPanel` and Phase 58 League ID input.
- **Rank header row:** `px-4 py-3` (16px / 12px) for the current-rank context block — slightly larger to give it visual prominence above the chart.

Source: `058-UI-SPEC.md`; `060-UI-SPEC.md`; `src/components/planner/RouteTreeTab.tsx`; `src/components/captaincy/CaptainPicksPanel.tsx`.

#### Fan Chart — Recharts implementation notes

Use `<AreaChart>` with `<ResponsiveContainer width="100%" height={256}>` (256px = mobile height). On `sm:` screens use 288px. These are static values passed as integers, NOT Tailwind classes (Recharts `height` prop takes a number).

Chart data shape: array of 6 objects (GW+0 as origin, GW+1–GW+5 as data points):

```ts
type ChartPoint = {
  gw: string      // "Start" | "GW+1" | ... | "GW+5"
  mean: number    // cumulative mean score for current XI
  p10: number     // cumulative p10 floor
  p90: number     // cumulative p90 ceiling
  altMean?: number // cumulative mean for alt XI (undefined until alt is selected)
}
```

GW+0 (origin point): `{ gw: 'Start', mean: 0, p10: 0, p90: 0, altMean: 0 }` — both lines start at 0 so divergence is visible from GW+1.

Recharts components:

```tsx
<CartesianGrid strokeDasharray="3 3" stroke="rgba(161,161,170,0.3)" />

<XAxis
  dataKey="gw"
  tick={{ fontSize: 12, fill: 'currentColor' }}
  axisLine={false}
  tickLine={false}
/>

<YAxis
  tick={{ fontSize: 12, fill: 'currentColor' }}
  axisLine={false}
  tickLine={false}
  width={32}
/>

{/* Confidence band — current XI only */}
<Area
  type="monotone"
  dataKey="p90"
  stroke="none"
  fill="rgba(161,161,170,0.25)"
  fillOpacity={1}
  legendType="none"
  activeDot={false}
  tooltipType="none"
  isAnimationActive={false}
/>
<Area
  type="monotone"
  dataKey="p10"
  stroke="none"
  fill="rgba(255,255,255,1)"  {/* Erases lower part of p90 fill to produce a band */}
  fillOpacity={1}
  legendType="none"
  activeDot={false}
  tooltipType="none"
  isAnimationActive={false}
/>

{/* Current XI mean — solid zinc */}
<Line
  type="monotone"
  dataKey="mean"
  stroke="var(--color-foreground)"
  strokeWidth={2}
  dot={false}
  isAnimationActive={false}
/>

{/* Alt XI mean — dashed amber (conditional) */}
{altXIComputed && (
  <Line
    type="monotone"
    dataKey="altMean"
    stroke="#f59e0b"
    strokeWidth={2}
    strokeDasharray="5 3"
    dot={false}
    isAnimationActive={false}
  />
)}
```

Note on the confidence band technique: Recharts `<Area>` stacking. Use `p90` fill as the upper area, then overlay `p10` with a solid white fill to "cut out" the lower portion, leaving only the band between p10 and p90 visible. This approach avoids the `referenceLine` clipping issues with Recharts v2. In dark mode, the `p10` erase-fill must match the dark canvas color `#0a0a0a` — use a CSS custom property: `fill="var(--background)"`.

`isAnimationActive={false}` on all lines — matches project convention (no gratuitous animation on data surfaces). The chart re-renders on XI selection changes; animation would cause visual confusion.

## Interaction Contracts

### Tab activation — Rank Sim

1. User clicks "Rank Sim" sub-tab in the Plan section nav (or "Rank Sim" on mobile — same label both breakpoints per CONTEXT.md D-15).
2. `activeSection === 'plan' && activeSubTab === 'rank-sim'` evaluates true.
3. `RankSimTab` mounts; reads squad from `useSquad(submittedId)` + `useMyTeam(isAuthenticated)`, reads rank from `useEntryRank(teamId)`, reads players from `usePlayers()`.
4. Squad picks null → render no-squad branch. Squad picks available → compute 5-GW trajectory and render chart.

### No-squad degradation (SC-05 pattern)

When no squad is loaded (`picks === null`):

```
<div className="rounded border border-zinc-200 dark:border-zinc-700 bg-zinc-50 dark:bg-zinc-800 px-4 py-6 text-center">
  <p className="text-sm font-semibold text-zinc-900 dark:text-zinc-100">
    Load your squad to run the rank simulator
  </p>
  <p className="text-xs text-zinc-500 dark:text-zinc-400 mt-1">
    Go to the Squad tab and enter your FPL Team ID to get started.
  </p>
</div>
```

No Team ID input in this component — the Squad tab owns authentication/squad loading. This is a passive prompt, not an input form.

### Rank fetch states

- **Loading:** rank context block renders with `—` in the rank value slot; P(rank gain) and P(rank drop) show `—` with `text-zinc-500` (neutral). Stats compute as soon as squad picks are available, even if rank is still loading.
- **Rank unavailable (teamId null or hook disabled):** Same as loading display — em-dash. Add title tooltip: `"Rank data requires your FPL Team ID."`
- **Rank fetch error:** `—` in rank slot; add `text-xs text-red-600 dark:text-red-400` note below: `"Could not load rank — check your Team ID."`

### Transfer comparison — dropdown interaction

1. User selects a player from the Sell dropdown.
2. Buy dropdown becomes enabled. Its option list filters to: same position as sold player, not already in squad, sorted by `xPts_1gw` descending.
3. User selects a player from the Buy dropdown.
4. `altXI` is computed: current squad with sold player replaced by bought player. `altMean` values computed over 5 GWs.
5. Chart re-renders with the dashed amber alt XI mean line. Legend row shows both entries.
6. The stat block (current rank / P values) does NOT update — it always reflects the current XI. The chart visual makes the comparison self-evident.

Clearing the comparison: User clicks the "Clear comparison" text link. Both dropdowns reset to placeholder. Alt XI line removed from chart. Legend entry for alt XI hidden.

Selling the captain: If the player selected as "Sell" is the current captain, the captain contribution doubles for the remaining players' highest-xPts pick in the alt XI. The label in the chart legend shows "Alt XI (new captain: [web_name])". Implementation detail — executor to determine new captain for alt XI as: highest `xPts_1gw` in alt XI squad (excluding the new buy's first week if desired).

### Chart tooltip

Custom `<Tooltip content={<CustomTooltip />}>`:

```tsx
function CustomTooltip({ active, payload, label }: TooltipProps<number, string>) {
  if (!active || !payload?.length) return null
  return (
    <div className="rounded border border-zinc-200 dark:border-zinc-700
                    bg-white dark:bg-zinc-900 px-3 py-2 text-xs shadow-sm">
      <p className="font-semibold text-zinc-900 dark:text-zinc-100 mb-1">{label}</p>
      {payload.map((entry) => (
        <p key={entry.name} style={{ color: entry.color }}>
          {entry.name}: {entry.value?.toFixed(1)} pts
        </p>
      ))}
    </div>
  )
}
```

Tooltip is suppressed for the confidence band area entries (those Area components get `tooltipType="none"` — Recharts v2 prop). Only the mean line(s) appear in the tooltip.

### EO mode toggle — MC label interaction

MC labels update when EO mode changes only in the sense that the candidate list order can change. The priority cascade for MC labels (`computeMCLabels`) runs over the current 5 EO candidates regardless of mode — it always assigns labels based on MC field values, not EO sort order. So the badges follow the player, not the rank slot.

When `differential_aggressive` mode returns fewer than 3 candidates, MC labels are assigned from the reduced candidate set (still greedy cascade, just fewer players competing).

### TC callout visibility

- **MC fields present** (`haul_prob !== undefined && haul_prob !== null` on at least one candidate): TC callout renders.
- **MC fields absent:** TC callout is not rendered. No empty state, no placeholder — the section simply doesn't exist in the DOM.

Load-bearing copy conventions carried forward (unchanged from all prior phases):

- **Em-dash `—`** for null / unavailable values (NOT empty string, NOT "N/A").
- **Tilde `~`** suffix on P(rank gain) and P(rank drop) labels to signal approximation (Claude's Discretion — `~` is more compact than appending "est." or a footnote).
- **Percentage format:** integer percent (e.g. `41%`, `62%`) — no decimal places on probability stats. Consistent with `haul_prob × 100` rounded format from CONTEXT.md D-18.
- **Points format:** one decimal place (e.g. `14.2 pts`, `4.8 pts`) on MC badge ceiling/floor values. Consistent with `xPts` display elsewhere in the app.
- **"Rank Sim"** — short form (4+3 chars, fits mobile pill width). Full "Rank Simulator" used only in the heading inside the tab. Source: CONTEXT.md D-15.
- **"TC:"** bold prefix followed by plain text — mirrors the in-sentence label style of CONTEXT.md specifics §TC callout format.
- **"P(rank gain)" / "P(rank drop)"** — parenthetical notation, no space before `(`. Consistent with FPL analytical convention.

## States Required

### `RankSimTab`

| State | Trigger | UI Response |
|-------|---------|-------------|
| No squad | `picks === null` | Empty-state heading + body only. No chart, no stats, no dropdowns. |
| Loading — hooks pending | `isLoading === true` (players or squad) | Inline `text-sm text-zinc-500`: `Loading…` replacing chart region. Stats block shows `—` values. |
| Squad loaded, rank loading | `picks !== null && rankLoading` | Stats block: rank value shows `—` (zinc-500); P values compute immediately from squad data while rank fetches. |
| Squad loaded, rank available | `picks !== null && rank !== null` | Full UI: stats block + fan chart + comparison dropdowns. |
| Squad loaded, rank unavailable | `picks !== null && rank === null && !rankLoading` | Stats block: rank shows `—` with rank error note. Chart still renders (rank not needed for trajectory). |
| No alt XI selected | `sell === null \|\| buy === null` | Single solid zinc mean line + confidence band on chart. Legend shows "Current XI" only. |
| Alt XI defined | `sell !== null && buy !== null` | Dashed amber alt XI mean line added to chart. Legend shows both entries. |
| Alt XI — sold player is captain | `sell.id === captainId` | Legend updates to "Alt XI (new captain: [new_cap.web_name])". |

### MC labels in `CaptainPicksPanel`

| State | Trigger | UI Response |
|-------|---------|-------------|
| MC fields absent | `haul_prob === undefined` on all candidates | No MC badges rendered. TC callout hidden. `CandidateRow` unchanged from Phase 57. |
| MC fields present | At least one candidate has `haul_prob !== undefined` | `computeMCLabels` runs; up to 3 badges assigned. TC callout renders above candidate list. |
| Differential mode — fewer than 3 candidates | `candidates.length < 3` | MC labels assigned from available candidates only; fewer than 3 badges may appear. |
| Differential mode — 0 candidates | `candidates.length === 0` | Existing empty-state copy renders; no MC labels. TC callout hidden. |

### Rank fetch states (`useEntryRank` hook)

| State | Trigger | UI Response |
|-------|---------|-------------|
| Disabled | `teamId === null` | Hook returns `{ data: null, isLoading: false }`. Rank slot shows `—`. |
| Loading | `teamId !== null && isFetching` | Rank slot shows `—` (zinc-500). |
| Success | `data.summary_overall_rank !== undefined` | Rank slot shows formatted rank `#N,NNN,NNN`. |
| Error | `isError === true` | Rank slot shows `—`. Error note `text-xs text-red-600` below stat block. |
