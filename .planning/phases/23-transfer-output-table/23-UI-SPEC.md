## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cell | 14px (text-sm) | 500 (font-medium) | 1.5 (Tailwind default) |

Notes:
- Two weights only: 500 (font-medium) for body and labels; 600 (font-semibold) for badges and the plan value headline

- Plan value headline is the only display-scale element; use text-xl font-semibold

Source: PlannerTab.tsx (text-sm font-medium for table content), HorizonSelector.tsx (text-sm font-medium), FixtureBadges.tsx (text-xs font-semibold), VerdictBadge.tsx

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff light / #0a0a0a dark (--background) | Page background, table background |
| Secondary (30%) | zinc-50 light / zinc-800 dark | Table row alternate bg (optional), section containers |
| Accent (10%) | zinc-900 light / white dark | Active chip toggle button, primary CTA ("Generate Plan" button) |
| DGW semantic | violet-700 light / violet-400 dark | DGW badge on GW label column only |
| BGW semantic | amber-600 light / amber-400 dark | BGW badge on GW label column only |
| Destructive | red-700 light / red-300 dark | Hit cost value when step.hitCost < 0 (negative, e.g. "-4 pts") |
| Unconfirmed fixture | zinc-400 light / zinc-500 dark | Projected gain value italic text when step.unconfirmedFixtures === true |

Accent reserved for:
1. The active/selected chip toggle button (Wildcard / Free Hit / Triple Captain / Bench Boost) per GW row
2. The "Generate Plan" primary CTA button (already implemented in PlannerTab.tsx)
3. Nothing else — all other interactive elements use zinc hover states

Dark mode: class-based via `.dark` selector — all colour declarations MUST include explicit `dark:` variant. Do NOT use hard-coded `text-black` or `bg-white`.

Source: globals.css (--background tokens), PlannerTab.tsx (zinc-900/white active pattern), HorizonSelector.tsx (same active pattern), FixtureBadges.tsx (violet DGW, green/amber/red tier colours), RESEARCH.md (BGW amber recommendation), STATE.md (Tailwind v4 class-based dark mode)

## Transfer Output Table Layout

### Table columns (desktop, all visible)

| # | Column header | Source field | Notes |
|---|---------------|--------------|-------|
| 1 | GW | step.gw | Show GW number + DGW/BGW badge inline |
| 2 | Chip | step.chip | ChipToggle control — 4 options + clear |
| 3 | Out | step.transfersOut[0] → playerMap lookup → web_name | "—" when no transfer |
| 4 | In | step.transfersIn[0] → playerMap lookup → web_name | "—" when no transfer |
| 5 | Hit | step.hitCost | Format: "0" or "-4 pts"; red text when < 0 |
| 6 | Gain | step.scoredTransfers[0]?.netGain ?? 0 | Format: "+X.X pts" or "−X.X pts"; italic zinc when unconfirmedFixtures |

### Hold row (when transfersIn.length === 0)

Columns 3–6 render as: "Hold" (colspan Out+In), "0", "—"
Body copy: "No profitable transfer this gameweek"

### Plan value headline (above table)

Position: above the table, below the "Generate Plan" button section
Format: `Plan value: +X.X pts` (total net gain across all steps)
Typography: text-xl font-semibold text-zinc-900 dark:text-zinc-100
Calculation: sum of `step.scoredTransfers[0]?.netGain ?? 0` across all steps

### Mobile layout

On screens < 640px (sm breakpoint):
- Hide "Chip" column label; show chip toggle below the GW cell as a stacked sub-row
- "Out" and "In" columns collapse to a single "Transfer" cell showing "PlayerOut → PlayerIn"
- "Hit" and "Gain" columns remain visible as two compact cells

## Chip Toggle Control

| Chip | Code | Display label |
|------|------|---------------|
| Wildcard | 'wildcard' | Wildcard |
| Free Hit | 'freehit' | Free Hit |
| Bench Boost | 'bboost' | Bench Boost |
| Triple Captain | '3xc' | Triple Captain |
| None | null | — (no chip) |

Interaction contract:
- Render 4 small buttons per GW row, one per chip option
- Active chip button: `bg-zinc-900 dark:bg-white text-white dark:text-zinc-900` (matches HorizonSelector active style)
- Inactive chip button: `bg-white dark:bg-zinc-800 text-zinc-700 dark:text-zinc-300 hover:bg-zinc-50 dark:hover:bg-zinc-700`
- Clicking the already-active chip clears it (toggle off → chip = null)
- min-h-[44px] on each button for touch compliance
- aria-pressed={chip === activeChip} on each button

## States and Interactions

| State | Trigger | Visual |
|-------|---------|--------|
| Plan not generated | Initial load / no planResult | Empty state message (see Copywriting) |
| Plan loading | handleGeneratePlan running (synchronous — no async) | N/A — generatePlan is synchronous; no loading spinner needed |
| Plan generated, hold step | step.transfersIn.length === 0 | Hold row with em-dash cells |
| Plan generated, transfer step | step.transfersIn.length > 0 | Full row with player names |
| Unconfirmed fixture | step.unconfirmedFixtures === true | Gain cell: italic text + asterisk |
| Chip active | step.chip !== null | Active chip button in zinc-900/white fill |
| Chip inactive | step.chip === null | All 4 chip buttons in inactive zinc style |
| Hit cost row | step.hitCost < 0 | Hit cell: red-700 dark:red-300 text |

## Accessibility

- Table uses `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`, `<td>` — semantic HTML, no div-table
- Chip toggle buttons: `aria-pressed` per button, `role="group"` with `aria-label="Chip for GW {N}"`
- DGW/BGW badges: `aria-label="Double gameweek"` / `aria-label="Blank gameweek"` on the badge span
- Unconfirmed fixture asterisk: wrapped in `<abbr title="Fixtures not yet confirmed for this gameweek">*</abbr>`
- Plan value headline: `aria-live="polite"` so screen readers announce when the value updates
