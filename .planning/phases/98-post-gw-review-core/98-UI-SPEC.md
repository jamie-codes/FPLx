# Phase 98 — UI Design Contract

> Visual and interaction contract for Phase 98: Post-GW Review Core (PGW-01, PGW-02, PGW-04).
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.

This is an **incremental phase**. No new screens, no new sub-tabs, no new top-level components.
All visible UI changes extend the existing `GwReviewTab` (Phase 73) and `page.tsx` auto-surface
behaviour. The design contract below locks the visual/interaction shape of those extensions and
the interface shape of the new `useSettledGws` hook.

## "Best Bench" Row — Visual Contract (PGW-01)

Position: immediately below the existing "Captain" info row inside `GwReviewTab`'s data-rendered
branch. The row appears only in the happy-path render — when `submittedId !== null`,
`settledGws.length > 0`, query is not loading/error, and `data` is present.

### Markup contract

```tsx
<div className="rounded border border-zinc-200 dark:border-zinc-700 px-3 py-2 flex items-baseline gap-2">
  <span className="text-xs text-zinc-500 dark:text-zinc-400">Best bench</span>
  <span className="text-sm font-semibold text-zinc-900 dark:text-zinc-100">
    {review.best_bench_player_name} — {review.best_bench_player_pts}pts
  </span>
</div>
```

### Visual rules

| Aspect | Rule |
|--------|------|
| Container shape | `rounded border` — identical to "Top scorer" and "Captain" rows |
| Border colour | `border-zinc-200 dark:border-zinc-700` |
| Inner padding | `px-3 py-2` (12px horizontal, 8px vertical) |
| Layout | `flex items-baseline gap-2` — label and value on baseline, 8px gap |
| Label colour | `text-zinc-500 dark:text-zinc-400` (12px, regular) |
| Value colour | `text-zinc-900 dark:text-zinc-100` (14px, semibold) |
| Separator | em-dash with single space either side: ` — ` (UTF-8 U+2014, not hyphen) |
| Points suffix | lowercase `pts` directly appended to integer (e.g. `5pts`) — matches existing "Top scorer" row |

### Vertical rhythm (parent `<section className="mt-6 space-y-3">`)

```
[ Section header                                ]
[ 2×4 stat grid                                 ]
[ "Top scorer" info row                         ]
[ "Captain" info row                            ]
[ "Best bench" info row    ← NEW (this phase)   ]
```

`space-y-3` (12px) separates each block. No additional margin or padding on the new row.

### Copy contract

| State | Copy |
|-------|------|
| Happy path | `Best bench` (label) + `{best_bench_player_name} — {best_bench_player_pts}pts` (value) |
| Zero points on bench (entire bench scored 0) | `Best bench` + `{name} — 0pts` (still render the highest-scoring bench player; `0pts` is informative) |

### Behaviour when bench data is missing or malformed

The API guarantees both fields are present on a 200 response (non-optional in the type). If the
API call fails, the row is never rendered — the error branch in `GwReviewTab` handles all
failure states uniformly (see "States" below). The component does **not** add a per-row
fallback string.

## Auto-Surface Behaviour — Visual & Interaction Contract (PGW-04)

The auto-surface logic produces **no new visible UI**. It is a navigation side-effect only.
The user perceives it as: "the app opened on Squad > Review instead of the previous tab".

### When the effect fires

`useEffect` in `page.tsx`, dependency array `[latestSettledGw]` (the last element of
`useSettledGws()` output). Effect body runs on:
- Initial mount, once `useSettledGws` has resolved.
- Any change to the latest settled GW number during the session (e.g. a new GW settles while
  the user has the app open and the hook refetches).

### Effect body (logical contract, not implementation)

```
1. If settledGws.length === 0  → return (no settled GW yet)
2. Let N = settledGws[settledGws.length - 1]
3. Let key = `pgw-reviewed:GW${N}`
4. If localStorage.getItem(key) !== null  → return (already surfaced)
5. setActiveSection('squad')
6. setActiveSubTab('review')
7. localStorage.setItem(key, '1')        // write immediately (D-04)
```

### Visual outcome

| Condition | What user sees on page load |
|-----------|-----------------------------|
| First visit after GW N settles | Squad > Review tab is active; `GwReviewTab` renders with selected GW = N |
| Subsequent visits (same GW N already flagged) | Whatever section/sub-tab they last had (no nav override) |
| No GW has settled yet (`settledGws === []`) | No nav override; user lands on default (`analyse / gems`) |
| Squad not loaded (`submittedId === null`) | Nav still overrides to `squad / review`; `GwReviewTab` renders its existing empty state: "Load your squad to see GW reviews." (D-02) |

### State-mutation order

The effect MUST call `setActiveSection('squad')` **before** `setActiveSubTab('review')`. React
batches these two state updates in a single commit, so order is cosmetic in v19 — but the
contract is fixed for readability and for downstream test assertions.

### LocalStorage write rules

| Rule | Value |
|------|-------|
| Key format | `pgw-reviewed:GW${N}` where `N` is the integer GW number (e.g. `pgw-reviewed:GW37`) |
| Value | `'1'` (any non-null string works; `'1'` chosen as the canonical sentinel) |
| TTL | None — persists indefinitely (D-05). Settled GW data is immutable, so a stale flag never causes incorrect behaviour |
| Write moment | At the moment of auto-navigation, before the next render (D-04) |
| Write failure handling | If `localStorage.setItem` throws (e.g. quota exceeded, private mode), swallow the error silently. The navigation has already occurred; missing flag means the user will be re-surfaced next visit, which is acceptable |

### Multi-tab behaviour

Out of scope. If the user has two tabs open during a GW settlement, both may auto-navigate.
This is acceptable — no contract is added for cross-tab coordination.

## `useSettledGws` Hook — Interface Contract

The hook produces no UI directly, but its return shape is part of the design contract because
two consumers depend on it.

### Signature

```ts
export function useSettledGws(): {
  data: number[]                  // last 3 settled GWs in ascending order; [] if none
  isLoading: boolean
  isError: boolean
}
```

### Return-value rules

| Rule | Value |
|------|-------|
| Array order | Ascending (e.g. `[33, 34, 35]`), matching the existing `SETTLED_GWS_PLACEHOLDER` |
| Maximum length | 3 (D-07) |
| Filter predicate | `event.finished === true && event.data_checked === true` (D-06) |
| Empty case | Returns `[]` — never `null` or `undefined` |
| Loading case | `data === []`, `isLoading === true` — consumers should not gate UI on loading; the empty array drives existing empty states |
| Error case | `data === []`, `isError === true` — same fallback as empty; do NOT show a separate error UI for this hook |

### Caching

- Source: `/api/fpl/[...proxy]/bootstrap-static` (consistent with existing patterns — D-?? Claude's discretion noted in CONTEXT)
- `staleTime`: 60 minutes (1 hour) — bootstrap events update at most once per GW
- `retry`: 1 (matches `useGwReview` and `useDecisionHistory`)

### Consumers

1. `page.tsx` — replaces `SETTLED_GWS_PLACEHOLDER`; output passed as `settledGws` prop to `GwReviewTab`.
2. `page.tsx` PGW-04 `useEffect` — reads `data[data.length - 1]` to derive the "latest settled GW" for auto-surface.

## States

The `GwReviewTab` already declares its own state matrix (no-squad / no-settled-gws / loading /
error / data). Phase 98 introduces **no new state branches**. The "Best bench" row appears only
inside the existing data-rendered branch.

### Loading / error / empty states (unchanged from Phase 73, restated for completeness)

| State | Trigger | Copy | Style |
|-------|---------|------|-------|
| No squad | `submittedId === null` | `Load your squad to see GW reviews.` | Centered text in zinc-bordered panel |
| No settled GWs | `settledGws.length === 0` OR `queryGw === null` | `GW review will appear once scores finalise.` | Centered text in zinc-bordered panel |
| Loading | `isLoading` | `Loading GW review...` | Left-aligned text in zinc-bordered panel |
| Unsettled (503) | API returns 503 | `GW review will appear once scores finalise.` | Neutral zinc-bordered panel (not red) |
| Stale Blob (404/502) | API returns 404 or 502 | `Review data unavailable - check back after the next pipeline run.` | Red-bordered panel (`border-red-300 dark:border-red-700 bg-red-50 dark:bg-red-950 text-red-700 dark:text-red-300`) |
| Generic error | other non-OK status | `Unable to load GW review. Please try again.` | Red-bordered panel (same as above) |
| Data (happy path) | `data` present | renders 2×4 grid + 3 info rows (incl. new "Best bench") | as specified above |

### `useSettledGws` loading/error states

Both surface as `data: []`. Consumers render the existing "GW review will appear once scores
finalise." panel — there is no separate "loading settled GWs..." copy.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Info row semantics | Plain `<div>` containing two `<span>` elements. No ARIA role — screen readers announce the label and value in reading order, which conveys the meaning ("Best bench, Salah, 7pts") |
| Info-row colour contrast | `text-zinc-500` on `bg-white` and `text-zinc-400` on `bg-zinc-950` both pass WCAG AA at 12px (existing rows already validated for Phase 73) |
| Em-dash pronunciation | Screen readers pronounce U+2014 as a pause; acceptable for this content |
| Auto-surface navigation | The `useEffect` fires before paint; the user sees Squad > Review as the initial render — no jarring flash. No `aria-live` announcement required (the URL/tab state is the announcement) |
| Auto-surface respects user agency | Once `localStorage['pgw-reviewed:GW{N}']` is set, the override never fires again for that GW — user can navigate freely afterwards |
| Touch target | The new row is non-interactive; touch-target floor (`min-h-[44px]`) does not apply |
| Keyboard | No new keyboard interactions. The existing `GwPillToggle` keyboard contract is unchanged |
| Reduced motion | No animations introduced in this phase |
| Empty bench-player name guard | API contract guarantees `best_bench_player_name` is a non-empty string when the response is 200 (bench always has 4 picks in standard FPL). If the field is missing or empty, executor must treat as a server bug — do NOT render `Best bench — pts` |
