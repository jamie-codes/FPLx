# Phase 59 — UI Design Contract: Manual Transfer Planner

## Component Inventory

### Visual Hierarchy (Focal Point)

- **No-squad state:** Single Team ID input + "Load Squad" CTA centered in the tab body. Empty state copy is the only other content. The submit button is the visual anchor.
- **No-plan state (squad loaded, plan empty):** The summary header (zeroed metrics) sits above N empty GW step cards. Each card's "+ Add Transfer" button is the primary call to action; the eye scans down through the step cards.
- **Plan-with-transfers state:** Summary header is the secondary visual anchor (running totals); the topmost GW step containing transfers is the primary anchor (most recent edit). Hits and break-even values use color (red badge / muted em-dash) to convey severity without dominating.

## Interaction Contracts

### Tab activation

1. User clicks "Manual Plan" sub-tab in the Plan section nav (or "Manual" on mobile).
2. `activeSection === 'plan' && activeSubTab === 'manual-plan'` evaluates true.
3. `ManualPlanTab` mounts; reads `localStorage.getItem('fplx_manual_plan')` once on mount.
4. If localStorage value parses to a valid `ManualPlan` shape → restore steps + horizon. Else → initialise fresh (horizon = 3, N empty steps).

### Squad loading branch (D-09)

1. On mount, hooks fire: `useAuthStatus()`, `usePlayers()`, `useSquad(teamId)`, `useMyTeam(isAuthenticated)`.
2. `picks = myTeamData?.picks ?? squadData?.picks ?? null`.
3. **No `picks`:** render the no-squad empty state (Team ID input + Load Squad button + heading copy). The summary header, GW steps, and caveat banner are NOT rendered in this branch.
4. **`picks` available:** render the full plan UI. If `!isAuthenticated` AND `picks` is from public `useSquad` → show caveat banner above the controls row.

### Horizon change (D-04 truncation)

1. User toggles `HorizonSelector` from current N to new M.
2. **If M < N:** truncate `steps` array to length M. No confirmation prompt. Any transfers in dropped steps are discarded.
3. **If M > N:** append (M − N) empty step objects (no transfers, chip = `'none'`).
4. Recompute summary header, FT propagation, and bank balances downstream.
5. Persist new state to `localStorage('fplx_manual_plan')`.

### Add Transfer flow (D-06)

1. User clicks "+ Add Transfer" in step `i`.
2. `openPicker(i)` builds picker state: `position = null` initially (user hasn't chosen player-out yet) — so the picker first prompts the user to pick from THIS GW's snapshot squad. Implementation note: a two-stage flow may be needed — first select sell, then re-open picker filtered by sell's position for the buy. (Refinement: planner spec may simplify by listing all 15 squad players as the first picker stage.)
3. After both sell and buy chosen, transfer is appended to `step.transfersIn` / `step.transfersOut`.
4. Modal closes (`PlayerPickerModal` calls `onClose`).
5. Plan is recomputed: bank balance, FT propagation, hit cost, break-even — all derived for steps `i..N`.
6. State persists to localStorage.

### Remove Transfer flow

1. User clicks ✕ on a transfer row in step `i`, position `j`.
2. The transfer pair (`transfersIn[j]`, `transfersOut[j]`) is removed from step `i`.
3. Subsequent steps recompute (bank, FT, snapshot squad).
4. State persists.
5. No confirmation modal (this is exploratory state — easy reversal expected).

### Chip toggle (D-08)

1. User clicks a chip button on step `i`'s `ChipToggle`.
2. If clicked chip equals current → set to `'none'` (toggle off behavior inherited from `ChipToggle`).
3. Else → set step's `chip` to clicked code.
4. `computeNextFTState` and `computeHitCost` re-derive for steps `i..N` (Wildcard / Free Hit affect FT bank).
5. State persists.

### Accordion toggle (D-10)

1. Each `GwStepCard` tracks its own `isOpen` boolean; `Set<number>` of open step indices held in `ManualPlanTab` state.
2. Default: all steps closed.
3. Clicking the "▼ Show squad" / "▲ Hide squad" button toggles the index in the open set.
4. Open state is **session-only** — NOT persisted to localStorage (avoids stale UI on return).

### Reset Plan

1. User clicks "Reset Plan" link.
2. Native `window.confirm("Clear all transfers from your manual plan?")` fires.
3. On confirm: clear `steps` to fresh empties at current horizon; clear `localStorage('fplx_manual_plan')`.
4. On cancel: no-op.

### Persistence (D-05, MTP-08)

- Write trigger: every `steps`/`horizon` mutation calls `persistManualPlan(state)`.
- Storage key: `fplx_manual_plan`.
- Schema: `{ horizon: 1|3|5, steps: SerializableStep[], version: 1 }` — `version` lets future migrations detect old shapes.
- Read trigger: `useState` lazy initializer on mount.
- Failure handling: `try/catch` around `JSON.parse`; on parse failure → fall back to fresh state and clear the corrupted key.
- SSR guard: `typeof window !== 'undefined'` before any read or write.

## States Required

### `ManualPlanTab`

| State | Trigger | UI Response |
|-------|---------|-------------|
| Initial — no squad, no localStorage | First visit, no `fpl_team_id` | Empty-state copy + Team ID input + Load Squad button |
| Initial — no squad, localStorage has team ID but fetch failed | Stale or invalid Team ID | Same as above with error helper text below input: `Couldn't find squad — please re-check your Team ID.` |
| Loading — players or squad fetching | Hooks pending | Single inline `Loading…` text replacing the entire body (`text-sm text-zinc-500`) |
| Squad loaded — authenticated | `isAuthenticated && myTeamData` | Full plan UI with exact sell prices, NO caveat banner |
| Squad loaded — unauthenticated | `!isAuthenticated && squadData` | Full plan UI WITH caveat banner above controls row |
| Plan empty — no transfers anywhere | All `step.transfersIn.length === 0` | Summary header reads `Hits: 0 | Hit cost: 0 pts | Avg break-even: —`; each GW step shows only "+ Add Transfer" button |
| Plan partial — some steps with transfers | At least one transfer exists | Summary populated; populated steps render `TransferRow`s |

### Summary header

| State | Trigger | UI Response |
|-------|---------|-------------|
| Zero hits | `totalHits === 0` | `Hits: 0`, `Hit cost: 0 pts`, `Avg break-even: —` |
| Some hits | `totalHits > 0` | All three metrics populated; `Avg break-even` shows arithmetic mean over hit transfers only |
| All hits unbreakable | All hit transfers have `xPtsDelta <= 0` | `Avg break-even: ∞` |

### `GwStepCard`

| State | Trigger | UI Response |
|-------|---------|-------------|
| Empty step | `step.transfersIn.length === 0` | Header + "+ Add Transfer" + footer (bank/FT) + closed accordion |
| Populated step | `step.transfersIn.length >= 1` | Header + N transfer rows + "+ Add Transfer" + footer + closed accordion |
| Accordion open | Index in open set | `SquadSnapshotRow` rendered below footer |
| WC chip active | `step.chip === 'wildcard'` | All transfers in this step show `Free` badge regardless of count; FT footer reads `WC active` |
| FH chip active | `step.chip === 'freehit'` | Same as WC visually for transfers; FT footer reads `FH active` |
