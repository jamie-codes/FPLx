# Plan 117-02: TypeScript Layer — Types + API route + useLineupNews hook

## Objective

Deliver the Next.js half of Phase 117: append five TypeScript types to `src/lib/types.ts`, create `src/app/api/lineup-news/route.ts` (clone of `gw-intel/route.ts` with four string substitutions), and create `src/lib/hooks/useLineupNews.ts` (clone of `useGWIntel.ts` with five substitutions). These are mechanical clones — no novel logic. The hook serves Phase 118 engine consumers (which add the 48h staleness gate from INFRA-02).

## Background

CONTEXT.md D-07 locks `useLineupNews` staleTime at 6h. RESEARCH.md §TypeScript Types and §Architecture Patterns provide verbatim type definitions and route/hook bodies derived from the verified `gw-intel/route.ts` and `useGWIntel.ts` files. INFRA-01 requires the route to read from Blob (when `USE_BLOB=true`) or local `pipeline/cache/lineup_news.json` (when false). INFRA-02 requires only that the artifact carry a `scraped_at` field — the actual staleness gate lives in Phase 118 consumers, so this plan ensures the type carries the field but does not enforce the cutoff.

This plan depends on Plan 117-01 for the existence of `pipeline/cache/lineup_news.json` (smoke test) but the route+hook code can be written and unit-checked independently. Wave 2 because runtime smoke verification needs the artifact from Wave 1.

<threat_model>
## Threat Model (ASVS L1)

| Threat | STRIDE | Severity | Mitigation |
|--------|--------|----------|------------|
| Path traversal via crafted request to read arbitrary files when USE_BLOB=false (V5) | Information disclosure | High | Cache path is hardcoded `join(process.cwd(), 'pipeline', 'cache', 'lineup_news.json')` — no request input flows into the path. Matches gw-intel/route.ts pattern. |
| Open redirect / SSRF via Blob URL manipulation when USE_BLOB=true | Information disclosure | Medium | `list({ prefix: 'lineup_news.json', limit: 1 })` returns Vercel-controlled URLs only; `fetch(blobs[0].url)` follows a server-trusted host. No user input flows to `fetch`. |
| Cached error response leaks file paths or stack traces | Information disclosure | Medium | All error responses return generic `{error: 'Failed to load lineup news'}` (500) or `{error: 'Lineup news not available'}` (404) — never `err.message` or `err.stack`. ENOENT detection is the only exception code branched on. |
| Stale-while-revalidate cache serves data older than 48h to engine consumers without warning | Tampering (logic) | Low | INFRA-02 explicitly delegates the 48h gate to Phase 118 consumers (RESEARCH.md §Phase Requirements). Route's `Cache-Control: s-maxage=3600` is independent of artifact freshness. The artifact's `scraped_at` field is what consumers check. |
| Unauthenticated public access exposes player news headlines | Information disclosure | Low | All player news is public data scraped from public RSS/HTML feeds. No access control needed (V4 N/A). Matches existing pattern for /api/gw-intel and /api/set-pieces. |
| Malformed JSON in cache file crashes the route (DoS) | Denial of Service | Low | `JSON.parse(data)` in try/except — falls through to generic 500 response. Pipeline (Plan 117-01) guards against empty `players[]` so well-formed-but-empty artifact is impossible. |
| Blob fetch hangs holding a connection | Denial of Service | Low | `fetch(blobs[0].url)` uses runtime default timeout (Node 25 fetch); Vercel Blob CDN is highly available. Failure → 502 with no retry loop. |

ASVS L1 controls applied: V5 (hardcoded path, no user input), V11 (generic error messages, no stack leakage), V12 (Cache-Control header set explicitly).
</threat_model>
