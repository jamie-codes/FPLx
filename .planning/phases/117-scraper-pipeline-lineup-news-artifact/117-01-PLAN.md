# Plan 117-01: Python Pipeline — lineup_news.py module + run.py integration + tests

## Objective

Deliver the Python pipeline half of Phase 117: a new standalone module `pipeline/lineup_news.py` that derives per-player availability from FPL bootstrap and enriches with three optional web scrapers (premierleague.com HTML, Sky Sports RSS, BBC Sport RSS), plus the 5-line `run.py` integration block immediately after `save('fpl_bootstrap.json', bootstrap)`, plus pytest coverage and dependency pins. The output is `lineup_news.json` (Vercel Blob or local cache) following the established `set_piece_quality` non-fatal pattern.

## Background

CONTEXT.md D-01..D-10 lock the implementation: FPL bootstrap is authoritative for `availability_factor`; web scrapers contribute `news_headline`+`news_source` only; per-source isolation via `try/except`; empty `players[]` is never written (SCRP-05); 48h staleness is enforced by Phase 118 consumers, not here. RESEARCH.md confirms feedparser 6.0.12 + beautifulsoup4 4.14.3 + lxml 6.1.0 as the stack, fuzzy cutoff 0.6 for difflib, and that `premierleague.com/latest-player-injuries` is JS-rendered so SCRP-02 will commonly yield zero matches — that is the acceptable outcome.

<threat_model>
## Threat Model (ASVS L1)

| Threat | STRIDE | Severity | Mitigation |
|--------|--------|----------|------------|
| Malicious RSS feed injects HTML/script into headline text stored in lineup_news.json (V5 input validation) | Tampering | Medium | Store `entry.get('title', '')` raw string only; never store `entry.description` HTML; pass through `json.dumps` (default escaping). Truncate to 280 chars in `_scrape_rss_*` helpers. |
| Excessively large RSS/HTML response causes DoS in pipeline runner | DoS | Medium | All `requests.get()` and `feedparser.parse()` calls bounded by `timeout=10` (matches `set_piece_quality` pattern). Per-source try/except prevents one slow source from blocking others. |
| premierleague.com returns HTML with `<script>` tags that BS4 might mis-parse and leak into headlines | Tampering | Low | `BeautifulSoup(resp.text, 'lxml').select(...)` followed by `el.get_text(strip=True)` extracts text only — no HTML preserved. |
| Scraper raises and crashes whole pipeline, losing merged_players.json work | Denial of Service (integrity) | High | Two-layer isolation: outer try/except in `run.py` around `compute_lineup_news`; inner per-source try/except in `lineup_news.py`. Both required by SCRP-05. |
| Empty `players[]` written to Blob overwrites valid previous run | Tampering | High | Explicit guard `if not players: return` BEFORE `save()` (SCRP-05). Test `test_empty_players_guard_skips_save` enforces this. |
| Error message containing PII or auth-token written to `source_health.last_error` | Information disclosure | Low | Truncate to 200 chars: `str(exc)[:200]`. Pipeline does not handle auth tokens for any of these sources. |
| Unbounded exception string spam in CI logs | Repudiation/DoS | Low | All error prints go to `sys.stderr` once per exception; no retry loops in this phase. |

ASVS L1 controls applied: V5 (input validation via BS4 `get_text` and json escape), V11 (business logic resilience via per-source isolation + empty guard).
</threat_model>
