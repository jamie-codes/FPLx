# Phase 63 — UI Design Contract: Model Versioning & Calibration Charts

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase carries forward the design system established in `058-UI-SPEC.md`, `059-UI-SPEC.md`, `060-UI-SPEC.md`, and `062-UI-SPEC.md` unchanged. Spacing, typography, color palette, dark-mode surface convention, and copywriting style are identical to all prior Plan-section and Analyse-section phases. Phase 63 extends `src/components/accuracy/AccuracyTab.tsx` — it does NOT introduce a new sub-tab. Two new visual surfaces are added inside the existing AccuracyTab section: a **Model Version History** table and a **Calibration Reliability** chart with a position tab selector.

Reused components and constants from `AccuracyTab.tsx` (`DeltaCell`, `TH_CLS`, `TR_CLS`, `TD_CLS`, `TABLE_CLS`, `HitRateBadge`, tier classes) are referenced by name only — their internals are NOT re-specified. New components (`VersionHistoryTable`, `CalibrationChart`, `PositionTabSelector`) are specified explicitly below.

Exceptions (carried forward from Phase 62):

- **Table cell padding:** `py-1` (4px vertical) per existing `TD_CLS` constant in `AccuracyTab.tsx:49`. NOT redefined for the new version table — reuse the existing constant verbatim.
- **Section break inside AccuracyTab:** `space-y-8` (32px) between the new Version History table, the new Calibration Reliability section, and the existing GwSummaryTable / HaulterList / PlayerDeltaTable. ## Component Inventory

### Visual Hierarchy (Focal Point)

**AccuracyTab (overall) — with version + calibration data present:**

The new Calibration Reliability chart is the new primary visual anchor of the AccuracyTab landing view. It sits second in the section order (after the Version History table) but its visual weight (288px chart card) makes it the focal point. The Version History table is secondary — a compact row-per-version reference.

**AccuracyTab — first pipeline run (`versions.length === 1`):**

The Version History table renders a single row with the current version. The Calibration chart renders normally if calibration data is available (calibration is computed every run, regardless of version-array dedup). Empty-state copy under the version table reads `First pipeline run — no version history yet.` as muted helper text.

**AccuracyTab — calibration data missing entirely** (`data.calibration === undefined`, e.g. legacy cache before Phase 63):

The Calibration section heading renders, with an empty-state body: `Calibration data not yet computed. Run the pipeline to populate this section.` No chart, no tab selector. Matches the Phase 41 / Phase 62 graceful-degrade pattern.

**AccuracyTab — calibration data has all empty buckets for the active position** (`bucket.length === 0` after sample_n filter):

Chart container renders with axes and reference diagonal but no data line. Inline annotation: `Insufficient sample (n<5) for ${position} this window.` rendered as `text-xs text-zinc-500 dark:text-zinc-400` centred over the chart area (absolute-positioned overlay).

### New Components

#### `VersionHistoryTable` — extension to `AccuracyTab.tsx`

Rendered as the FIRST sub-section inside the existing AccuracyTab `<section>` wrapper, ABOVE `GwSummaryTable`. CONTEXT.md D-08 layout order: (1) Version History, (2) Calibration, (3) GwSummaryTable, (4) HaulterList, (5) PlayerDeltaTable.

Top-level structure:

```
<div>
  <h2 className="text-lg font-semibold mb-2">Model Version History</h2>
  <table className={TABLE_CLS}>
    <thead>
      <tr>
        <th className={TH_CLS}>Version</th>
        <th className={TH_CLS}>Recorded</th>
        <th className={TH_CLS}>Hit Rate</th>
        <th className={TH_CLS} title="Change vs previous version">Δ</th>
        <th className={TH_CLS}>Active Gates</th>
      </tr>
    </thead>
    <tbody>
      {data.versions.map((v, i) => {
        const prev = data.versions[i - 1]
        const delta = prev ? (v.hit_rate - prev.hit_rate) * 100 : null
        const isCurrent = i === data.versions.length - 1
        return (
          <tr key={v.formula_version} className={TR_CLS}>
            <td className={TD_CLS}>
              {v.formula_version}
              {isCurrent && (
                <span className="ml-2 text-xs font-semibold text-zinc-500 dark:text-zinc-400">
                  (current)
                </span>
              )}
            </td>
            <td className={TD_CLS}>{formatRecordedAt(v.recorded_at)}</td>
            <td className={TD_CLS}><HitRateBadge rate={v.hit_rate} /></td>
            <td className={TD_CLS}>
              {delta === null
                ? <span className="text-zinc-400 dark:text-zinc-500">—</span>
                : <DeltaCell delta={delta} />}
            </td>
            <td className={TD_CLS}>
              <GateFlagsCell flags={v.gate_flags} />
            </td>
          </tr>
        )
      })}
    </tbody>
  </table>
  {data.versions.length === 1 && (
    <p className="text-xs text-zinc-500 dark:text-zinc-400 mt-2">
      First pipeline run — no version history yet.
    </p>
  )}
</div>
```

`formatRecordedAt(iso: string): string` — render as `YYYY-MM-DD` (date only, no time). Use `new Date(iso).toISOString().slice(0, 10)`. Time of day is irrelevant for daily pipeline cadence and adds visual noise. (Claude's Discretion — date-only matches the existing project convention; no library dependency added.)

`Δ` column delta values are expressed in **percentage points** (not raw rate differences) and displayed with one decimal — e.g. `+1.4` means hit rate went from 12.0% to 13.4%. The DeltaCell component already formats with `+` prefix on positive and one-decimal precision. The `Δ` for the first version row (no previous) renders as `—` in muted zinc.

`GateFlagsCell` (inline component, defined in same file):

```tsx
function GateFlagsCell({ flags }: { flags: VersionGateFlags }) {
  const enabled = (Object.entries(flags) as Array<[keyof VersionGateFlags, boolean]>)
    .filter(([, on]) => on)
    .map(([key]) => GATE_LABEL[key])

  if (enabled.length === 0) {
    return <span className="text-zinc-400 dark:text-zinc-500">—</span>
  }

  return (
    <div className="flex flex-wrap gap-1">
      {enabled.map((label) => (
        <span
          key={label}
          className="inline-block text-xs rounded px-2 py-0.5 bg-zinc-100 text-zinc-700 dark:bg-zinc-800 dark:text-zinc-300"
        >
          {label}
        </span>
      ))}
    </div>
  )
}

const GATE_LABEL: Record<keyof VersionGateFlags, string> = {
  xmins_v2_enabled: 'xmins v2',
  bonus_predictor_enabled: 'bonus predictor',
  form_signal_enabled: 'form signal',
}
```

Chip pattern matches the `HitRateBadge` token pattern from `AccuracyTab.tsx:21-28` (rounded, `text-xs`, `px-2 py-0.5`). Zinc neutral palette — these are descriptive flags, not severity signals.

Chart data shape (per CONTEXT.md D-06):

```ts
type CalibrationBucket = {
  bucket_mid: number      // 0.05, 0.15, …, 0.95 (decile midpoints)
  predicted_rate: number  // expected rate for the bucket (used in tooltip)
  actual_rate: number     // observed rate (the plotted line)
  sample_n: number        // observation count
}

// chartData = data.calibration.by_position[position].filter(b => b.sample_n >= 5)
```

`connectNulls={false}` ensures buckets with `sample_n < 5` (which we filter out before passing to the chart) appear as a visible gap rather than a misleading interpolated line. CONTEXT.md D-07.

`isAnimationActive={false}` — matches Phase 62 RankSimTab convention; no gratuitous animation on data surfaces. Position tab switches re-render the chart; animation would cause visual confusion.

Reference diagonal: `<ReferenceLine segment={[{x:0,y:0}, {x:1,y:1}]} ifOverflow="extendDomain">` — Recharts v3 uses the `segment` prop for an arbitrary two-point line. This is the perfect-calibration y=x line that CONTEXT.md D-10 calls for.

`CalibrationTooltip`:

```tsx
function CalibrationTooltip({ active, payload }: TooltipContentProps) {
  if (!active || !payload?.length) return null
  const p = payload[0].payload as CalibrationBucket
  const bucketLow = Math.round((p.bucket_mid - 0.05) * 100)
  const bucketHigh = Math.round((p.bucket_mid + 0.05) * 100)
  return (
    <div className="rounded border border-zinc-200 dark:border-zinc-700 bg-white dark:bg-zinc-900 px-3 py-2 text-xs shadow-sm">
      <p className="font-semibold text-zinc-900 dark:text-zinc-100 mb-1">
        Decile {bucketLow}%–{bucketHigh}%
      </p>
      <p className="text-zinc-700 dark:text-zinc-300">
        Predicted: {(p.predicted_rate * 100).toFixed(1)}%
      </p>
      <p className="text-zinc-700 dark:text-zinc-300">
        Actual: {(p.actual_rate * 100).toFixed(1)}%
      </p>
      <p className="text-zinc-500 dark:text-zinc-400 mt-1">n = {p.sample_n}</p>
    </div>
  )
}
```

#### `PositionTabSelector` — inline component

Five pill buttons in a horizontally-scrollable row container. Default selected: `'all'`. Per CONTEXT.md D-09, position breakdown uses a tab selector (GK / DEF / MID / FWD / All) above the chart, following the RankSimTab pattern. "All" is the default.

```tsx
type CalibrationPosition = 'all' | '1' | '2' | '3' | '4'

const POSITION_PILLS: Array<{ value: CalibrationPosition; label: string }> = [
  { value: 'all', label: 'All' },
  { value: '1', label: 'GK' },
  { value: '2', label: 'DEF' },
  { value: '3', label: 'MID' },
  { value: '4', label: 'FWD' },
]

function PositionTabSelector({
  value,
  onChange,
}: {
  value: CalibrationPosition
  onChange: (v: CalibrationPosition) => void
}) {
  return (
    <div
      role="tablist"
      aria-label="Calibration position filter"
      className="flex flex-wrap gap-2 mb-2"
    >
      {POSITION_PILLS.map((pill) => {
        const active = pill.value === value
        const cls = active
          ? 'bg-zinc-900 text-white dark:bg-zinc-100 dark:text-zinc-900'
          : 'bg-zinc-100 text-zinc-700 dark:bg-zinc-800 dark:text-zinc-300 hover:bg-zinc-200 dark:hover:bg-zinc-700'
        return (
          <button
            key={pill.value}
            type="button"
            role="tab"
            aria-selected={active}
            onClick={() => onChange(pill.value)}
            className={`min-h-[44px] px-3 py-1 rounded text-xs font-semibold uppercase tracking-wide transition-colors ${cls}`}
          >
            {pill.label}
          </button>
        )
      })}
    </div>
  )
}
```

Pill width is content-driven (`px-3`); pills wrap on narrow viewports. Active pill uses the established sub-tab pill token (`bg-zinc-900 text-white dark:bg-zinc-100 dark:text-zinc-900`) — same as `MobileNav` and `page.tsx` Plan/Squad sub-tab pills. Inactive pills use the zinc-100/zinc-800 surface with hover state.

`min-h-[44px]` per pill satisfies WCAG 2.5.5 touch target.

`positionLabel(p: CalibrationPosition): string` — helper used in the empty-state copy: `'all' → 'All'`, `'1' → 'GK'`, `'2' → 'DEF'`, `'3' → 'MID'`, `'4' → 'FWD'`.

## Interaction Contracts

### AccuracyTab landing — render order

1. AccuracyTab mounts (existing behaviour).
2. `useAccuracy()` resolves; `data` is the `AccuracyBacktest`.
3. Loading → existing loading message.
4. Error → existing error message.
5. No data → existing no-data message.
6. Data present → render in this order inside the existing `<section className="mt-6 space-y-8">`:
   1. `<VersionHistoryTable data={data} />` — only renders when `data.versions && data.versions.length >= 1`.
   2. `<CalibrationSection data={data} />` — only renders when `data.calibration` is present.
   3. `<GwSummaryTable data={data} />` (existing — unchanged).
   4. `<HaulterList data={data} />` (existing — unchanged).
   5. `<PlayerDeltaTable data={data} />` (existing — unchanged).

If `data.versions` is undefined or empty, the Version History table is suppressed entirely (no heading, no empty-state surface — the section simply does not exist). Same rule for `data.calibration`. This keeps legacy AccuracyTab visually identical for users with stale cached pipeline output.

### Position tab switching

1. User taps a position pill (GK / DEF / MID / FWD / All).
2. `setPosition(pill.value)` updates local component state.
3. `chartData` recomputes (memoised on `data.calibration.by_position[position]` and the `sample_n >= 5` filter).
4. Chart re-renders. No animation. Tab pill visual state updates immediately.
5. If the new position has zero usable buckets after the n<5 filter, the chart container renders the "Insufficient sample" overlay instead of a data line.

State is **session-only** — no localStorage persistence. Position tab resets to `'all'` on page reload. Matches CONTEXT.md D-09 ("'All' is the default tab").

### Tooltip on calibration chart

Hovering / tapping a data point shows the `CalibrationTooltip` with: decile range (e.g. `Decile 30%–40%`), predicted rate, actual rate, sample size. The reference diagonal does NOT have a tooltip (Recharts `<ReferenceLine>` is non-interactive by default). Matches the Phase 62 pattern of suppressing tooltips on non-data layers.

### Version table — interaction

The Version History table is **read-only**. No sorting (versions are already sorted in append order), no filtering, no row expand. The `(current)` marker on the last row is a static label, not interactive.

### Empty-state cascades

| Condition | UI Response |
|-----------|-------------|
| `data.versions === undefined` (legacy cache) | Version History table suppressed entirely |
| `data.versions.length === 1` | Single row + helper text "First pipeline run — no version history yet." below the table |
| `data.versions.length >= 2` | Full table with delta column populated for rows ≥2 |
| `data.calibration === undefined` (legacy cache) | Calibration section suppressed entirely |
| `data.calibration.by_position[position]` exists but every bucket has `sample_n < 5` | Chart axes + reference diagonal render; centred overlay text "Insufficient sample (n<5) for ${positionLabel} this window." |
| `data.calibration.by_position[position]` has ≥1 bucket with `sample_n >= 5` | Line renders; sparse buckets appear as gaps via `connectNulls={false}` |

Load-bearing copy conventions (carried forward from all prior phases — reaffirmed here):

- **Em-dash `—`** for null / unavailable values (NOT empty string, NOT "N/A").
- **Greek capital delta `Δ`** (U+0394) for the delta column header — single character, font-agnostic, matches the project standard for variance/change columns (e.g. `xPts Δ` at `AccuracyTab.tsx:255`).
- **Tilde-less probability format:** percentages formatted as `12.3%` (one decimal) when computed from rate × 100, no tilde suffix on column headers (the Δ column conveys uncertainty by being a delta, not a point estimate).
- **Lowercase `n`** for sample-size labels (`n = 47`, `n<5`) — statistical convention. Lowercase in chart tooltips and overlay text.
- **Decile range format:** `Decile 30%–40%` — en-dash range separator (U+2013), space on either side absent (matches FPL convention for inclusive ranges).
- **Position labels:** `GK / DEF / MID / FWD / All` — uppercase abbreviations for the four FPL position codes; "All" mixed-case (proper word, not an abbreviation). Pill text typography handles the case via `uppercase tracking-wide` — except "All" uses the same class but the underlying string is `"All"` so the visual output is `ALL` in the pill (consistent capitalisation across the row).
- **No exclamation marks. No emoji. No first-person ("we", "our"). No vague verbs ("Click here", "Learn more").** Standard for the codebase per Phase 51 and onwards.
