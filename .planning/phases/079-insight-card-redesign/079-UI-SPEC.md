## Spacing Scale

Declared values (multiples of 4 only — Tailwind default `space-{n}` where `n × 4px`):

| Token | Value | Tailwind class | Usage in this phase |
|-------|-------|----------------|---------------------|
| xs | 4px | `space-y-1` / `gap-1` / `py-0.5` | Pill badge vertical padding (`py-0.5`); progress bar to label gap |
| sm | 8px | `space-y-2` / `gap-2` / `px-2` | Inter-zone spacing inside InsightCard (D-15: `space-y-2`); chip horizontal padding (`px-2`) |
| md | 16px | `p-4` / `space-y-4` | InsightCard padding (D-15: `p-4`); InsightsTab horizontal padding (`px-4`) |
| lg | 24px | `space-y-6` / `gap-6` | Inter-section spacing between collapsible sections |
| xl | 32px | `mb-8` | Page-level vertical breathing room above Decision Summary |

**Touch targets:** All interactive elements (collapsible section toggle button, `<details>` summary, future chip clicks) MUST satisfy `min-h-[44px]` per POL-03. Section toggle uses `min-h-[44px]` explicitly per RESEARCH §Pattern 4.

**Exceptions:**
- `h-2` (8px) for the progress bar track height (D-13 / RESEARCH §Pattern 3) — visual element, not a touch target.
- `h-4` (16px) for the benchmark vertical line which overhangs the bar (RESEARCH §Code Examples).
- `top-[-4px]` (4px overhang) on the benchmark line — single-pixel-grid-friendly value (`-1 × spacing-1`).
- Sticky offset for Decision Summary: `top-[var(--nav-height,96px)]` per D-09 / RESEARCH Pitfall 3 — fixed offset, not a token.

## Typography

Phase 79 declares 4 type roles. Geist Sans throughout; weights restricted to 2 (regular 400 + semibold 600). Tabular-nums applied explicitly to the headline metric.

| Role | Size | Weight | Line height | Tailwind class | Usage |
|------|------|--------|-------------|----------------|-------|
| Display (headline metric) | 30px (`text-3xl`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) | `text-3xl font-semibold leading-tight tabular-nums` | Zone 3 metric value (e.g. "55.2%"); range 28–36px per ROADMAP success criterion 1 — `text-3xl` (30px) sits inside that band |
| Heading (card title) | 15px (`text-[15px]`) | 600 (`font-semibold`) | 1.25 (`leading-tight`) | `text-[15px] font-semibold leading-tight` | Zone 2 card title; range 15–16px per ROADMAP success criterion 1 |
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 (default) | `text-sm` | Zone 4 takeaway sentence; Decision Summary action-hint line |
| Label | 12px (`text-xs`) | 400 (regular) | 1.4 (default) | `text-xs` | Zone 1 category label; Zone 5 action hint; signal badge text; chip text; methodology details body; section count badge |

**Constraints (binding for executor):**
- Exactly 4 sizes — no other text sizes permitted in InsightsTab.
- Exactly 2 weights (400, 600) — no `font-medium` (500), no `font-bold` (700).
- Headline metric MUST include `tabular-nums` class explicitly per D-17 (defends against future global-class regressions).
- Card title is `text-[15px]` (custom Tailwind) — chosen because Tailwind has no native 15px size; 15px is inside the requirement band 15–16px and pairs with 30px metric at a 2:1 vertical hierarchy ratio.

## Copywriting Contract

Phase 79 has no destructive actions and no traditional "primary CTA". The card itself is informational; the closest CTA-equivalent is the per-card `action_hint` and the methodology toggle.

| Element | Copy |
|---------|------|
| Methodology toggle (`<summary>`) | `Methodology` (verb-free label; native browser caret hint via `<details>`) |
| Methodology body format | `Sample: {sample_n}/{sample_total} · {gw_coverage} · Confidence: {confidence_pct}%` (D-14, exact format) |
| Section header format | `{Section name} · {count}` (D-12, exact format — middle-dot separator U+00B7) |
| Section names (D-10, INS-04) | `Priority Insights`, `Defensive Patterns`, `Attacking Patterns`, `Player-Specific Patterns` |
| Decision Summary heading | `Decision Summary` (D-07/D-09) |
| Empty section state | `No insights in this section yet — check back after the next pipeline run.` (graceful empty-state per RESEARCH Pitfall 1; applies when a category has 0 insights) |
| Empty Decision Summary state | `null` render — when `insights.length === 0` OR no insights have entity lists AND fallback yields none (RESEARCH §Pattern 5: `if (top3.length === 0) return null`) |
| Empty entire tab | `Insights are being generated. Refresh after the next pipeline run.` (already present in existing `InsightsTab.tsx:64-69`; preserve verbatim) |
| Error state (insight fetch fails) | `Couldn't load insights. {error.message}` (preserve existing `InsightsTab.tsx:55-63` error pattern; replace any `bg-red-*` hex with `text-negative` / `bg-negative/10` token classes) |
| Loading state | `Loading insights…` (preserve existing `InsightsTab.tsx:46-54` skeleton/spinner pattern) |
| Destructive confirmations | not applicable — no destructive actions in this phase |

**Action hint copywriting rules** (downstream — pipeline emits these per insight ID; planner clarifies exact strings during plan-check):
- Verb-led, ≤7 words, present tense (e.g. "Target home defenders in good runs").
- No hedging ("might", "could", "perhaps"). The action hint is a recommendation, not speculation.
- No player names embedded — names live in the chip row of the Decision Summary, not in the action hint string itself (avoids stale-name issues when pipeline regenerates).

**Signal label vocabulary (D-04, locked):** Exactly 6 strings — "Strong signal", "Watchlist", "Weak signal", "Trap risk", "Regression risk", "Hidden gem". No alternative casing, no plurals, no aliasing.

## Interaction Contract

| Interaction | Trigger | Behavior | Accessibility |
|-------------|---------|----------|---------------|
| Section collapse | Click chevron-row button | Toggle local `useState` boolean (D-11); no animation; conditional render | `<button type="button" aria-expanded={open}>`; chevron has `aria-hidden="true"`; label text is the accessible name; `min-h-[44px]` for touch |
| Methodology expand | Click `<summary>` | Native `<details>` toggle; no JS | Native browser keyboard (Enter/Space); `cursor-pointer select-none` for visual affordance only |
| Decision Summary chips | None (read-only per D-08) | No click handler; no hover state | Plain `<span>` — no role/tabindex; chip text is read by screen readers in line with the action hint |
| Sticky scroll | Page scroll | Decision Summary pins at `top-[var(--nav-height,96px)] z-30` below nav (`z-40`) | `position: sticky` is keyboard-/screen-reader-neutral |

**No animations declared** — D-11 explicit (no transition on collapse). Native `<details>` provides no built-in animation. This is intentional: zero motion = zero motion-reduction CSS to maintain.

**Keyboard navigation:** Tab order = nav → Decision Summary (chips skipped, no tabindex) → Section 1 toggle → Section 1 cards (each `<details>` is one tab stop) → Section 2 toggle → … No focus traps; no roving-tabindex; no custom keyhandlers.

## Layout Contract

| Layer | Position | Z-index | Source |
|-------|----------|---------|--------|
| Page nav (Phase 78 sticky) | `sticky top-0` | `z-40` | `src/app/page.tsx:177` (carried forward) |
| Decision Summary | `sticky top-[var(--nav-height,96px)]` | `z-30` | D-09 — must NOT exceed nav z-index |
| InsightCard | flow (within section) | (default) | D-15 |
| Methodology `<details>` open panel | flow (inside card) | (default) | D-14 |

**Card layout vertical order (binding — D-15):**
1. Zone 1 — category badge row (`flex justify-between` with category label left, signal badge right)
2. Zone 2 — title (`text-[15px] font-semibold`)
3. Zone 3 — metric + progress bar (`text-3xl tabular-nums` metric; `h-2` bar + `h-4` benchmark line beneath)
4. Zone 4 — takeaway sentence (`text-sm`)
5. Zone 5 — action hint (`text-xs text-muted`)
6. Methodology — `<details>` collapsed by default (separator implicit via spacing)

Inter-zone spacing: `space-y-2` (8px) inside `p-4` (16px) card padding.

**Progress bar geometry (D-13, RESEARCH §Pattern 3):**
- Outer track: `relative w-full h-2 bg-surface-elevated rounded-full overflow-hidden`
- Inner fill: `h-full rounded-full bg-primary`, width = `clamp(0, metric_value, 100)%`
- Benchmark line: `absolute top-[-4px] w-px h-4 bg-muted`, left = `clamp(0, benchmark_value, 100)%`, with `aria-label="Benchmark {n}%"`
- The `overflow-hidden` on the track is required so the inner fill respects the rounded corners; the benchmark line escapes the track because it's a sibling, not a child of the fill — attach it inside the relative track but above the fill in DOM order.
