### Minutes Risk Badge Colors

These are semantic colors, not accent — they convey data meaning:

| mins_risk value | Background | Text | Border | Label |
|-----------------|-----------|------|--------|-------|
| nailed | green-100 (#dcfce7) | green-800 (#166534) | none | Nailed |
| likely_start | blue-100 (#dbeafe) | blue-800 (#1e40af) | none | Likely start |
| rotation_risk | amber-100 (#fef3c7) | amber-800 (#92400e) | none | Rotation risk |
| cameo | zinc-100 (#f4f4f5) | zinc-600 (#52525b) | none | Cameo |
| injured | — | — | — | (suppressed — use existing StatusBadge dot; no MinsRisk badge rendered) |

Rationale: `injured` is already communicated by the existing amber-400/red-500 dot StatusBadge. Rendering a second badge for `injured` would duplicate the signal. When `mins_risk === 'injured'`, render no MinsRisk badge.

Source: semantic extension of the existing badge pattern in TransferPanel.tsx (`bg-green-100 text-green-700`, `bg-red-100 text-red-700`).

## Component Inventory

### New: MinsRiskBadge component

**File:** `src/components/shared/MinsRiskBadge.tsx`

**Props:**
```
{ minsRisk: MinsRisk }
```

**Rendering contract:**
- `nailed` → `<span class="inline-block text-xs font-medium text-green-800 bg-green-100 rounded px-1.5 py-0.5">Nailed</span>`
- `likely_start` → `<span class="inline-block text-xs font-medium text-blue-800 bg-blue-100 rounded px-1.5 py-0.5">Likely start</span>`
- `rotation_risk` → `<span class="inline-block text-xs font-medium text-amber-800 bg-amber-100 rounded px-1.5 py-0.5">Rotation risk</span>`
- `cameo` → `<span class="inline-block text-xs font-medium text-zinc-600 bg-zinc-100 rounded px-1.5 py-0.5">Cameo</span>`
- `injured` → `null` (render nothing; StatusBadge already communicates this)

**Accessibility:** Each span receives a `title` attribute describing the classification in plain English:
- nailed → `title="Nailed: high start probability (≥85%)"`
- likely_start → `title="Likely start: moderate start probability (65–84%)"`
- rotation_risk → `title="Rotation risk: rotation risk identified"`
- cameo → `title="Cameo: low minutes expected"`

### Modified: SquadView.tsx

Add a "Risk" column header and `<MinsRiskBadge minsRisk={player.mins_risk} />` cell between the existing "Status" column and the right edge. The StatusBadge dot stays — it communicates injury/availability, not rotation risk.

Column order after change:
```
Player | Team | Price | Own% | Mins | Gem | Status | Risk
```

No other structural changes to SquadView.

### Modified: GemTable columns.tsx

Add a new column accessor for `mins_risk` as a display column positioned after the existing "Status" column:

```typescript
col.display({
  id: 'mins_risk',
  header: 'Risk',
  enableSorting: false,
  cell: ({ row }) => <MinsRiskBadge minsRisk={row.original.mins_risk} />,
})
```

Column position in GemTable after change (append after existing "Status" column):
```
... | Status | Risk | Trend | Next 5
```

### Modified: transfer-engine.ts (logic only, no new UI)

Transfer suggestions ranking: rotation-risk and cameo players are de-prioritised relative to equivalent gem-score players without rotation risk. This is a sort-order change in the engine, not a visual change. No new UI element is needed for MINS-03 — the existing suggestion list already shows players in ranked order.

However, a small indicator on rotation-risk sell candidates in the suggestion list is useful to confirm the penalty was applied. Add `<MinsRiskBadge />` inline after the player name in the "Sell" entry of each suggestion row in TransferPanel.tsx.

Example: `Sell <strong>Saka</strong> <MinsRiskBadge minsRisk={s.sell.mins_risk} /> (0.82) → Buy ...`
