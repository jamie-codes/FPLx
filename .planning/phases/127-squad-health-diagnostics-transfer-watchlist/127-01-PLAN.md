|----------|-------------|

| Vercel Blob → /api/pre-season-squad | Route reads the JSON file produced by the pipeline (server-side, trusted) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-127-01 | Tampering | pre_season_squad_health.json content | accept | Blob is write-protected by Vercel auth; only the pipeline service identity can write. Read path is server-only; clients never write. |
| T-127-02 | Information Disclosure | Envelope leaks structural data (sweep range) | accept | Sweep range constants are publicly knowable (FPL budget caps). No PII / no secrets. |
| T-127-03 | Denial of Service | Health side-read adds a second Blob fetch per request | mitigate | Promise.all runs both reads in parallel; existing Cache-Control (`s-maxage=3600, stale-while-revalidate=86400`) already absorbs traffic via the Vercel edge cache — net latency unchanged. |
| T-127-04 | Integrity | JSON.parse on health file fails on malformed data | mitigate | The parse runs inside the existing route try/catch; a throw routes to the 500 error path which already returns a generic `{ error: 'Failed to load pre-season squad' }`. No partial-envelope leaks. |
| T-127-05 | Repudiation | Pipeline failure (squad_health.py crash) leaves stale health on Blob | accept | run.py wraps the call in try/except with stderr logging matching every other pipeline step; existing operational pattern. |
</threat_model>
