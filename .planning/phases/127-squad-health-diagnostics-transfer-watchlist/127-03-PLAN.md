`usePlayers()` returns `UseQueryResult<MergedPlayer[]>` where MergedPlayer includes `id`, `web_name`, `element_type`, `team`, `now_cost`, `selected_by_percent`, `cost_change_event`, `team_short_name`. The hook stale-caches at 6h.

`useLineupNews()` returns `UseQueryResult<Map<number, LineupNewsPlayer> | undefined>` — `undefined` when the whole-file scrape is >48h stale. When defined, `map.get(id)` returns `{ news_headline: string | null, ...other }` or `undefined` when the player has no news entry. The whole-map 48h gate is the 48h freshness contract (RESEARCH.md Pitfall 4; no per-player `news_added` field exists).

`usePreSeasonSquad()` after Plan 04 returns `UseQueryResult<PreSeasonSquadResponse | null>`. In THIS plan (Wave 2), the hook still returns `PreSeasonSquad | null` because Plan 04 has not landed yet. The WatchlistTab must therefore call the hook through a type assertion that reads `data?.squad?.starters` defensively — Plan 04 will tighten the type after it ships.

Wait — that creates a type ordering problem. Resolution: WatchlistTab in this plan accesses the squad data via `data` cast through `as PreSeasonSquadResponse | null` ONLY where needed; once Plan 04 updates the hook, the cast becomes a noop. See task action for the exact pattern.

Actually a cleaner resolution: WatchlistTab reads `data?.squad` via the future shape because Plan 01 ALREADY ships the `PreSeasonSquadResponse` type. Plan 04 only updates `usePreSeasonSquad.ts` to use that type as the generic. Until Plan 04 lands, `data?.squad` is a type error. Workaround: this plan defines a tiny local type guard `function unwrapSquad(data: unknown): PreSeasonSquad | null` that handles both the legacy shape (data is the squad) and the new envelope shape (data.squad). Plan 04 deletes the guard.

`useTransferNews()` returns `UseQueryResult<TransferNewsArticle[]>` (Phase 125 hook). `buildConfirmedSigningMap(articles)` in `src/lib/buildConfirmedSigningMap.ts` returns `Map<number, string>` mapping `element_id` to the tooltip text `"<title> · <source-label>"`. `ConfirmedSigningBadge` from `src/components/shared/ConfirmedSigningBadge.tsx` accepts an optional `tooltipText?: string` and renders the green "Confirmed Signing" pill. The exact reuse pattern is visible in `src/components/gem-table/GemTable.tsx` lines 32, 395–400.
