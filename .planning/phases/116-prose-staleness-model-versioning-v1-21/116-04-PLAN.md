## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-04-01 | Tampering | `v.sample_gws` field on legacy version records | mitigate | `(v.sample_gws ?? 0) < 3` predicate treats absent/undefined as 0 → cold-start; legacy entries render safely as cold-start labels rather than crashing |
| T-116-04-02 | Information Disclosure | Versions table content | accept | Displayed values are public model-accuracy stats; no PII, no auth tokens |
| T-116-04-03 | Cross-Site Scripting | `v.formula_version`, `v.recorded_at` rendered as text | mitigate | All version-record fields rendered as JSX text children → React default escaping; no `dangerouslySetInnerHTML`. Existing render path (pre-Phase-116) is unchanged for these fields. |
| T-116-04-04 | Denial of Service | Very long `versions` list | accept | List is bounded by accuracy.py's append-on-version-change logic (one entry per FORMULA_VERSION); table rendering is O(n) and capped in practice at <50 versions. No DoS surface. |
| T-116-04-05 | Tampering | Untyped `v.sample_gws` (e.g. string instead of number) | mitigate | TypeScript declares `sample_gws?: number`; at runtime, the `< 3` comparison coerces non-numeric to NaN which is `false` against `< 3`, falling through to the `HitRateBadge` branch. This is acceptable — non-numeric `sample_gws` in cache is a pipeline bug, not a UI bug. |
| T-116-04-06 | Spoofing | N/A | accept | No auth boundary in the AccuracyTab. |
| T-116-04-07 | Repudiation | N/A | accept | No state mutation crosses a trust boundary in this plan. |
| T-116-04-08 | Elevation of Privilege | New `subTab === 'versions'` render branch | accept | Pure UI routing; no API call or capability gained. |
