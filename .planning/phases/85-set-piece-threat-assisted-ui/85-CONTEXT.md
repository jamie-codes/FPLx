<domain>
## Phase Boundary

Add delivery-quality tier badges (Elite / Good / Weak / —) to the FK and Corner taker rows in `SetPieceTakerPanel`. Extend `/api/set-pieces` to read `sp_quality.json` alongside `set_piece_changes.json`, compute quartile-based tier strings server-side, and return sp_quality fields merged into each `SetPieceTaker` object. **Two deliverables (both required):**
1. `/api/set-pieces` route extended to merge `sp_quality.json` and emit flat sp_quality fields + computed `sp_tier` on each taker
2. `SetPieceTakerPanel` renders delivery-quality badge in FK and corner taker rows with tooltip

<decisions>
## Implementation Decisions

### Badge Scope
- **D-01:** Delivery quality badge appears on **FK taker and corner taker rows only** — not on the penalty taker row. Penalty takers score; they don't assist shots. Adding a badge there would show "—" always (no delivery data), creating visual noise with no signal value. Claude chose this based on semantic correctness.

### Tier Computation
- **D-02:** The `/api/set-pieces` route computes the Elite/Good/Weak tier string server-side. After merging sp_quality.json, collect all non-null `delivery_quality_rank` values across all takers, compute quartile cut points (top 25% = Elite, middle 50% = Good, bottom 25% = Weak), then assign `sp_tier: 'Elite' | 'Good' | 'Weak' | null` per taker. Null when `delivery_quality_rank` is null. Frontend just renders the string — no rank math in the component.

### Type Shape
- **D-03:** Add sp_quality fields as **flat optional fields** on the existing `SetPieceTaker` interface:
  ```ts
  corner_danger_score?: number | null
  fk_danger_score?: number | null
  delivery_quality_rank?: number | null
  sp_sample_n?: number | null
  sp_tier?: 'Elite' | 'Good' | 'Weak' | null
  ```
  Matches the existing flat shape of `SetPieceTaker`. No nested object.

### Tooltip Implementation
- **D-04:** Use a native `title` attribute on the badge element — consistent with the existing "Changed" badge pattern in `TakerRow`. Exact wording (locked by SPQ-03): `"xG generated by this taker's assisted set-piece shots — measures how often their deliveries produce high-xG chances (n=[sp_sample_n] shots)"` with `sp_sample_n` value substituted. When `sp_tier` is null (insufficient data), badge shows "—" with no tooltip (title omitted).

### Tier Colour Mapping
- **D-05:** Define a new `SP_TIER_CLASSES` constant in `SetPieceTakerPanel.tsx` (not reusing `TIER_CLASSES` from AccuracyTab — different tier names and different colour assignments):
  ```ts
  const SP_TIER_CLASSES = {
    Elite: 'bg-green-100 text-green-800 dark:bg-green-900 dark:text-green-200',
    Good:  'bg-zinc-100 text-zinc-600 dark:bg-zinc-800 dark:text-zinc-400',
    Weak:  'bg-amber-100 text-amber-800 dark:bg-amber-900 dark:text-amber-200',
  }
  ```
  Insufficient data ("—") badge: `bg-zinc-100 text-zinc-400 dark:bg-zinc-800 dark:text-zinc-500`.

### Graceful Fallback
- **D-06:** When `sp_quality.json` is missing from Blob/local cache, the route logs the error and returns the existing taker data with sp_quality fields omitted (all undefined). `SetPieceTakerPanel` renders "—" badge (insufficient data) when `sp_tier` is undefined or null — no console noise, no blank card. Mirrors `set_piece_changes.json` fallback pattern.

### Claude's Discretion
- Badge layout: badge renders inline after the player name in `TakerRow`, matching the existing "Changed" badge placement. Use the same `ml-2 text-xs font-normal rounded px-2 py-1` class pattern.
- API merge order: read `set_piece_changes.json` first (primary artifact), then attempt `sp_quality.json` read in a separate try/catch. Failure of quality read does not fail the route.
- Vitest test: cover the missing-taker-in-quality-map case (SC-4) with a fixture that omits one taker from the quality map; assert the card renders "—" badge and no error is thrown.

</decisions>

<specifics>
## Specific Ideas

- Quartile tie-breaking: if fewer than 4 distinct ranked takers exist (unlikely but possible early-season), all non-null takers default to "Good" tier to avoid degenerate Elite/Weak split.
- Badge on "—" (insufficient data): `sp_tier` is null when `delivery_quality_rank` is null in sp_quality.json, or when the taker has no entry in sp_quality.json. Either condition → show "—" badge with no tooltip. Do not show tooltip for the "—" case.
- Blob prefix for sp_quality.json: confirm it matches the pipeline's Blob upload key. Phase 84 context doesn't specify — the planner should verify against `pipeline/run.py` Blob upload block.

</specifics>
