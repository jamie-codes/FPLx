  <action>
Add a scroll-based back-to-top button inside GemTable.tsx, mobile-only.

1. Add state declaration near the existing `isMobile` state:
```tsx
const [showBackToTop, setShowBackToTop] = useState(false)
```

2. Add a useEffect for the scroll listener (place near the existing isMobile useEffect):
```tsx
useEffect(() => {
  const handleScroll = () => setShowBackToTop(window.scrollY > window.innerHeight)
  window.addEventListener('scroll', handleScroll, { passive: true })
  return () => window.removeEventListener('scroll', handleScroll)
}, [])
```

The `{ passive: true }` option is required for mobile scroll performance — do NOT omit it.

3. Add the button JSX at the END of the GemTable return, AFTER the `overflow-x-auto` div, BEFORE the closing `</div>` of the root wrapper:
```tsx
{isMobile && showBackToTop && (
  <button
    onClick={() => window.scrollTo({ top: 0, behavior: 'smooth' })}
    className="fixed bottom-24 right-4 z-50 bg-zinc-900 text-white rounded-full w-10 h-10 flex items-center justify-center shadow-lg active:scale-95 transition-transform sm:hidden"
    aria-label="Back to top"
  >
    ↑
  </button>
)}
```

Class breakdown:
- `fixed bottom-24 right-4` — positioned in bottom-right, 6rem from bottom clears MobileNav (56px + safe area)
- `z-50` — above everything including the sticky filter bar (z-40)
- `bg-zinc-900 text-white` — high contrast floating button
- `rounded-full w-10 h-10` — 40px circle, meets 44px tap target with shadow overflow
- `active:scale-95` — consistent with project's tap feedback pattern
- `sm:hidden` — CSS-level hide on desktop as safety net (isMobile gate already prevents render)

Do NOT use IntersectionObserver. Do NOT add overflow-y to any container. Do NOT create a separate component file — keep it inline in GemTable.tsx.
