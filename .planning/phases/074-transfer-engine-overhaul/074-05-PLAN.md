Close the two critical gaps and the supporting warnings/info findings flagged by 074-VERIFICATION.md and 074-REVIEW.md after Phase 74 wave 3 execution. Specifically:

1. **CR-01**: The `−8 Hit` row is silently absent when `ftCount=1` (the default unauthenticated state). The mapper looks up `best2FTCombo` by `cost === 0` but the engine only emits `cost: 4` combos when `ftCount=1`. Fix the mapper so it falls back to the best `cost:4` combo when no `cost:0` combo exists.
2. **CR-02**: The "Free transfers" `<input>` is rendered and writable, but `derivedFtCount` never reads `freeTransfers`. Wire it into the unauthenticated branch of the `useMemo`.
3. **WR-01**: `badgeFor` ignores `isMarginal` for `combo-hit` rows; extend the check.
4. **WR-03**: `combo-hit` `isMarginal` should compare against `xPtsGainNet` (`xPtsGain − 4`), not raw `xPtsGain`.
5. **WR-04**: Remove the redundant inner `sell2.id === sell1.id` guard inside the `buy2` loop in `suggest-transfers.ts`.
6. **IN-01**: Consolidate `src/lib/__tests__/opportunity-cost.test.ts` into `src/lib/opportunity-cost.test.ts` and delete the duplicate.
7. **IN-03**: Replace `transition-colors` + `transition-transform` with single `transition` on the Submit button.

Plus add the two requested unit tests:
- A test verifying CR-01 (−8 Hit row IS present when `ftCount=1` and a single `cost:4` combo is supplied).
- A test verifying CR-02 (when unauthenticated and `freeTransfers=2`, the unauth fallback resolves to `2`).

Purpose: Restore TFX-03 ("user can view 1FT, 2FT, −4 hit, −8 hit scenarios simultaneously") for the majority-user `ftCount=1` state, and restore TFX-05 ("when unauthenticated, the user can manually enter…and it is used for all affordability checks") so the FT-count manual input is honoured.
