## Spacing Scale

Declared values (multiples of 4 only). Project uses Tailwind utility classes throughout — no custom spacing tokens.

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `gap-1`, `px-1`, `py-1` | Icon gaps, tight inline spacing |
| sm | 8px | `gap-2`, `px-2`, `py-2` | Element gaps within a row, badge padding |
| md | 16px | `p-4`, `gap-4` | Card/panel padding — primary internal padding for all TransferPanel sections |
| lg | 24px | `space-y-6` | Section breaks within TransferPanel |
| xl | 32px | `mt-8` | Vertical separation between major sections |

Exceptions:
- Table cell padding: `px-3 py-2` (12px × 8px) — matches existing OCS table rows (source: OpportunityCostTable.tsx)
- Touch targets: `min-h-[44px]` on GwToggle buttons — inherited from GwToggle.tsx (FtToggle is removed; GwToggle touch target retained)
- Bank balance input inline layout: `py-1.5 px-3` — matches existing FPL Team ID and Free Transfers inputs in TransferPanel.tsx form

> **Inherited project constants (read-only, not spacing tokens):** `py-1.5` (6px) matches existing form inputs in `TransferPanel.tsx` (Team ID and FT count fields); `min-h-[44px]` is the accessibility touch-target minimum in `GwToggle.tsx`. Both are inherited from existing code and are not introduced by Phase 74. They are exempt from the 4px-multiple rule as they are codebase constants, not grid scale values.

**Source:** TransferPanel.tsx `p-4 space-y-3`, OpportunityCostTable.tsx cell padding, FtToggle.tsx `min-h-[44px]`.

## Visuals

**Primary focal point:** The 5-row OCS table body. The "Transfer Opportunity Cost" section heading is the visual entry point; all other UI elements (GwToggle, bank balance sub-line, badge column, disabled reason label) are subordinate to the table.

All visual hierarchy follows the zinc-based dark/light scale established in Phase 50. No decorative elements, illustrations, or imagery are introduced in this phase. Data density is the primary visual concern — the table must be scannable at a glance across all 5 rows without visual noise.

| Marginal | `bg-amber-100 dark:bg-amber-900` | `text-amber-800 dark:text-amber-200` | 2FT or −8 Hit row where xPtsGain is within 1.0 xPts of break-even |

**Disabled row treatment (new in Phase 74, per D-05):**

Unaffordable rows are shown-but-disabled — NOT silently hidden.

| Property | Value |
|----------|-------|
| Row opacity | `opacity-50` |
| Reason label | `text-xs text-red-600 dark:text-red-400` below the badge in the Label column |
| Reason label copy | "Over budget by £{X}m" (X to 1 decimal place) |
| Strikethrough | `line-through text-zinc-400 dark:text-zinc-600` on the xPts Gain cell value only |
| Hover | `hover:bg-zinc-50 dark:hover:bg-zinc-800/50` still applies — row is scannable, not inert |
| `aria-disabled` | `aria-disabled="true"` on the `<tr>` element |

Rationale: Opacity-50 communicates "this exists but is currently out of reach" without removing the row from the decision context. The reason label names the shortfall precisely so the user knows how close they are.

## Layout: Load Your Squad Form — Bank Balance Field

The bank balance input is added to the existing "Load Your Squad" form card, as the third field after "FPL Team ID" and "Free transfers". Same `flex-col gap-1` pattern as the existing inputs.

```
<div class="flex flex-col gap-1">
  <label for="bankBalance" class="text-sm text-zinc-600 dark:text-zinc-400">
    Bank balance
    <span title="Your available transfer budget in £m. Pre-filled from FPL when connected."
          class="text-zinc-400 cursor-help underline underline-offset-2 decoration-dotted ml-1">
      ?
    </span>
  </label>
  <div class="relative flex items-center">
    <input
      id="bankBalance"
      type="number"
      min="0"
      max="20"
      step="0.1"
      value={manualBank}
      onChange={...}
      placeholder="0.0"
      class="border border-zinc-300 dark:border-zinc-600 rounded px-3 py-1.5 pr-10
             text-base sm:text-sm text-zinc-900 dark:text-zinc-100
             bg-white dark:bg-zinc-800
             focus:outline-none focus:ring-1 focus:ring-zinc-400
             w-full sm:w-28"
    />
    <span class="absolute right-3 text-xs text-zinc-400 dark:text-zinc-500 pointer-events-none">
      £m
    </span>
  </div>
</div>
```

**Authentication states:**

| State | Field value | Field appearance |
|-------|-------------|-----------------|
| Authenticated + squad loaded | Pre-filled from `entry_history.bank / 10` (tenths → £m) | `text-zinc-900 dark:text-zinc-100` — editable, no special styling |
| Authenticated, annotation | Below field: `text-xs text-zinc-400 italic` — "From your FPL account — override if needed." | Annotation only when `isAuthenticated && myTeamData` |
| Unauthenticated | Empty string / 0 | Standard placeholder "0.0"; no annotation |

**Internal conversion:** `manualBank` state stores the raw £m float (e.g. `2.5`). Multiply by 10 before passing to engine to convert to tenths (e.g. `25`). This matches `entry_history.bank` units used throughout the codebase.

**Source:** D-09, D-10, D-11, D-12. Pattern: TransferPanel.tsx existing input fields (lines 202–236).

## Layout: OpportunityCostTable — 5-Row Format

The table always renders 5 rows when squad data is loaded. Row order is fixed.

### Table column layout (unchanged from Phase 50)

| Column | Width | Content |
|--------|-------|---------|
| Option | 20% | Scenario label |
| Player Move | 35% | Transfer pair(s); Roll shows "—" |
| xPts Gain (net) | 20% | Formatted value; disabled rows show strikethrough |
| Break-even | 15% | "N GWs" or "—"; `hidden sm:table-cell` |
| Label | 10% | Coloured badge + (for disabled rows) reason label below |

**Mobile behaviour (unchanged):** Break-even column `hidden sm:table-cell`. All other columns always visible.

### Row definitions

**Row 1 — Roll (always first, always enabled):**
- Option label: "Roll"
- Player Move: "—"
- xPts Gain: "0.0"
- Break-even: "—"
- Badge: zinc "Baseline"
- Disabled: never

**Row 2 — 1 FT (single free transfer):**
- Option label: "1 FT" (with sub-label `text-xs text-zinc-500` — "Free" when cost:0; nothing when cost:4 and user has 1 FT remaining)
- Player Move: "Sell {sell.web_name} → Buy {buy.web_name}"
- xPts Gain: "+{N.N} xPts"
- Break-even: "—" (free transfer has no break-even period)
- Badge: green "Free" when cost:0; red "Hit" when cost:4 (1 FT with 0 banked FTs = hit)
- Disabled: when `bank < (buy.now_cost − sell_price)` — show `opacity-50` + reason label

**Row 3 — 2 FT (two free transfers):**
- Option label: "2 FT"
- Player Move: Two stacked transfer lines
- xPts Gain: "+{N.N} xPts" (net; includes no hit cost when both FTs available)
- Break-even: "{N} GWs" or "—"
- Badge: green "Free" or amber "Marginal — verify" when isMarginal
- Disabled: when combined cost exceeds bank — show `opacity-50` + reason label

**Row 4 — −4 Hit:**
- Option label: "−4 Hit"
- Player Move: "Sell {sell.web_name} → Buy {buy.web_name}"
- xPts Gain: "+{N.N} xPts" (net of 4pt hit) with xs sub-text "−4pt hit"
- Break-even: "{N} GWs"
- Badge: red "Hit"
- Disabled: when bank insufficient — show `opacity-50` + reason label

**Row 5 — −8 Hit (new in Phase 74, per D-06/D-07):**
- Option label: "−8 Hit"
- Player Move: Two stacked transfer lines (same player pair as 2FT row per D-07)
- xPts Gain: "+{N.N} xPts" (net of 8pt hit; may be negative) with xs sub-text "−8pt hit"
- Break-even: "{N} GWs"
- Badge: red "Hit" (or amber "Marginal — verify" when net gain < 1.0)
- Disabled: when combined transfer cost exceeds bank — show `opacity-50` + reason label

**Negative net gain display:** When `xPtsGainNet < 0` (hit not worth it), format as `"{N.N} xPts"` (no plus sign; negative number shown directly, e.g. "−1.2 xPts"). No special colour change beyond existing text colour — the negative value communicates the situation clearly alongside the break-even figure.

**Source:** D-05 (disabled row treatment), D-06 (−8 hit always present), D-07 (−8 hit reuses 2FT pair), D-08 (label correctness via derivedFtCount).

### Bank balance display in OCS

The remaining bank balance after each scenario is shown as a secondary sub-line in the xPts Gain cell (below the xPts figure):

```
+2.1 xPts
Bank: £1.3m
```

Format: `text-xs text-zinc-500 dark:text-zinc-400` — "Bank: £{X.X}m"
Roll row bank: shows current bank unchanged.
Disabled row bank: still shows projected bank (may be negative — shown as "Bank: −£0.5m" in red-400).

**Source:** TFX-04 requirement ("projected bank balance remaining after the move").

## Interaction Contract

### Bank balance input

- Type: `type="number"` with `step="0.1"` and `min="0"` — decimal allowed, no negative values
- On change: update `manualBank` local state; engine recomputes on next render via useMemo dependency
- Authenticated pre-fill: runs on `myTeamData` change via useEffect; sets `manualBank` to `myTeamData.entry_history.bank / 10`; subsequent user edits override without re-fill until auth changes
- Form submit: bank balance is NOT part of the form submit action (Load Squad). It is a live-filter input — changes take effect immediately on the OCS table
- Accessibility: `<label>` with `for` attribute; `aria-label` not required (explicit label present)

### GwToggle (OCS section header)

- Unchanged from Phase 50 — same component, same behaviour
- Component: `GwToggle` (src/components/gem-table/GwToggle.tsx)
- State: local `useState<OptimiserHorizon>(1)` named `ocsHorizon` in TransferPanel
- Default: 1 GW
- Does not share state with OptimiserPanel

### Disabled row interaction

- `<tr aria-disabled="true">` — row is visible and scannable
- No click action on any OCS row (rows are read-only comparison data in all states)
- `opacity-50` does not affect hover behaviour — `hover:bg-zinc-50 dark:hover:bg-zinc-800/50` still applies
- Reason label is always visible (not tooltip-gated) so it is readable on mobile without hover

### Table row hover (unchanged)

`hover:bg-zinc-50 dark:hover:bg-zinc-800/50` on `<tr>`. No click action.

### Loading / empty states

- OCS section only renders when `squadData && scoredPlayers.length > 0` (unchanged gate)
- When `suggestTransfers()` returns no suggestions: Roll row renders alone with footnote (unchanged from Phase 50)
- Bank balance input renders immediately in the Load Squad form (before squad is loaded) — matches the FT count input which is also always visible

## States Inventory

| State | Trigger | Visual treatment |
|-------|---------|-----------------|
| Pre-load | No squad submitted | OCS section hidden; bank balance input visible in Load Squad form |
| Loading | Squad fetch in-flight | OCS section hidden (same gate as TransferPanel) |
| Squad loaded | `squadData && scoredPlayers.length > 0` | All 5 OCS rows render |
| Row affordable | `bank >= transfer_cost` | Normal row — full opacity, no reason label |
| Row unaffordable | `bank < transfer_cost` | `opacity-50`, `aria-disabled="true"`, "Over budget by £Xm" reason label, strikethrough on xPts value |
| Row — negative net gain | `xPtsGainNet < 0` | No special colour; negative value displayed directly (e.g. "−1.2 xPts"); break-even shows how long to recover |

| Unauthenticated | `!isAuthenticated` | Bank input empty/0; no annotation |
| Bank overridden by user | User edits pre-filled value | No annotation change — override is silent; annotation remains visible as reminder of source |
| Chip: Free Hit | `active_chip === 'freehit'` | OCS section hidden or shows chip warning (existing chip warning pattern in TransferPanel) |
| Chip: Wildcard | `active_chip === 'wildcard'` | OCS section visible; all scenarios show as Free (0 cost) rows; existing wildcard banner above |
| No improvements | `suggestTransfers()` returns empty | Roll row only + "No transfer improvements found" footnote |
