## Visuals

Phase 9 adds three sortable numeric columns to GemTable and a projected points row in TransferPanel suggestion cards. The visual hierarchy must remain table-first — new columns follow existing column width conventions (whitespace-nowrap, px-2 py-1 cells).

### GW Horizon Toggle

A three-button toggle control positioned above the GemTable to the right of the PositionFilter. Renders the labels "1 GW", "3 GW", "5 GW". Only one GW horizon is active at a time. The active button uses `bg-zinc-900 text-white rounded`; inactive buttons use `bg-white text-zinc-700 border border-zinc-300 rounded`. The toggle renders as a flex row with no gap between buttons (rounded-l on first, rounded-r on last, flat inner edges) to form a joined button group.

Button group class pattern:
```
flex rounded overflow-hidden border border-zinc-300
```
Each button:
```
px-3 py-1 text-sm font-medium
```
Active modifier:
```
bg-zinc-900 text-white
```
Inactive modifier:
```
bg-white text-zinc-700 hover:bg-zinc-50
```

### Projected Points Columns in GemTable

Three new sortable columns added to GemTable: `proj_pts_1gw`, `proj_pts_3gw`, `proj_pts_5gw`. Only one column is visible at a time — toggled by the GW horizon control. The visible column is the active GW horizon column; the other two are hidden via column visibility API.

Column header labels:
- 1 GW active: "Proj Pts"
- 3 GW active: "Proj Pts (3)"
- 5 GW active: "Proj Pts (5)"

Values are displayed as absolute FPL points with one decimal place: `7.2`, `14.5`, `22.1`. No normalisation applied — values must be in the 2–15 range for regular starters per REQUIREMENTS (PROJ-04, v1.1 Roadmap locked decision).

Column position in GemTable: insert after existing "Risk" column and before "Trend":
```
... | Status | Risk | Proj Pts | Trend | Next 5
```

### Projected Points in TransferPanel Suggestion Cards

Each suggestion card (sell → buy row) gains a projected points line in the metadata row beneath the player names. Displayed as: `Proj pts (1 GW): {sell_pts} → {buy_pts}`. The GW horizon shown in TransferPanel is always 1 GW (next-GW horizon is the most actionable signal for transfer decisions — multi-GW view deferred to a future phase).

Rendered as `text-xs text-zinc-500` inline with the existing "Gem improvement" and "Cost" metadata:
```
Gem improvement: +0.14 | Cost: £8.5m (approx) | Proj pts (1 GW): 6.1 → 9.3
```

### New: GwToggle component

**File:** `src/components/gem-table/GwToggle.tsx`

**Props:**
```typescript
{ value: 1 | 3 | 5; onChange: (v: 1 | 3 | 5) => void }
```

**Rendering contract:**
```tsx
<div className="flex rounded overflow-hidden border border-zinc-300">
  {([1, 3, 5] as const).map((gw) => (
    <button
      key={gw}
      onClick={() => onChange(gw)}
      className={`px-3 py-1 text-sm font-medium transition-colors ${
        value === gw
          ? 'bg-zinc-900 text-white'
          : 'bg-white text-zinc-700 hover:bg-zinc-50'
      }`}
    >
      {gw} GW
    </button>
  ))}
</div>
```

**Accessibility:** Each button is a native `<button>` element. The active button should have `aria-pressed="true"`; inactive buttons `aria-pressed="false"`. Wrap the group in `<div role="group" aria-label="Projected points horizon">`.

## Interaction States

### GwToggle interaction states

| State | Rendering |
|-------|-----------|
| 1 GW active (default) | "1 GW" button: bg-zinc-900 text-white; others: bg-white text-zinc-700 |
| 3 GW active | "3 GW" button: bg-zinc-900 text-white; others: bg-white text-zinc-700 |
| 5 GW active | "5 GW" button: bg-zinc-900 text-white; others: bg-white text-zinc-700 |
| Hover on inactive button | hover:bg-zinc-50 |
| Click | Calls onChange(gw) synchronously — no loading state (data already loaded) |

### GemTable projected points column states

| State | Rendering |
|-------|-----------|
| Data loaded | proj_pts value rendered as `{value.toFixed(1)}` — e.g. "7.2" |
| Column sorted ascending | Sort indicator ▲ appended to header (existing pattern) |
| Column sorted descending | Sort indicator ▼ appended to header (existing pattern) |
| Data loading | Parent GemTable shows "Loading players..." — column not rendered |
| Error state | Parent GemTable shows error message — column not rendered |
| proj_pts value is 0.0 | Renders "0.0" (never em-dash — all 6 projected fields are non-null per Phase 07-02 locked decision) |

### TransferPanel proj pts display states

| State | Rendering |
|-------|-----------|
| Data loaded | "Proj pts (1 GW): 6.1 → 9.3" inline in metadata row |
| No suggestions (SAVE result) | Metadata row not rendered (suggestion cards are not rendered) |
| CHIP_WARNING result | Metadata row not rendered (suggestion cards are not rendered) |
