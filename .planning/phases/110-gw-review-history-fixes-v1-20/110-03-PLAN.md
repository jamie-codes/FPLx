<objective>
Fix FIX-06 — the captain delta column on the Back / Decision History view shows `—` for every row because `modelCeilingPts` is hardcoded to `null` in the API route (CR-01 from Phase 96). The fix replaces the hardcoded null with a request-time `element-summary/{id}/` lookup, deduplicated across unique ceiling element ids, populating actual model-ceiling points so `computeRegret` produces real regret values.

Purpose: Phase 96 shipped the captain regret backtester with an explicit deferral comment (CR-01) — the snapshot schema didn't store actual_pts at the time, so the route returned null rather than a misleading xPts-vs-actual comparison. This phase resolves that deferral the right way: a request-time lookup against the FPL element-summary endpoint, which carries full season history per player. With a single ceiling player like Salah typically being the ceiling across many GWs, deduplication cuts the typical fetch count from 38 to 1-5.

Output: A new Step 2b in `decision-history/route.ts` that collects unique non-null ceiling ids from the snapshots, fans out `element-summary/{id}/` requests via `Promise.allSettled` (so single failures never abort the others), builds `actualPtsMap: Map<elementId, Map<gwRound, actualPts>>`, and rewires the Step 3 RegretEntry assembly so `modelCeilingPts` derives from `actualPtsMap.get(modelCeilingId)?.get(gw) ?? null`. Plus a brand-new test file (this is the Wave 0 gap from VALIDATION.md) covering RED→GREEN, SC-5 fallback, and the dedup invariant.
</objective>
