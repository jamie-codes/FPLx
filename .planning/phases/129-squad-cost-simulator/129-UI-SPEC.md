## Component Inventory

New UI elements for this phase, all added inline to `NextSeasonPlannerTab.tsx`:

### 1. Budget Slider Block

Location: inside the "Pre-Season Squad" section (`<div>` containing `<h3>Pre-Season Squad</h3>`), immediately after the section heading, before `squadSection` renders. Renders only when `data` is non-null (squad data available).

Structure:
```
<div className="py-2">
  <label className="text-sm text-zinc-700 dark:text-zinc-300 font-semibold">
    Budget: £{(sliderValue).toFixed(1)}m
  </label>
  <input
    type="range"
    min={80}
    max={120}
    step={0.5}
    value={sliderValue}
    onInput={...}         // updates sliderValue on every tick (visual only)
    onPointerUp={...}     // commits to committedBudget
    onKeyUp={...}         // 300ms debounce commits to committedBudget
    className="w-full mt-2"
    style={{ background: <amber-gradient or zinc> }}
    aria-label="Budget slider"
    aria-valuemin={80}
    aria-valuemax={120}
    aria-valuenow={sliderValue}
    aria-valuetext={`£${sliderValue.toFixed(1)}m`}
  />
</div>
```

Slider track CSS (inline style, applied dynamically):
- When `health?.min_feasible_budget_greedy` is non-null:
  ```
  background: `linear-gradient(to right, #f59e0b 0%, #f59e0b ${threshold}%, #71717a ${threshold}%, #71717a 100%)`
  ```
  where `threshold = ((health.min_feasible_budget_greedy - 80) / 40) * 100`
- When `health` is null or `health.min_feasible_budget_greedy` is null: single-colour neutral zinc track — `background: #71717a`. Slider remains fully interactive.

Label format: `Budget: £100.0m` — always one decimal place, £ prefix, m suffix, space before value.

States:
- Default (no drag): label shows `£100.0m`; track shows amber zone if health present
- Dragging: label updates every tick to current `sliderValue`; track gradient updates accordingly
- Committed: `committedBudget` triggers `buildPreSeasonSquad` via `useDeferredValue`

Source: CONTEXT.md D-05 (initial value £100m), D-10 (amber gradient technique), D-11 (null health = zinc-only), Specifics section (gradient string, threshold formula).

### 2. Infeasibility Message

Location: directly above `FormationGrid` (or above the squad section content), rendered when `buildPreSeasonSquad()` returns null for the committed budget. The formation grid continues to display the last valid committed squad behind/below this message — it is additive, not a replacement.

Variants:

**Variant A** — `health.min_feasible_budget_greedy` is non-null:
```
<p className="text-sm text-amber-600 dark:text-amber-400 py-2">
  No squad possible at £X.Xm — try £Y.Ym+
</p>
```
where X = `committedBudget / 10` (1 decimal), Y = `health.min_feasible_budget_greedy` (1 decimal).

**Variant B** — `health` is null OR `health.min_feasible_budget_greedy` is null:
```
<p className="text-sm text-amber-600 dark:text-amber-400 py-2">
  No squad possible at £X.Xm
</p>
```

Color rationale: `text-amber-600 dark:text-amber-400` matches the amber slider track warning — same semantic signal, not full destructive red.

Source: CONTEXT.md D-07 (grid stays visible showing last valid squad), D-08 (Variant A copy verbatim), D-09 (Variant B copy verbatim), D-10 (amber = warning, not error).

### 3. Health Indicator (existing — no visual change)

The existing `<HealthIndicator health={health} />` in Phase 127 remains below the formation grid. This phase does not alter its appearance. The cost slider sits above the formation grid; the health indicator sits below it.

Source: CONTEXT.md §code_context — "Health indicator in NextSeasonPlannerTab below the cost slider showing greedy null rate + min viable budget."

## Interaction Contract

### useDeferredValue Pattern

Two states coexist in `NextSeasonPlannerTab`:

1. `sliderValue` (number, £m) — updated `onInput` every tick. Drives the label display and the CSS gradient. Does NOT trigger `buildPreSeasonSquad`.
2. `committedBudget` (number, £m) — updated only on:
   - `onPointerUp` (mouse/touch release)
   - `onKeyUp` after a 300ms `setTimeout` debounce (keyboard navigation)

`deferredBudget = useDeferredValue(committedBudget)` feeds into `buildPreSeasonSquad(inputs.players, scoreMap, deferredBudget * 10, teamCap)`. The formation grid renders from `deferredBudget` (not `sliderValue`) — slider stays visually responsive at every tick.

### Client-Side Score Map Hydration

`scoreMap` arrives from the API as `Record<string, number>` (CONTEXT.md D-03). Client reconstructs: `new Map(Object.entries(inputs.scoreMap).map(([k, v]) => [Number(k), v]))`. This is a one-time hydration on first load; subsequent recomputes use the in-memory Map.

### lastValidSquad Pattern

`lastValidSquad` state (initialised from `data.squad` on first load). On each commit:
- If `buildPreSeasonSquad(...)` returns non-null: update `lastValidSquad` to new result.
- If returns null: keep `lastValidSquad` at previous value; show infeasibility message above grid.

Formation grid always renders from `lastValidSquad` — never null after first load. This prevents a blank grid at infeasible budgets.

### Slider Initialization

On first mount (before any drag), slider shows £100.0m. Formation grid shows `data.squad` from the API (ILP or greedy, as the server resolved). Client greedy result only replaces this after the first pointer release or keyboard commit.

Source: CONTEXT.md D-05, D-06 (slider at £100m; API squad until first commit).

### No Round-Trip Per Tick

`/api/pre-season-squad?include=inputs` is fetched once on tab load (staleTime 6h, matching current `usePreSeasonSquad` pattern). All subsequent recomputes are client-side only using cached `inputs`.

## Accessibility Notes

- Budget slider: native `<input type="range">` with explicit `aria-label`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, `aria-valuetext`. Screen readers announce the current budget value.
- Slider wrapper: `min-h-[44px]` touch target on the container div.
- Infeasibility message: plain `<p>` — no role needed; reads naturally in document flow above the formation grid.
- Amber color distinction: amber text + amber track are used for "warning" (infeasible range), which is distinct from the destructive red (`--color-negative`). Color alone is not the only signal — the infeasibility message provides text confirmation.
