## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| suggestTransfers output → capByPosition → OCS rows | Engine output is the trust authority; capByPosition narrows the discriminated union, OCS rows compute from the capped list |
| ocsTotalsByPosition Map (number→number) → JSX template interpolation | Numeric values from Map render into DOM text and data-testid attribute |
| New optional prop `totalsByPosition` on OpportunityCostTable | Backward-compat surface: any caller omitting the prop sees the existing behavior unchanged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-08 | Tampering | ocsTotalsByPosition keys could be unexpected element_type values (e.g., 0 or 5) if engine output had bad data | accept | Engine validates element_type at source (FPL bootstrap is the canonical 1–4 enum). Defensive fallback `POSITION_LABELS[pos] ?? '??'` in the footnote prevents crash if an unknown key slips through; the testid uses the literal numeric key in that case. |
| T-112-09 | Information Disclosure | Footnote reveals pre-cap totals ("Showing top 3 of 12 MID suggestions.") | accept | Same as T-112-03 / T-112-06 — derived from public FPL data; rendering is the stated D-07 requirement. No PII. |
| T-112-10 | Spoofing | A bad actor could fabricate a `totalsByPosition` Map via React DevTools to display false counts | accept | DevTools-level state tampering is out of scope for client UI; the only side effect is misleading text shown to the same user; no privilege boundary crossed. |
| T-112-11 | Repudiation | If `highOwnershipAbsent` now reports a previously-suggested player as "absent" because the cap dropped it, the user could be confused about why an obvious pick "isn't suggested" | mitigate | This is by design per CONTEXT.md ("the user sees what we actually surface"). The cap-footnote-{POSITION} message gives the user a transparency signal: "you're seeing top 3 of N — there are more candidates the engine considered". The footnote IS the mitigation. |
</threat_model>
