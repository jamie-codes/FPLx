## Visuals

Phase 10 introduces two new UI surfaces: (1) a Buy/Hold/Sell verdict column in SquadView and (2) a standalone CaptaincyPanel component. Both are scoped to the existing transfer tab — no new page or route is added.

### Buy/Hold/Sell Verdict Badge

A new "Rec" column in SquadView's per-position tables, positioned after the existing "Risk" column. Each starting-XI row displays exactly one verdict badge: Buy, Hold, or Sell. Bench players (position >= 12) do not display a verdict badge — the cell is empty.

Badge rendering contract (follows MinsRiskBadge.tsx structure exactly):

```
<span className="inline-block text-xs font-normal {text} {bg} rounded px-2 py-1"
      title="{tooltip}">
  {label}
</span>
```

Column position in SquadView table:

```
Player | Team | Price | Own% | Mins | Gem | Status | Risk | Rec
```

The "Rec" column header uses `text-zinc-500 font-medium whitespace-nowrap` consistent with all other column headers in SquadView.

### CaptaincyPanel Component

A new section rendered beneath the SquadView within the existing TransferPanel container. Visible only when squad data is loaded (same conditional as the existing SquadView section). Renders a ranked list of 5 captaincy candidates with:

- Rank number (1–5)
- Player name and team short name
- Projected captain points for next GW (proj_pts_1gw × 2, displayed as e.g. "14.2 pts (C)")
- A type badge: either "Safe" or "Upside"
- MinsRisk badge (reused from MinsRiskBadge.tsx)

Panel layout:

```
[Section heading: "Captaincy Picks — GW {next_gw}"]
[Rank] [Name] [Team] [Proj Cap Pts]  [Type badge] [Risk badge]
  1    Salah   LIV    18.4 pts (C)   [Safe]        [Nailed]
  2    Haaland  MCI   16.0 pts (C)   [Safe]        [Nailed]
  3    Palmer   CHE   14.4 pts (C)   [Upside]      [Likely start]
  4    Watkins   AVL  12.6 pts (C)   [Upside]      [Nailed]
  5    Saka     ARS   12.2 pts (C)   [Safe]        [Nailed]
```

Container class pattern (consistent with existing panel sections):

```
rounded border border-zinc-200 p-4 space-y-3
```

Section heading class:

```
text-base font-semibold text-zinc-900 mb-3
```

Each candidate row:

```
rounded border border-zinc-100 bg-zinc-50 px-3 py-2
flex items-center gap-3
```

Rank number:

```
text-sm text-zinc-400 w-4 shrink-0
```

Player name:

```
text-sm font-medium text-zinc-900 flex-1
```

Team short name:

```
text-sm text-zinc-500
```

Projected captain points:

```
text-sm text-zinc-700 whitespace-nowrap
```

Format: `{value} pts (C)` where value is `(proj_pts_1gw * 2).toFixed(1)`.

Type badge and MinsRisk badge are rendered inline after the projected pts, consistent with badge patterns in MinsRiskBadge.tsx.

## Component Inventory

### Modified: SquadView.tsx

Add a "Rec" column to each per-position table. The column receives the verdict for each player from the parent (TransferPanel or wherever SquadView is hosted). The verdict value type is `'buy' | 'hold' | 'sell' | null`.

- For starting-XI players (pick.position < 12): render `<VerdictBadge verdict={verdict} />`
- For bench players (pick.position >= 12): render empty cell

The `VerdictBadge` component is declared in the same file or co-located in `src/components/shared/`.

**Props change:** SquadView receives an optional `verdicts: Map<number, 'buy' | 'hold' | 'sell'>` prop (keyed by player element id). Null/missing verdicts render an empty cell.

**Props:**

### New: CaptaincyPanel component

**File:** `src/components/captaincy/CaptaincyPanel.tsx`

**Props:**
```typescript
interface CaptaincyCandidateRow {
  player: ScoredPlayer

        <MinsRiskBadge minsRisk={c.player.mins_risk} />
      </div>

  </div>
</div>
```

## Interaction States

### VerdictBadge states

| State | Rendering |
|-------|-----------|
| verdict = 'buy' | bg-green-100 text-green-800 "Buy" badge |
| verdict = 'hold' | bg-zinc-100 text-zinc-700 "Hold" badge |
| verdict = 'sell' | bg-red-100 text-red-700 "Sell" badge |
| verdict = null (bench player) | Empty cell — no badge rendered |
| Hover | No hover state — badge is display-only, not interactive |

### CaptaincyPanel states

| State | Rendering |
|-------|-----------|
| 5 candidates available | All 5 rows rendered, rank 1–5 |
| Fewer than 5 candidates (edge case) | Render all available candidates, no placeholder rows |
| Squad not loaded | Panel not rendered (same conditional gate as SquadView) |
| Players data loading | Panel not rendered |
| No starting XI players (edge case) | Panel not rendered — empty candidates array |

### SquadView verdict column states

| State | Rendering |
|-------|-----------|
| Starting-XI player with verdict | VerdictBadge rendered |
| Starting-XI player, no verdict in map | Empty cell |
| Bench player | Empty cell (no verdict shown for bench players) |
| Loading | Parent not rendered |
