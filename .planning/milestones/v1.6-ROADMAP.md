# Milestone v1.6: Squad Optimiser

**Status:** ✅ SHIPPED 2026-05-01
**Phases:** 42-46
**Total Plans:** 12

## Overview

Delivered a full in-browser squad optimiser with configurable GW horizon, captain/VC recommendation, transfer-aware suggestions with break-even indicator, and chip mode support (Wildcard, Free Hit, Bench Boost). Also shipped a form signal improvement to the xPts engine, gated by backtest against the accuracy pipeline. The entire optimiser is client-side pure TypeScript — no backend changes required.

## Milestone Summary

**Key Decisions:**

- Pure TS enumeration for optimiser (C(15,11)=1,365 subsets, <1ms) — no WASM solver needed; `glpk.js` explicitly ruled out
- Form signal gated by accuracy backtest (`form_signal_enabled` gate in `accuracy_backtest.json`) — never ships without measurable improvement
- `optimiseLineup` extended via `chipMode` param rather than forked — chip modes reuse the same engine, no parallel code path
- Budget arithmetic uses integer tenths throughout; `selling_price` (not `now_cost`) used in transfer-aware mode
- `changeCount` uses set-difference (optimised starters not in current XI) — avoids overcounting when sort reshuffles pairs
- `isPromoted` flag uses `currentId` (the player promoted into XI from bench) — plan spec had inversion error, caught in execution
- Test fixtures require valid single-GK formations (4-3-3, 5-3-2) for deterministic no-change/single-change assertions
- 2-FT `xPtsGain` uses additive approximation (sum of individual deltas) — full `optimiseLineup` re-run per combo not warranted
- `FtToggle` disabled in FH chip mode (FH uses full pool, free transfers irrelevant)

**Issues Resolved:**

- `isPromoted` inversion bug caught before shipping (plan spec error corrected in execution)
- `changeCount` overcounting when sort reshuffled pairs — set-difference approach adopted
- `MIN_SLOTS` validation enforced post-launch code-review fix (CR commit after Phase 46 complete)
- Mobile Bench Boost bench row opacity fix applied in same CR commit

**Issues Deferred:**

- Pre-existing TypeScript errors in `captain-picks.test.ts` (5 TS2554 errors) — existed before Phase 45, out of scope, deferred
- `form_signal_enabled` gate: whether the form signal actually improved hit rate above 16.7% baseline — gate logic exists, production validation pending a full pipeline run

**Technical Debt Incurred:**

- ACC-03 gate validation requires a real pipeline run with live data — local backtest only; gate may or may not fire in production
- `suggestTransfers()` 2-FT gain is an additive approximation — could be made exact with a per-combo `optimiseLineup` re-run if needed
