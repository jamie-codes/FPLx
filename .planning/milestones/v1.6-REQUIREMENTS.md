## v1.6 Requirements

### Lineup Optimiser (OPT)

- [x] **OPT-01**: User sees the best starting 11 + bench order + auto-selected formation from their current 15-player squad, scored by xPts — Phase 43
- [x] **OPT-02**: User can select a 1 / 3 / 5 GW horizon; the optimiser scores and ranks players by the corresponding xPts window — Phase 43
- [x] **OPT-03**: Captain and vice-captain are identified within the optimised lineup (captain = highest xPts_90th_1gw starter; VC = second) — Phase 43
- [x] **OPT-04**: Bench order respects FPL rules: GK isolated at bench slot 0; outfield bench positions ordered by xPts descending — Phase 43
- [x] **OPT-05**: BGW players are hard-excluded from the starting XI; a warning is shown if fewer than 11 eligible players exist in the squad — Phase 43

### Comparison Output (CMP)

- [x] **CMP-01**: User sees current lineup vs optimised lineup side-by-side, with xPts delta shown per slot — Phase 44
- [x] **CMP-02**: A diff headline summarises the delta: "Changes: N players | +X.X xPts gain" — Phase 44
- [x] **CMP-03**: On mobile (< 640px), current and optimised lineups stack vertically with a Changes badge; only changed rows are highlighted — Phase 44

### Transfer-Aware Mode (TFR)

- [x] **TFR-01**: User can enable transfer-aware mode that factors in 1–2 available free transfers when optimising — Phase 45
- [x] **TFR-02**: Transfer suggestions are shown alongside the optimised lineup (Out | In | Cost | xPts gain per suggestion) — Phase 45
- [x] **TFR-03**: A hit break-even indicator is shown for each -4pt hit: "Breaks even in X GWs based on xPts gain" — Phase 45

### Chip Modes (CHIP)

- [x] **CHIP-01**: Wildcard mode removes transfer constraints entirely and selects the best 15 from all available players, then shows the best XI from that squad — Phase 46
- [x] **CHIP-02**: Free Hit mode optimises for the current GW only from the full player pool; output is clearly labelled as this-GW-only / reverts next GW — Phase 46
- [x] **CHIP-03**: Bench Boost mode surfaces the optimised bench order with expected bench xPts, shown as a dedicated view — Phase 46

### Navigation (NAV)

- [x] **NAV-01**: Squad section gains sub-tabs (Transfers | Optimiser); MobileNav updated to show Squad sub-tab pills when Squad section is active — Phase 43

### xPts Accuracy (ACC)

- [x] **ACC-01**: A form/momentum signal is added to the pipeline: recency-weighted xG+xA over the last 3–5 GWs that surfaces in-form players alongside fixture-based xPts — Phase 42
- [x] **ACC-02**: Any new signal is backtested against the existing 5-GW accuracy pipeline (`compute_accuracy_backtest`) before being incorporated into xPts scoring — Phase 42
- [x] **ACC-03**: A new signal only ships if backtesting shows it improves hit rate above the current 16.7% baseline on the backtest window — Phase 42 (gate logic implemented; production validation pending live pipeline run)
- [x] **ACC-04**: Mid-tier scorer detection: the model reliably surfaces 6–8 pt scorers (clean sheet defenders, assist/bonus accumulators), not only 10+ point haulters — Phase 42 (mid-tier track added to accuracy backtest)

## Future Requirements (Deferred to v1.7+)

- **Standalone squad builder**: Budget-only squad construction from scratch (greedy over ~650 players within £100m, 3-per-club cap, positional quotas) — deferred to v1.7
- **Formation preference picker**: User locks a preferred formation before optimisation — deferred
- **Player locking**: User pins specific players as must-start before optimising — deferred
- **Captain swap what-if**: "What if my captain doesn't play?" simulation — deferred
- **Time-decay weighting on xG/xA**: Historical data weighted by recency beyond 3–5 GW window — deferred
- **Monte Carlo xPts simulation**: Stochastic simulation over point outcomes — explicitly anti-feature for v1.6 (latency cost, negligible accuracy gain over existing analytical model)
