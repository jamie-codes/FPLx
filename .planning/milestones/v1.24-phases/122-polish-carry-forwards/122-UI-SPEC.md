## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge gaps (`gap-1`), icon-to-text gaps |
| sm | 8px | Compact element spacing (`gap-2`, `px-2 py-1`) |
| md | 16px | Default element spacing (`px-4`, `gap-4`) |
| lg | 24px | Section padding (`space-y-4`, table cell padding `px-3 py-3`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- ChipToggle button min-height: 44px (touch target minimum, already established in `ChipToggle.tsx`)
- Badge pill padding: `px-2 py-1` (8px / 4px — established in `MinsRiskBadge.tsx`)

## Interaction Contract

### POL-01: ChipToggle State Wiring (RouteTreeTab)

- Replace hardcoded `chipMode = null` at line 90 with `const [chipMode, setChipMode] = useState<PlannerChip>(null)`
- Pass `activeChip={chipMode}` and `onToggle={(chip) => setChipMode(prev => prev === chip ? null : chip)}` to `<ChipToggle>`
- Remove `disabled={true}` — chip buttons become fully interactive
- Toggle-deselect: clicking the active chip again returns `chipMode` to `null` (same pattern as `ManualPlanTab.handleChipToggle`)
- All 4 chips enabled: wildcard, freehit, bboost, 3xc
- `aria-pressed` on each chip button — already handled by `ChipToggle.tsx`
- `aria-disabled` on the group wrapper — already handled by `ChipToggle.tsx`; once `disabled` prop is removed, `aria-disabled` resolves to `false` automatically

### POL-02: Column Label Fix (RouteTreeTab)

- Change `<th>` text from `"Hits"` to `"Transfer Hits"` at `RouteTreeTab.tsx:269`
- No style change, no layout change — text only

### POL-04: MinsRiskBadge in OpportunityCostTable

- Render `<MinsRiskBadge minsRisk={t.buy.mins_risk} />` after `<StatusLabelBadge>` in buy-player badge cluster
- `t.buy` is `ScoredPlayer` which already carries `mins_risk: MinsRisk` — no new prop drilling needed
- If `minsRisk` is `undefined` or `'injured'`, `MinsRiskBadge` returns `null` — no conditional wrapper needed
- `mins60Prob` prop is optional — omit it in this context (consistent with other surfaces that do not supply it)

### POL-03, POL-05, POL-06: Verification Only

- No interaction or visual changes — confirm existing badge/column renders in target surface
- Verification pass: visual inspection + relevant test assertions
