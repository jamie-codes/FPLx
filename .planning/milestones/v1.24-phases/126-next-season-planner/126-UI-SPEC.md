## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / player name | 14px (`text-sm`) | 400 regular | 1.5 |
| Label / section header | 10px (`text-[10px]`) | 600 semibold (`font-semibold`) | 1.2 |
| Heading (tab-level) | 20px (`text-xl`) | 600 semibold (`font-semibold`) | 1.2 |
| Cost / stat / mono data | 12px (`text-xs`) | 400 regular | 1.5 |

Typography rules:
- Player web_name: `text-sm font-semibold text-zinc-700 dark:text-zinc-300`
- Position section labels (GK / DEF / MID / FWD / Bench): `text-[10px] font-semibold uppercase text-zinc-500 dark:text-zinc-400`
- Cost and last-season points: `text-xs text-zinc-500 dark:text-zinc-400` with `font-variant-numeric: tabular-nums` (via `.tabular-nums` class or `[data-numeric]`)
- Section heading ("Pre-Season Squad", "GW1–8 Fixtures"): `text-xl font-semibold`
- Empty/graceful state copy: `text-sm text-zinc-500 dark:text-zinc-400`

Source: `ChipSquadView.tsx` (player row typography), `FixtureHeatMap.tsx` (section heading, heatmap header), `globals.css` (tabular-nums utility).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` — `#F7F8FC` light / `#0a0a0a` dark | Page background, tab surface |
| Secondary (30%) | `var(--surface)` — `#ffffff` light / `#111827` dark; `var(--surface-elevated)` — `#f3f4f6` light / `#1f2937` dark | Player card rows, section label backgrounds (`bg-zinc-50 dark:bg-zinc-800/40`) |
| Accent (10%) | `var(--color-primary)` — `#22c55e` (green) | Left border on starting XI player rows (`border-l-2 border-green-500`) only |
| Destructive | `var(--color-negative)` — `#ef4444` | Error state text (`text-red-600 dark:text-red-400`) only |

Accent reserved for: the 2px left border on starting XI (starters) player rows in the formation grid — identical to the ChipSquadView `border-l-2 border-green-500` treatment. Accent is NOT applied to bench rows, headings, CTAs, or empty states.

Semantic colors used in heatmap cells (inherited from HeatMapRow — do not modify):
- Easy fixture: `bg-green-100 text-green-800 dark:bg-green-900 dark:text-green-200`
- Medium fixture: `bg-amber-100 text-amber-800 dark:bg-amber-900 dark:text-amber-200`
- Hard fixture: `bg-red-100 text-red-800 dark:bg-red-900 dark:text-red-200`

Graceful state ("Prices pending", "Fixtures not yet published"):
- Text: `text-sm text-zinc-500 dark:text-zinc-400`
- No background color accent — plain muted text only

Bench rows opacity: `opacity-60` — matches ChipSquadView bench treatment exactly.

Source: `globals.css` (custom properties), `ChipSquadView.tsx` (XI border, bench opacity), `FixtureHeatMap.tsx` (TIER_CLASSES).

## Interaction Contract

### Tab Registration (NSP-04)
- Sub-tab ID: `'next-season'`
- Label: `"Next Season"` (desktop)
- mobileLabel: `"Pre-Season"` (mobile nav)
- Position: appended after `'rivals'` in Plan SECTIONS array
- Render condition: `activeSection === 'plan' && activeSubTab === 'next-season'`
- Source: `src/app/page.tsx` lines 80–88, Phase 125 `'window'` tab as exact pattern

### Read-only Formation Grid (D-04)
- No drag, swap, lock, or edit affordances
- No buttons on player rows
- Player rows are purely display — no hover state beyond native browser tooltip from `title` attribute

### Tooltip for Pts-Per-Minute (D-06)
- Implementation: native HTML `title` attribute on the total-points `<span>`
- Format: `title="X.Xpts/min (last season)"`
- No JS tooltip library — matches existing HeatMapRow and FixtureHeatMap `title` pattern

### Loading / Skeleton State
- Formation grid: display `<p className="text-zinc-500 dark:text-zinc-400">Loading pre-season squad...</p>` while `usePreSeasonSquad` is in loading state
- FDR heatmap: display `<p className="text-zinc-500 dark:text-zinc-400">Loading fixture data...</p>` while next-season fixture data is loading
- No skeleton components — matches `FixtureHeatMap` loading pattern exactly

### Formation Default
- Formation is determined by `buildPreSeasonSquad()` output — the greedy function returns a `formation` string (e.g. `"4-3-3"`, `"3-5-2"`)
- UI renders whichever formation the function returns; no UI override control in this phase
- Bench always shows 4 players: 1 GK-first, then 3 field players sorted by ppm desc

## States Required

The executor must implement all states below for both the formation grid and the FDR heatmap sections:

### Formation Grid (NSP-04)

| State | Trigger | UI Treatment |
|-------|---------|--------------|
| Loading | `usePreSeasonSquad.isLoading === true` | `<p>Loading pre-season squad...</p>` — muted text |
| Prices pending | `usePreSeasonSquad` returns `null` (404 from API) | Heading + body copy as per Copywriting Contract; muted text, no icon |
| Prices note | Archive present but FPL hasn't reset prices yet | Small `text-xs italic text-zinc-400` note below headline row |
| Data ready | `data` is non-null `PreSeasonSquad` | Full formation grid (GK/DEF/MID/FWD sections + Bench section) |
| Error | `usePreSeasonSquad.isError === true` | `<p className="text-sm text-red-600 dark:text-red-400">Failed to load pre-season squad. Check the pipeline output and refresh.</p>` |

### FDR Heatmap (NSP-03)

| State | Trigger | UI Treatment |
|-------|---------|--------------|
| Loading | Fixture data loading | `<p>Loading fixture data...</p>` — muted text |
| Fixtures not yet published | `fixtures.length === 0 \|\| fixtures.every(f => f.finished)` on next-season GW1-8 data | Heading + body copy as per Copywriting Contract; muted text |
| Data ready | Next-season fixture data present with at least one non-finished fixture | `HeatMapRow`-based table for GW1–8 — no ATT/DEF toggle, no horizon toggle in this phase (fixed 8 GW window) |
| Error | Fixture fetch error | `<p className="text-sm text-red-600 dark:text-red-400 py-4">Failed to load fixture data. Check the pipeline output and refresh.</p>` |

Note: The FDR heatmap in `NextSeasonPlannerTab` is a simplified read of `HeatMapRow` — no ATT/DEF toggle or horizon selector is needed (next-season data only covers GW1–8 at phase launch; toggles can be added in a future phase). This simplification reduces implementation scope while reusing the rendering primitive correctly.
