<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| useTransferNews → SummerWindowTab article rendering | Article `url`, `title`, `source`, `published`, `scraped_at`, and `classification` fields originate from the server-controlled Vercel Blob feed (`/api/transfer-news`). They cross into the browser and are rendered in `<a href>`, `<a>` text, `<span>` source badge text, and date paragraphs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-01 | Tampering (open redirect / tab-napping) | Article title `<a>` link in SummerWindowTab.tsx | mitigate | Every `<a>` rendering `article.url` carries both `target="_blank"` and `rel="noopener noreferrer"`. This blocks `window.opener` access from the destination and prevents tab-napping. The URL itself is sourced from the server-controlled Vercel Blob artifact (not user-supplied), so this is defense-in-depth. Test 10 asserts the rel attribute is present on every link. |
| T-125-02 | Tampering (XSS) | Article title `<a>` text and source badge `<span>` text | mitigate | React auto-escapes string interpolation into both element children and attribute values. SummerWindowTab uses only `{article.title}`, `{SOURCE_LABEL[...]}`, and `{formatRelativeTime(...)}` as React children — no `dangerouslySetInnerHTML` anywhere. Acceptance criteria explicitly grep the file for absence of `dangerouslySetInnerHTML`. |
</threat_model>
