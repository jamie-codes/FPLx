## Spacing Scale

The project uses Tailwind's default 4px-base spacing scale. All values below are multiples of 4. Tokens declared as the actual Tailwind classes the executor must use — no custom `tailwind.config` extensions required.

| Token | Value | Tailwind class | Usage in this panel |
|-------|-------|----------------|---------------------|
| xs | 4px | `gap-1`, `mb-1`, `space-y-1` | Inline icon/label gaps inside a pick card |
| sm | 8px | `gap-2`, `space-y-2`, `py-2`, `px-2` | Vertical rhythm between meta lines inside a card; badge padding |
| md | 12px | `gap-3`, `p-3`, `space-y-3` | Card grid `gap-3`; section vertical rhythm; card inner padding when content density is medium |
| md+ | 16px | `p-4`, `mb-4` | Pick card inner padding (preferred — matches `SetPieceTakerPanel` `p-3` upgraded to `p-4` for the larger captain card) |
| lg | 24px | `mt-6`, `mb-6` | Top margin separating the panel section from the `<GemTable />` above it |
| xl | 32px | `py-8` | Loading state vertical padding (matches `SetPieceTakerPanel.tsx:37`) |

**Locked classes (executor MUST use these literal strings):**

| Surface | Tailwind class string |
|---------|-----------------------|
| Section wrapper | `section className="mt-6 space-y-3"` |
| Section header inner | `space-y-1` (h2 + tagline) |
| Card grid | `grid grid-cols-1 sm:grid-cols-2 gap-3` |
| Pick card | `rounded border border-zinc-200 dark:border-zinc-700 bg-white dark:bg-zinc-900 p-4 space-y-2` |

| Loading state container | `text-center py-8` |
| Error state container | `py-4` |
| Same-player note (footer) | (no extra padding — inline `<p>` after the grid) |

**Exceptions:** none. Tailwind's `gap-1.5` (6px) is used in `CaptaincyPanel.tsx` but is NOT permitted in this panel — keep to the 4-multiples scale above for consistency with `SetPieceTakerPanel`.

| Role | Tailwind class | Computed | Weight | Line height | Usage |
|------|----------------|----------|--------|-------------|-------|

| Section tagline | `text-sm text-zinc-500 dark:text-zinc-400` | 14px | 400 | 1.5 | "Ceiling = chase rank. EO-Adjusted = protect rank." |
| Card label (Ceiling / EO-Adjusted) | `text-sm font-semibold` | 14px | 600 | 1.5 | Card `<h3>` — wraps native `title` tooltip |

## Color

Project uses Tailwind's `zinc-*` neutral scale + dark-mode parity for chrome, and named hue scales (green, amber, blue, violet, red) for semantic state — all hues exclusively from the `100/200`, `700/800`, `200/300`, `400/500`, `900` rails. No hex literals. The 60/30/10 split below maps cleanly onto the existing system.

| Role | Light token | Dark token | Tailwind class | Usage |
|------|-------------|-----------|----------------|-------|
| Dominant (60%) — page background | `white` (page) / `zinc-900` (dark) | (handled at root) | inherited from page | Body surface beneath the panel |
| Secondary (30%) — card surface | `bg-white` | `dark:bg-zinc-900` | `bg-white dark:bg-zinc-900` | Both pick cards (inverse of `SetPieceTakerPanel` pattern) |
| Secondary border | `zinc-200` | `zinc-700` | `border border-zinc-200 dark:border-zinc-700` | Pick card border |
| Muted text | `zinc-500` | `zinc-400` | `text-zinc-500 dark:text-zinc-400` | Tagline, meta line, percentile annotation, same-player note |
| Body text | (default zinc-900) | (default zinc-100) | inherit | Player name, xPts numbers, section heading |
| Accent (10%) — none reserved this phase | — | — | — | See note below |
| Destructive | `red-600` | `red-400` | `text-red-600 dark:text-red-400` | Error state copy ONLY |

**Accent reserved for:** **none in this phase.** This panel deliberately avoids hue accents on the pick cards. Rationale:
1. The two cards are equally weighted recommendations — using a hue on one (e.g. violet for ceiling, blue for EO) would imply a hierarchy that doesn't exist in the contract (D-02: two picks side-by-side).
2. The `VarianceBadge` (Phase 28) already owns violet (`bg-violet-100 dark:bg-violet-900`) for the "ceiling" semantic on a per-row basis in GemTable; reusing violet here would be a near-duplicate signal.
3. The `CaptaincyPanel` (Squad tab) already owns blue (`Safe`) and amber (`Upside`) for captain-type chips. Re-using either would create cross-tab semantic collision.

**Therefore:** Pick cards use only the neutral zinc surface + monochrome typography. The "Ceiling" vs "EO-Adjusted" distinction is carried entirely by the **label text + tooltip**, not by colour. This is consistent with `SetPieceTakerPanel`, which also uses no hue accents on its cards.

**Position chip:** plain `text-xs text-zinc-500 dark:text-zinc-400` text — NOT a coloured badge. Reason: position is identification metadata, not a signal.

**Forbidden:**
- No `bg-violet-*`, `bg-blue-*`, `bg-amber-*`, `bg-green-*`, `bg-red-*` on pick cards or their children.
- No gradient backgrounds, no shadows beyond Tailwind's defaults (do not add `shadow-md`/`shadow-lg`).
- No emoji glyphs in copy. (Unicode arrows are also out of scope this phase — distinction is textual.)

None in this phase. The panel is read-only; no buttons, no forms, no irreversible interactions. No confirmation dialogs required.

None in this phase. The panel surfaces information; the user acts on it elsewhere (FPL site or Planner tab).

## Interaction Contract

| Interaction | Behaviour | Source pattern |
|-------------|-----------|----------------|
| Hover on card label `<h3>` | Native `title` tooltip appears (browser default delay, no custom positioning) | `VarianceBadge.tsx:11`, `DifferentialBadge.tsx:23` |
| Hover on card body | No effect — cards are display-only | — |
| Click on card | No effect — no navigation, no modal, no expansion | — |
| Tab focus | Cards themselves are not focusable. The `<h3>` is not interactive — `title` is a hover-only affordance. (Acknowledged accessibility limitation, consistent with project convention; reconsider if/when a tooltip primitive is adopted project-wide.) | — |
| Loading → loaded transition | Replace loading paragraph with the section. No skeleton, no animation. | `SetPieceTakerPanel.tsx:36-37` |
| Error → loaded transition | Replace error paragraph with the section on next successful refetch. React Query 6h `staleTime` + manual page refresh trigger refetch. | `useSetPieces` pattern |
