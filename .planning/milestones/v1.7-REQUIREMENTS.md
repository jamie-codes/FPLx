## Validated Requirements

### Clean Sheet Probability

- [x] **CS-01**: User can see CS% per fixture for all GK/DEF-relevant teams, derived from rolling xGA (consistent with xPts model — same inputs as `cs_pts` in `xPts_components_1gw`) — **Phase 47, `cs_prob_1gw` in pipeline + GemTable Analysis column**
- [x] **CS-02**: CS% for DGW fixtures shows combined probability (formula: `1 - (1-p1)*(1-p2)`) so managers see the full double-gameweek opportunity — **Phase 47, pipeline/merge.py DGW aggregation**
- [x] **CS-03**: CS% is surfaced in a GK/DEF-oriented context (panel or column) — reduces need to cross-reference Club Form tab for defensive picks — **Phase 47, GemTable Analysis preset CS% column**

### Fixture Swing Detector

- [x] **SWG-01**: User can see teams with materially improving upcoming fixtures (buy signal), where swing is defined as `upcoming_3gw_ease - past_3gw_ease ≥ threshold` (threshold: 0.20) — **Phase 47, FixtureSwingDetector panel**
- [x] **SWG-02**: User can see teams with materially worsening upcoming fixtures (sell signal) — symmetric with SWG-01 — **Phase 47, FixtureSwingDetector panel (worsening section)**
- [x] **SWG-03**: Fixture swing view is toggleable across 1/3/5 GW windows (consistent with existing horizon controls) — **Phase 47, horizon pills in FixtureSwingDetector**
- [x] **SWG-04**: User's owned players from high-swing teams are highlighted, personalising the signal to their actual squad — **Phase 47, owned player row highlighting in FixtureSwingDetector**

### Player Lifecycle Labels

- [x] **LCL-01**: Squad players display a lifecycle label that extends beyond Buy/Hold/Sell — labels include: Buy Next Week, Hold One More, Sell Soon, Minutes Trap, Fixture Trap — **Phase 49, 7-label taxonomy in lifecycle-label.ts**
- [x] **LCL-02**: Labels are computed as a pure-TS function over existing `MergedPlayer` fields — no new pipeline data required — **Phase 49, `computeLifecycleLabel()` + `computeLifecycleLabels()`**
- [x] **LCL-03**: When multiple label conditions apply for a player, a priority hierarchy determines which label is shown (prevent conflicting labels) — **Phase 49, priority cascade: Minutes Trap > Fixture Trap > Buy Next Week > Hold One More > Sell Soon > Sell > Hold**

### Explainable xPts Breakdown

- [x] **XPT-01**: User can view a component-level breakdown of any player's `xPts_1gw` — components: appearance probability, goal contribution, assist contribution, clean sheet probability, bonus points, minutes risk modifier — **Phase 48, XPtsCell hover card (5 labeled rows + Total)**
- [x] **XPT-02**: Components displayed sum to the headline `xPts_1gw` value (±0.01 rounding tolerance) — **Phase 48, `sum(components)` rendered as Total row (not headline prop)**
- [x] **XPT-03**: Breakdown includes fixture-adjusted CS% (uses CS-01 data) so the CS component is grounded in the specific upcoming fixture — **Phase 48, `cs_pts` component from `xPts_components_1gw` (Phase 47 output)**
- [x] **XPT-04**: Breakdown is accessible without requiring authentication (public squad data is sufficient) — **Phase 48, hover card uses `usePlayers()` data only**

### Transfer Opportunity Cost Simulator

- [x] **OCS-01**: User can compare Roll / 1-FT / 2-FT / Hit options in a single table, each row showing xPts gain net of hit cost and per-GW break-even weeks — **Phase 50, OpportunityCostTable + `computeOpportunityCostRows()`**
- [x] **OCS-02**: Each option shows the specific player-in/player-out pair for 1-FT and 2-FT (grounds the comparison in real names) — **Phase 50, OCSRow.playerIn/playerOut fields**
- [x] **OCS-03**: Comparison table is toggleable across 1/3/5 GW horizons and updates all values accordingly — **Phase 50, GwToggle in OCS section header**
- [x] **OCS-04**: Simulator operates on user's actual squad (requires squad/team ID loaded); the Roll row explicitly shows 0 gain to make inaction cost visible — **Phase 50, Roll row with gain=0 always present when squad loaded**
- [x] **OCS-05**: Simulator respects current FT count (1 or 2) — options that incur a hit are labelled as such and show the 4pt cost deducted from net gain — **Phase 50, FtToggle + derivedFtCount + hit cost labelling**

### Weekly Decision Summary

- [x] **WDS-01**: User sees captain recommendation, transfer recommendation, chip timing flag, and risk flags on a single screen — no tab-hopping required — **Phase 51, DecisionSummaryTab (4 cards)**
- [x] **WDS-02**: Recommendations are presented in priority order: captain → transfer → chip timing → risks — **Phase 51, card ordering in DecisionSummaryTab**
- [x] **WDS-03**: Each recommendation carries a severity signal (High / Medium / Low) so the manager knows what to act on urgently — **Phase 51, `computeDecisionSeverity()` + SeverityBadge on each card**
- [x] **WDS-04**: Screen degrades gracefully when no squad is loaded — shows captain picks and chip timing cards; hides transfer and bench recommendations — **Phase 51, no-squad fallback with NoSquadPlaceholder**
- [x] **WDS-05**: DGW or BGW context flag is shown when the upcoming gameweek is a double or blank, affecting the relevance of chip recommendations — **Phase 51, DGW/BGW badges on Chip card; `isDGW`/`isBGW` wired into `computeDecisionSeverity`**

## Future Requirements (deferred from v1.7)

The following were explicitly deferred and remain candidates for future milestones:

- Lifecycle labels for all 600+ players in GemTable (not just squad) — increases scope; squad context sufficient for v1.7
- xPts breakdown for 3GW and 5GW horizons — pipeline extension needed; 1GW breakdown ships first
- AI/LLM-generated prose for Decision Summary — adds external dependency and hallucination risk; structured data sufficient
- Fixture swing notifications / alerts — no notification infrastructure in scope
- Automated chip activation — recommendation only; irreversible action out of scope
- Injury probability model for transfer simulator — data not available

## Out of Scope (maintained from v1.7)

| Exclusion | Reason |
|-----------|--------|
| Multi-week transfer sequence optimiser | Already exists in GW Planner (v1.3); do not duplicate |
| Mini-league or head-to-head analysis | PROJECT.md constraint |
| Live in-match CS% updates | Daily refresh is sufficient |
| Betting odds data feeds | External data source dependency; model inconsistency risk |
| Price rise/fall prediction labels | Requires transfer volume modelling; out of scope |
| Push notifications or deadline reminders | Web-only tool; no notification infrastructure |
