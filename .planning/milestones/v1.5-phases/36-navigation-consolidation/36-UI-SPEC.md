### State Model (Claude's Discretion — CONTEXT.md §Discretion)

Chosen: nested `{ section, subTab }` object replaces flat `activeTab`.

```typescript
// page.tsx state
const [activeSection, setActiveSection] = useState<Section>('analyse')
const [sectionMemory, setSectionMemory] = useState<Record<Section, SubTab | null>>({
  analyse: 'gems',
  plan: 'planner',
  squad: null,
})

// Derived active sub-tab
const activeSubTab = sectionMemory[activeSection]

// On section change
function handleSectionChange(section: Section) {
  setActiveSection(section)
  // sub-tab already in sectionMemory — no reset needed (D-05)
}

// On sub-tab change
function handleSubTabChange(subTab: SubTab) {
  setSectionMemory(prev => ({ ...prev, [activeSection]: subTab }))
}
```

Rationale: Nested state cleanly separates section from sub-tab memory without any lookup indirection. The existing flat `activeTab` string is replaced entirely. `MobileNav` props signature changes from `{ activeTab, onTabChange }` to `{ activeSection, activeSubTab, onSectionChange, onSubTabChange }`.

Source: CONTEXT.md §Code Context — "page.tsx owns activeTab state"; discretion granted for internal state shape.

## Accessibility Contract

- `aria-current="page"` on the active section button (both desktop and mobile).
- `aria-current="page"` on the active sub-tab button (desktop sub-tab row and mobile pill).
- Desktop section row: `<nav aria-label="Section navigation">` wrapper.
- Desktop sub-tab row: `<nav aria-label="{Section} sub-tabs">` wrapper.
- Mobile nav: existing `aria-label="Mobile navigation"` unchanged.
- All interactive nav buttons are `<button>` elements — no `<a>` tags (no URL routing change in this phase).
- Pill row is within the same `<nav>` as the mobile section bar (single nav landmark for mobile; screen reader announces both rows as one navigation region).

Source: CONTEXT.md §Code Context — "`aria-current='page'` on active tab button is the existing accessibility pattern — apply to both section and sub-tab buttons."
