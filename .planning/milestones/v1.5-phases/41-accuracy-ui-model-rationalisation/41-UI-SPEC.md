## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline cell padding |
| sm | 8px | Gap between controls, inter-row spacing |
| md | 16px | Horizontal page padding (`px-4`), cell padding in tables |
| lg | 24px | Section margin-bottom (`mb-6`), gap between stacked Accuracy sections |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Section heading bottom margin: `mb-2` (8px) — matches `InsightsTab.tsx` `h2 className="text-lg font-semibold mb-2"` pattern.
- Section top margin: `mt-6` (24px) — matches `InsightsTab.tsx` `section className="mt-6 space-y-6"` pattern.
- Inter-section gap on Accuracy tab: `space-y-8` (32px) between the three stacked sections.
- `py-0.5` (2px) — badge pill vertical padding; 4px (`py-1`) would double badge height at `text-xs` scale. Optical exception for pill badges only.

Source: `src/components/insights/InsightsTab.tsx` — canonical tab pattern for this codebase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff / #0a0a0a | Page background (white in light, near-black in dark) |
| Secondary (30%) | zinc-100/zinc-800 | Table row alternation, card/panel background |
| Accent (10%) | zinc-900 (light) / white (dark) | Flagged ✓ indicators; positive hit-rate badge text |
| Destructive | red-600 (light) / red-400 (dark) | Error state text only; NOT used for model removal action |

Accent reserved for: **flagged ✓ column cells** in the haulter list (xPts flagged / proj_pts flagged = true), and **hit-rate badges** when hit rate >= 50% (same green-100/green-800 treatment as InsightsTab HIGH tier). No other elements use accent fill.

**Focal point:** Primary visual anchor is the GW Accuracy Summary table — the aggregate hit-rate snapshot draws the eye first before the user drills into per-player detail in the sections below.

**Semantic colour map for hit-rate badges:**

| Hit-rate threshold | Light | Dark | Label |
|-------------------|-------|------|-------|
| >= 50% (HIGH) | `bg-green-100 text-green-800` | `bg-green-900 text-green-200` | HIGH |
| 30–49% (MEDIUM) | `bg-amber-100 text-amber-800` | `bg-amber-900 text-amber-200` | MEDIUM |
| < 30% (LOW) | `bg-zinc-100 text-zinc-600` | `bg-zinc-800 text-zinc-400` | LOW |

Source: `src/components/insights/InsightsTab.tsx` lines 7–10 (TIER_CLASSES — reuse verbatim).

**Flagged cell indicator:**
- `xpts_flagged = true` or `proj_pts_flagged = true`: render `✓` in `text-green-600 dark:text-green-400`
- Flagged = false: render `✗` in `text-zinc-400 dark:text-zinc-500`

**Delta column colour coding (player delta table):**
- xPts Δ or proj_pts Δ negative (over-prediction): `text-red-600 dark:text-red-400`
- Δ positive (under-prediction): `text-green-600 dark:text-green-400`
- Δ = 0: `text-zinc-500`

**GW{N} Pts column (GemTable):**
- Value present: plain cell, inherits table cell colour — no special treatment.
- Value null/missing: `—` in `text-zinc-400`.

Source: `src/components/gem-table/columns.tsx` line 17 (`fmtScoreNull` em-dash pattern); `InsightsTab.tsx` TIER_CLASSES.

**Nav wire-in:**

2. Haulter List (middle)

### Sub-Section 1 — GW Summary Table (ACC-02)

**Heading:** `<h2 className="text-lg font-semibold mb-2">GW Accuracy Summary</h2>`

**Table structure:**

| Column | Source field | Format |
|--------|-------------|--------|
| GW | `summary.gws[].gw` | Integer, "GW{N}" |
| Haulters | `summary.gws[].haulter_count` | Integer |
| xPts Flagged | `summary.gws[].xpts_flagged` | Integer |
| xPts Hit Rate | `summary.gws[].xpts_hit_rate` | Percentage, 1 decimal: "37.5%" |
| proj_pts Flagged | `summary.gws[].proj_pts_flagged` | Integer |
| proj_pts Hit Rate | `summary.gws[].proj_pts_hit_rate` | Percentage, 1 decimal: "25.0%" |

**Summary row:** A final row labelled "Overall" showing `summary.xpts_hit_rate` and `summary.proj_pts_hit_rate`. Visually distinct: `font-semibold bg-zinc-50 dark:bg-zinc-800`.

**Hit-rate cells:** Apply hit-rate badge colour (HIGH/MEDIUM/LOW from colour table above) to the hit-rate percentage values as inline badges: `<span className="inline-block text-xs rounded px-2 py-0.5 {tier_classes}">37.5%</span>`.

**Sort order:** GW descending (most recent first). No interactive sort on this table — it is a fixed 5-row summary.

**Table chrome:** `<table className="w-full text-sm border-collapse">` with `<th>` cells using `text-left font-semibold text-zinc-600 dark:text-zinc-400 pb-1 border-b border-zinc-200 dark:border-zinc-700`. Body rows: `even:bg-zinc-50 dark:even:bg-zinc-800/50`.

### Sub-Section 2 — Haulter List (ACC-03)

**Heading:** `<h2 className="text-lg font-semibold mb-2">Correctly Flagged Haulters</h2>`

**Definition:** A haulter is any player who actually scored 10+ pts in that GW (source: `haulters[]` in `accuracy_backtest.json`).

**Table structure:**

| Column | Source field | Format |
|--------|-------------|--------|
| Player | `haulters[].player_name` | String |
| GW | `haulters[].gw` | "GW{N}" |
| Actual Pts | `haulters[].actual_pts` | Integer |
| xPts Pred | `haulters[].xpts_predicted` | 1 decimal: "8.2" |
| xPts Rank | `haulters[].xpts_rank` | Integer |
| xPts | `haulters[].xpts_flagged` | ✓ or ✗ (see colour spec above) |
| proj_pts Pred | `haulters[].proj_pts_predicted` | 1 decimal: "6.1" |
| proj_pts Rank | `haulters[].proj_pts_rank` | Integer |
| proj_pts | `haulters[].proj_pts_flagged` | ✓ or ✗ |

**Sort order:** GW descending, then `actual_pts` descending within each GW (D-04). No interactive sort.

**Column header tooltips (title attribute):**
- xPts: "Model predicted this player would score 10+ points in this GW"
- proj_pts: "Projection model predicted this player would score 10+ points in this GW"
- xPts Rank: "Player's rank by xPts prediction in this GW (lower = higher predicted score)"
- proj_pts Rank: "Player's rank by proj_pts prediction in this GW"

**Pagination:** None. Show all rows. If the list exceeds 50 rows, the page scroll handles it — no artificial pagination. Source: D-05 (Claude's discretion — use existing GemTable patterns for consistency; GemTable renders all rows without pagination).

**Table chrome:** Same classes as GW Summary Table.

### Sub-Section 3 — Player Delta Table (ACC-04)

**Heading:** `<h2 className="text-lg font-semibold mb-2">Player Prediction Errors</h2>`

**Description text beneath heading:** `<p className="text-xs text-zinc-500 dark:text-zinc-400 mb-2">Sorted by biggest xPts over-prediction (most negative delta first). Click any column header to re-sort.</p>`

**Data shape:** Flatten `players[].gws[]` — each row represents one player × one GW.

**Table structure:**

| Column | Source field | Format | Sortable |
|--------|-------------|--------|---------|
| Player | `players[].player_name` | String | Yes |
| Team | `players[].team` | String | No |
| GW | `gws[].gw` | "GW{N}" | Yes |
| Actual Pts | `gws[].actual_pts` | Integer | Yes |
| xPts Pred | `gws[].xpts_predicted` | 1 decimal | Yes |
| xPts Δ | `gws[].xpts_delta` | Signed 1 decimal: "+2.1" / "-9.8" | Yes |
| proj_pts Pred | `gws[].proj_pts_predicted` | 1 decimal | Yes |
| proj_pts Δ | `gws[].proj_pts_delta` | Signed 1 decimal | Yes |

**Default sort:** xPts Δ ascending (most negative first — biggest over-prediction at the top). Source: D-05.

**Sort interaction:** Click any `<th>` to sort by that column. Second click on same column reverses direction. No visual sort icon beyond a CSS `cursor-pointer` on `<th>` cells. Active sort column header: `text-zinc-900 dark:text-white` (vs default `text-zinc-600 dark:text-zinc-400`).

**Delta formatting:** Render signed value. Positive deltas: prefix `+`. Apply delta colour coding from colour spec above.

**Pagination:** None — show all flattened rows (expected ~25–75 rows for a 5-GW backtest over ~5–15 haulters). Source: Claude's discretion — no pagination needed at this scale.

**Table chrome:** Same classes as GW Summary Table.

**Note on model rationalisation (ACC-06):** Both `xpts_*` and `proj_pts_*` columns are visible in this table until the human checkpoint in D-06 determines which model to remove. After removal (D-07), the loser's column pair (`{loser}_pred`, `{loser}_delta`) is deleted from this table along with the rest of that model's UI. The executor will determine which model loses at checkpoint time — this spec does not pre-decide.

### Surface 2 — GW{N} Pts Column in GemTable (ACC-05)

**Column id:** `last_gw_actual_pts`

**Column header:** `GW{N} Pts` where N = `accuracy_backtest.json gws_covered[0]` (most recent covered GW). Header renders as a static string computed once when data loads, e.g. "GW32 Pts". Apply hover tooltip: `title="Actual FPL points scored in GW{N} — from backtest data"`.

**Column position:** Immediately to the right of the surviving model's primary 1GW prediction column. Before ACC-06 removal: place after `xPts_1gw`. After removal: same position relative to whichever column survives.

**Cell format:**
- Value present (integer or float): display as integer, e.g. `Math.round(value).toString()` — actual FPL points are always whole numbers.
- Value null / player absent from backtest: render `—` (`&mdash;`) in `text-zinc-400`.

**Cell renderer pattern:** Follow `fmtScoreNull` convention from `columns.tsx` line 17.

**Preset visibility (D-10):**

Add `last_gw_actual_pts` to each preset's hidden-column map:

| Preset | Visible |
|--------|---------|
| default | **yes** — not in the hidden map |
| analysis | **yes** — not in the hidden map |
| compact | **no** — add `last_gw_actual_pts: false` to `PRESET_COLUMN_VISIBILITY.compact` in `GwToggle.tsx` |

No GW-horizon interaction — `last_gw_actual_pts` is not gated by the 1/3/5 GW toggle. It is a fixed historical column, always shown regardless of which horizon the toggle is set to.

**Data source (D-11):** The `/api/gems` route (or whichever route serves `merged_players.json` to GemTable) must join `accuracy_backtest.json players[]` keyed by `player_id` to add `last_gw_actual_pts` to each `ScoredPlayer` row. Null for players not in the backtest.

**Type update required:** Add `last_gw_actual_pts: number | null` to `ScoredPlayer` in `src/lib/types.ts`.

### Surface 3 — Human Checkpoint (ACC-06 / D-06)

This surface is terminal output only — no browser UI. The executor's checkpoint plan (Plan 03 or similar, `autonomous: false`) must:

1. Print a formatted summary to the terminal derived from `accuracy_backtest.json`:
   - Overall: `xPts hit rate: {X}% vs proj_pts hit rate: {Y}%`
   - Per-GW breakdown table (GW, xPts hit rate, proj_pts hit rate)
2. Prompt: `Which model do you want to REMOVE? [xpts/proj_pts]: `
3. Await user input. Proceed with removal only after explicit confirmation.

No browser-side UI for this checkpoint — it is a pipeline/build-time decision, not a runtime UI feature.

## Interaction Contract

### Accuracy Tab

| Interaction | Behaviour |
|-------------|-----------|
| Click "Accuracy" sub-tab | `AccuracyTab` mounts; triggers data fetch from `/api/accuracy` |
| Data loading | Show loading paragraph; no skeleton (matches InsightsTab) |
| Data fetch error | Show error paragraph with "run the pipeline and refresh" instruction |
| No data file yet | Show "No accuracy data yet" empty state |
| Click sortable column header (delta table) | Sort column toggles asc/desc; header text colour changes to active state |
| Click active column header again | Reverses sort direction |
| Scroll | Tab content scrolls within `main` — no sticky elements inside AccuracyTab |

### GW{N} Pts Column

| Interaction | Behaviour |
|-------------|-----------|
| Switch to Compact preset | Column hides (not in compact visibility map) |
| Switch to Default preset | Column shows |
| Switch to Analysis preset | Column shows |
| Change GW horizon toggle (1/3/5) | Column remains visible — not gated by horizon |
| Null cell | Renders `—`; no tooltip |
| Non-null cell | Renders integer; no tooltip (value is self-explanatory) |

### Accessibility

- `AccuracyTab`: Wrap in `<section aria-label="Projection accuracy">`.
- Table headings: `<th scope="col">` on all column headers.
- Sortable column headers: add `aria-sort="ascending"` or `"descending"` to active sort column; `aria-sort="none"` on inactive sortable columns.
- Flagged ✓/✗ cells: add `aria-label="Flagged: yes"` / `aria-label="Flagged: no"` to the cell.
- Sub-tab nav wire-in: inherits existing `aria-current="page"` pattern from `page.tsx` line 116.
