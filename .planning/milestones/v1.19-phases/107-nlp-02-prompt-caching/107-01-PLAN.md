| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-107-01 | Information Disclosure | `console.log('[player-insight] cache', {...})` log line | mitigate | Log payload contains only `attempt` (0 or 1) and two integer token counts from `msg.usage`. No player ID, no web_name, no prompt text, no API key, no PII. Player ID and web_name remain only in the existing 200-response body which is returned to the authenticated client (existing Phase 105 surface, unchanged). |
| T-107-02 | Tampering | `cache_control` block on system prompt | accept | `cache_control: { type: 'ephemeral' }` is a directive to Anthropic to cache the system prompt prefix server-side at Anthropic. It does not change prompt content, does not weaken the guardrail check (`passesGuardrail` still runs on every response), and does not bypass the two-attempt retry. Cached prompt is byte-identical to non-cached; an attacker cannot inject content via the cache. No mitigation needed beyond the existing guardrail. |
| T-107-03 | Denial of Service | Per-request Anthropic cost | accept | Caching REDUCES cost for repeated identical prefixes (cache-read pricing is ~0.1× input). At ~80 tokens the prompt is below the 1024-token cache minimum (D-01), so the cost profile is identical to Phase 105 until the prompt grows. The defence-in-depth Anthropic Console monthly spending cap from Phase 105 is unchanged and still applies. |
| T-107-04 | Repudiation | Cache log line in Vercel logs | accept | Vercel log retention and access control are unchanged. The `[player-insight] cache` prefix is grep-able by operators but contains no user-identifying data, so no repudiation surface is created. |
| T-107-05 | Elevation of Privilege | `as const` literal types | accept | `as const` is a compile-time TypeScript widening control; it does not affect runtime behavior or auth. The Anthropic SDK validates payload shape on its side. |
| T-107-06 | Spoofing | Anthropic API response `msg.usage` fields | mitigate | `msg.usage.cache_creation_input_tokens ?? 0` and `msg.usage.cache_read_input_tokens ?? 0` use null-coalescing to handle the SDK's `number | null` type. A malformed response (missing `usage`) would throw a TypeError on `.cache_creation_input_tokens` access, which would propagate to the existing `catch (err)` block at line 185 and trigger the 502 retry path — same behavior as today. Acceptance criterion on Task 1 ensures every test mock includes a well-formed `usage` object so the success path is exercised. |
