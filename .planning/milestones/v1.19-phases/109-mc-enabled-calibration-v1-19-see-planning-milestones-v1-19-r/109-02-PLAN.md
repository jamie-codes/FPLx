## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-04 | Tampering | data.summary.calibration_mode field value | mitigate | Component reads via `as CalibrationMode \| undefined` cast and renders only if the string is truthy. The `MODE_BADGE_CLASSES[calibrationMode]` lookup would return `undefined` for an unexpected string (e.g. `'malicious'`), which React renders as the empty class — no XSS surface because the value is interpolated into `className`, not into HTML. The `aria-label` template literal interpolates `MODE_BADGE_LABEL[calibrationMode]` which is also undefined for unexpected strings, producing `Calibration mode: undefined` text — degraded but safe. |
| T-109-05 | Information Disclosure | Mode badge text exposes calibration mode | accept | Mode label is operational metadata (which evidence path the app uses) — already implied by the existing tier badge and surfaced for transparency. No PII, no auth token, no client-side secret. |
| T-109-06 | Injection (XSS) | aria-label and badge text content | accept | `MODE_BADGE_LABEL[calibrationMode]` resolves to one of two hard-coded string literals ('MC' or 'Analytical'); not user input. React JSX text interpolation escapes by default. |

ASVS L1 categories applicable: V5 (Validation, Sanitization and Encoding) — covered by React's default text escaping; no inline HTML, no `dangerouslySetInnerHTML`.
