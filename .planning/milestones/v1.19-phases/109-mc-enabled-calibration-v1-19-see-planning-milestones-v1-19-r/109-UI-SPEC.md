## Component Specification

### CalibrationHealthIndicator — modifications

**File:** `src/components/squad/CalibrationHealthIndicator.tsx` (existing — modify)

**New imports / types:**
- No new imports required. `AccuracyBacktest` already imported from `@/lib/types`.
- `AccuracySummary` type (in `src/lib/types.ts`) must gain optional `calibration_mode?: 'mc' | 'analytical'` (handled in the types task, not the component task).

**New constant — `MODE_BADGE_CLASSES`:**

Add adjacent to `TIER_BADGE_CLASSES` (around line 11):

```ts
type CalibrationMode = 'mc' | 'analytical'

const MODE_BADGE_CLASSES: Record<CalibrationMode, string> = {
  mc: 'text-teal-700 dark:text-teal-400 bg-teal-100 dark:bg-teal-900',
  analytical: 'text-zinc-600 dark:text-zinc-400 bg-zinc-100 dark:bg-zinc-800',
}

const MODE_BADGE_LABEL: Record<CalibrationMode, string> = {
  mc: 'MC',
  analytical: 'Analytical',
}
```

**New read path:**
```ts
const calibrationMode = data.summary?.calibration_mode as CalibrationMode | undefined
```

**Bug fix — `maxDeviation` computation (CONTEXT.md D-11):**

Current (line 56):
```ts
const maxDeviation = Math.max(...buckets.map((b) => Math.abs(b.actual_rate - b.bucket_mid)))
```

Change to:
```ts
const maxDeviation = Math.max(...buckets.map((b) => Math.abs(b.actual_rate - b.predicted_rate)))
```

`predicted_rate` is already in the `CalibrationBucket` type (`src/lib/types.ts` lines 461–476). In analytical mode `predicted_rate === bucket_mid`, so this is behaviour-preserving in analytical mode and correct in MC mode where `predicted_rate = mean(haul_prob)` per bucket.

**New mode-badge render (CONTEXT.md D-08, D-09):**

In the non-cold-start branch (the existing tier-badge `<span>` block), insert a sibling `<span>` immediately AFTER the tier badge and BEFORE the status sentence:

```tsx
{calibrationMode && (
  <span
    aria-label={`Calibration mode: ${MODE_BADGE_LABEL[calibrationMode]}`}
    className={`text-xs font-semibold rounded px-2 py-0.5 ${MODE_BADGE_CLASSES[calibrationMode]}`}
  >
    {MODE_BADGE_LABEL[calibrationMode]}
  </span>
)}
```

**Null-render rule (CONTEXT.md D-09):**

When `data.summary?.calibration_mode` is `undefined` (legacy cache predating Phase 109), the mode badge MUST NOT render. The conditional above (`{calibrationMode && (...)}`) handles this. The rest of the row (label, tier badge, sentence) renders unchanged.

**Cold-start branch — no mode badge:**

The mode badge is NOT rendered in the cold-start branch (`data.gws_covered.length < 3`). The cold-start row layout (`"Model health"` label + cold-start sentence) is unchanged from Phase 103. The mode badge attaches only to the populated tier-badge row.

**Final flex order (non-cold-start, mode known):**

```
[Model health] [tier]   [MC|Analytical]   Calibration: tier — predicted vs actual within Npp across M deciles
```

Children inside the existing `<div role="status" className="flex items-center gap-3 ...">`:

1. `"Model health"` label span — unchanged
2. Tier badge span — unchanged (still uses `TIER_BADGE_CLASSES`)
3. **Mode badge span** — NEW, conditional on `calibrationMode` being defined
4. Status sentence span — unchanged

The existing `gap-3` (12px, Phase 103) provides consistent spacing between all four children. No new wrapper or sub-flex required.

**Placement in `DecisionSummaryTab.tsx`:** unchanged — the component is still rendered between the 4-card grid and `<ProseSummaryBlock>` (currently `DecisionSummaryTab.tsx:690`). No prop signature changes; `data` already carries `summary.calibration_mode`.

**Accessibility:**
- `role="status"` on outer wrapper — unchanged from Phase 103.
- `aria-label="Calibration mode: MC"` or `"Calibration mode: Analytical"` on the new mode badge — pattern matches the existing `aria-label="Calibration health: {tier}"` on the tier badge.
- Visible text inside the badge (`"MC"` / `"Analytical"`) is descriptive on its own; the aria-label is supplementary clarification for screen readers that may read `"MC"` as initials.

Copy rules specific to Phase 109:
- `"MC"` is always uppercase — it is a proper-noun acronym for Monte Carlo, treated the same way the codebase already treats `MC_ENABLED`, `MCDistributionBar`, `mc_enabled`, etc.
- `"Analytical"` is always Title Case (initial cap, lowercase remainder). Not `"analytical"` (case mismatch with `MC`) and not `"ANALYTICAL"` (visual noise — caps lock on long word).
- Mode badge labels are NEVER followed by punctuation. They appear standalone inside a coloured pill.
- The mode badge does NOT alter the status sentence. The sentence string is locked by Phase 103 D-11 and reused verbatim.

## Bug-Fix Risk Note

The one-line `maxDeviation` change from `b.bucket_mid` to `b.predicted_rate` (CONTEXT.md D-11) is behaviour-preserving in the analytical path (where `predicted_rate === bucket_mid`) and is corrective in the MC path (where `predicted_rate !== bucket_mid`). The change has no visual side-effects in the analytical path beyond fixing the tier calculation to use the canonical predicted-rate field that the rest of the calibration JSON already exposes.

Component tests should cover:
1. Mode badge renders teal `"MC"` when `summary.calibration_mode === 'mc'`.
2. Mode badge renders zinc `"Analytical"` when `summary.calibration_mode === 'analytical'`.
3. Mode badge does NOT render when `summary.calibration_mode` is undefined (legacy cache).
4. Mode badge does NOT render in the cold-start branch.
5. Tier badge classes for `good`/`fair`/`poor` are unchanged.
6. `aria-label` on the mode badge contains the human-readable mode name.
