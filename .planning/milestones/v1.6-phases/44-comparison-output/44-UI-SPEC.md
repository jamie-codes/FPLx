## Spacing Scale

Inherited from 43-UI-SPEC.md. Exceptions added for the comparison table:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding (`px-1`, `py-0.5`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`) |
| lg | 24px | Section padding (`space-y-6`, `mb-6`) |
| xl | 32px | Layout gaps between major blocks |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used in panel-level components) |

Exceptions:
- `border-l-2` (2px) — left accent border on changed rows. Presentational only, not layout spacing.
- `px-1` / `py-0.5` — delta pill and badge inline padding. Matches existing badge patterns (PlayerComparisonModal, DifferentialBadge).
- `py-1.5` (6px) — table data row cell padding. Half-step between 4px and 8px for compact table row density. Applied consistently to all `<td>` cells in the comparison table body.
- `mb-0.5` (2px) — mobile arrow element micro-spacing. Presentational only, not layout spacing.
- Touch targets: `min-h-[44px]` on GwToggle buttons — inherited from Phase 43, unchanged.

| Secondary surface (30%) | `bg-zinc-50` / `bg-zinc-100` | `dark:bg-zinc-800` | Table section header rows |
| Accent — active/selected (10%) | `bg-zinc-900` | `dark:bg-white` | Active horizon pill fill |
| Changed row left border | `border-green-500` | `border-green-500` (same) | 2px left accent on changed rows only |
| Delta pill background | `bg-green-950` | `bg-green-950` (same) | Changed row delta pill fill (starting XI) |
| Delta pill text | `text-green-400` | `text-green-400` (same) | `+X.X xPts` text in delta pill |
| **Promoted badge background** | `bg-green-100` | `dark:bg-green-950` | Bench slots where player is promoted |
| **Promoted badge text** | `text-green-700` | `dark:text-green-400` | "Promoted" label in bench changed slots |
| **Dropped badge background** | `bg-zinc-100` | `dark:bg-zinc-800` | Bench slots where player is dropped |
| **Dropped badge text** | `text-zinc-600` | `dark:text-zinc-400` | "Dropped" label in bench changed slots |
| Unchanged row | no border, no pill | no border, no pill | Plain — no accent |
| BGW amber warning | `text-amber-800` / `bg-amber-50` / `border-amber-400` | `dark:text-amber-200` / `dark:bg-amber-950` | Carried forward from Phase 43 |
| Destructive / error | `text-red-700` / `bg-red-50` / `border-red-300` | `dark:text-red-300` / `dark:bg-red-950` | Squad load error state only |

Color balance target: 60% dominant surface / 30% secondary surface / 10% accent.

Accent reserved for:
1. Active horizon selector button (1GW/3GW/5GW pill — `bg-zinc-900 dark:bg-white`)
2. Active sub-tab underline (`border-b-2 border-zinc-900 dark:border-white`)
3. Changed row left border (`border-l-2 border-green-500`) — comparison table only
4. Delta pill (`bg-green-950 text-green-400`) — comparison table only

The `bg-green-950` pitch background is removed. The `bg-green-950` delta pill background is a reuse of the same token in a new semantic context (dark green badge on white surface — readable).

## Phase-Specific Component Contracts

### 1. Headline Row (CMP-02, D-07)

**Source:** D-07, CONTEXT.md §specifics.

Rendered between the horizon selector and the comparison table. Single flex row.

```
<div className="flex items-center gap-2 text-sm text-zinc-700 dark:text-zinc-300 py-2">
  <span><span className="font-semibold">Formation:</span> {formation}</span>
  <span className="text-zinc-400">│</span>
  <span><span className="font-semibold">Changes:</span> {changeCount} {changeCount === 1 ? 'player' : 'players'}</span>
  <span className="text-zinc-400">│</span>
  <span className="font-semibold text-green-600 dark:text-green-400">+{xPtsGain.toFixed(1)} xPts gain</span>
</div>
```

- `changeCount`: count of starting-XI positions where current player ≠ optimised player (bench excluded from change count per D-06/D-07).
- `xPtsGain`: sum of `(optimisedXPts - currentXPts)` per changed starter slot where optimised > current. Bench excluded.
- Horizon selector sits above this row (carried from Phase 43 layout).

**Data row — unchanged:**

```
  <td className="py-1.5 text-zinc-700 dark:text-zinc-300">{optimisedPlayer.web_name}</td>
  <td className="text-right pr-2">{/* empty */}</td>
</tr>
```

**Data row — changed starter (starting XI):**
```
<tr className="border-b border-zinc-100 dark:border-zinc-800 border-l-2 border-l-green-500">
  <td className="py-1.5 pl-2 text-zinc-700 dark:text-zinc-300">{currentPlayer.web_name}</td>
  <td className="text-right text-zinc-500 dark:text-zinc-400 text-xs">{currentXPts.toFixed(1)}</td>
  <td className="text-center text-zinc-400">→</td>
  <td className="py-1.5 text-green-700 dark:text-green-400 font-semibold">{optimisedPlayer.web_name}</td>
  <td className="text-right pr-2">
    <span className="text-xs font-semibold text-green-400 bg-green-950 rounded px-1 py-0.5">
      +{delta.toFixed(1)} xPts
    </span>
  </td>
</tr>
```

Note: `border-l-2 border-l-green-500` applies the 2px left accent. In Tailwind v4 the `border-l-2` sets left border width and `border-l-green-500` sets the left border color. Both classes must be present.

**Data row — changed bench slot:**
```
<tr className="border-b border-zinc-100 dark:border-zinc-800 border-l-2 border-l-green-500 opacity-80">
  <td className="py-1.5 pl-2 text-zinc-500 dark:text-zinc-400">{currentPlayer.web_name}</td>
  <td className="text-right text-zinc-400 text-xs">{currentXPts.toFixed(1)}</td>
  <td className="text-center text-zinc-400">→</td>
  <td className="py-1.5 text-zinc-700 dark:text-zinc-300">{optimisedPlayer.web_name}</td>
  <td className="text-right pr-2">
    {isPromoted
      ? <span className="text-xs font-semibold text-green-700 dark:text-green-400 bg-green-100 dark:bg-green-950 rounded px-1 py-0.5">Promoted</span>
      : <span className="text-xs font-semibold text-zinc-600 dark:text-zinc-400 bg-zinc-100 dark:bg-zinc-800 rounded px-1 py-0.5">Dropped</span>
    }
  </td>
</tr>
```

`isPromoted` computation: `true` when the optimised player ID for that bench slot exists in `lineup.starters` (i.e. the optimised lineup moves that player into the starting XI). `false` (Dropped) when the optimised player ID for that bench slot does NOT exist in `lineup.starters` AND the player differs from the current bench occupant (i.e. a current starter is demoted to this bench slot in the optimised lineup).

A bench slot is "changed" when `currentBenchPlayerId !== optimisedBenchPlayerId`. If changed and `isPromoted=true`, show "Promoted" badge. If changed and `isPromoted=false`, show "Dropped" badge. Unchanged bench rows (same player ID) get no badge and follow the general unchanged row HTML — no additional `opacity` class on desktop; `opacity-60` on mobile as specified in §6.

### 4. "Current lineup" derivation (D-05)

**Source:** D-05. No new computation — uses existing `useSquad` hook output.

- Current starting XI: `SquadPick.position <= 11`
- Current bench: `SquadPick.position >= 12` (positions 12, 13, 14, 15)
- Sort bench by position ascending (12 → 15) to preserve FPL submission order.
- Each current slot is matched to the corresponding optimised slot by position group section + index within section.

Row pairing algorithm: pair by position order within each section:
- GK section: current GK starter vs optimised GK starter (always exactly 1 each)
- DEF section: sort both current DEF starters and optimised DEF starters by xPts descending; pair index-for-index
- MID section: same sort-and-pair
- FWD section: same sort-and-pair
- Bench section: current bench[0] (GK) vs optimised bench[0]; current bench[1–3] vs optimised bench[1–3] (engine order)

A row is "changed" when `currentPlayerId !== optimisedPlayerId` for that slot.
