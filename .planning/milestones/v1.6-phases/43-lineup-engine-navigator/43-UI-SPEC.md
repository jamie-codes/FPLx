## Spacing Scale

Declared values (multiples of 4, 4px base unit). Source: existing app Tailwind class audit.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding (`px-1`, `py-0.5`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`) |
| lg | 24px | Section padding (`space-y-6`, `mb-6`) |
| xl | 32px | Layout gaps between major blocks |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used in panel-level components) |

Exceptions:
- Touch targets (mobile nav buttons, horizon toggle buttons): minimum 44px height via `min-h-[44px]` — matches existing GwToggle.tsx pattern.
- Player circle diameter on pitch: 64px (`w-16 h-16`) to allow two lines of text (web_name + xPts).
- 1px (`w-px`) — bench divider line between GK slot and outfield bench slots. Presentational only, not layout spacing.
- 2px (`px-0.5`) — player circle text clearance (horizontal padding on web_name span inside circle). Presentational only, not layout spacing.

## Typography

Source: globals.css (`--font-sans: var(--font-geist-sans)`), existing component audit (text-xs/sm/base pattern).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Pitch micro-label (web_name, xPts, C/VC badges, GK bench label) | 10px (`text-[10px]`) | 400–600 (see note) | 1.0 |
| Label / badge / caption | 12px (`text-xs`) | 600 semibold | 1.4 |
| Body / table text | 14px (`text-sm`) | 400 regular | 1.5 |
| Subheading / panel title | 16px (`text-base`) | 600 semibold | 1.3 |

Note on 10px weight: web_name inside player circle uses `font-semibold` (600). xPts value below circle uses `font-normal` (400). (C) and (VC) badges use `font-semibold` (600). GK bench label uses `font-normal` (400). All resolve to exactly 2 weights: 400 (regular) and 600 (semibold).

Formation label ("Formation: 4-3-3") uses `text-sm font-semibold` (14px/600).

### 1. Sub-Tab Row Wiring (NAV-01)

**Source:** D-05 through D-10 from 43-CONTEXT.md. page.tsx current structure confirmed by codebase read.

#### SubTab Union Extension

```
// src/app/page.tsx — current
type SubTab = 'gems' | 'insights' | 'defcon' | 'set-pieces' | 'planner' | 'club-form' | 'value-gems' | 'accuracy'

// After Phase 43
type SubTab = 'gems' | 'insights' | 'defcon' | 'set-pieces' | 'planner' | 'club-form' | 'value-gems' | 'accuracy' | 'transfers' | 'optimiser'
```

#### SECTIONS Squad Entry Change

```

// After Phase 43
{
  id: 'squad',
  label: 'Squad',
  subTabs: [
    { id: 'transfers', label: 'Transfers', mobileLabel: 'Transfers' },
    { id: 'optimiser', label: 'Optimiser', mobileLabel: 'Optimiser' },

  defaultSubTab: 'transfers',
```

#### sectionMemory Initial State Change

```

// After
squad: 'transfers'
```

#### Desktop Sub-Tab Row Guard Change

Remove the `activeSection !== 'squad'` guard. Squad now renders the same sub-tab row nav as Analyse and Plan. The sub-tab row renders for ALL sections (Squad now has subTabs). The squad-specific spacer `<div className="mb-6 hidden sm:block" />` is removed.

#### Content Render Guards Change

```

// Add:

  <TransferPanel teamId={teamId} onTeamIdChange={setTeamId} />
```

#### MobileNav Squad Pill Row (D-10)

Remove the `activeSection !== 'squad'` guard in MobileNav.tsx. Squad now shows the pill row when active, identical to Analyse/Plan. The guard becomes unconditional — it renders the pill row for every section that has `subTabs.length > 0`.

Pill visual spec (matches existing MobileNav pill pattern):

### 2. Team ID State Lift (D-11)

**Source:** D-11, 43-CONTEXT.md.

State moved from TransferPanel's local `useState` to page.tsx:

```
// page.tsx — new state
const [teamId, setTeamId] = useState<string>(() =>
```

### 5. Pitch Layout (D-01, D-04)

**Source:** D-01, D-04, 43-CONTEXT.md §specifics, CONTEXT Claude's Discretion.

#### Pitch Container

```
// Outer pitch wrapper
<div className="relative rounded-lg overflow-hidden bg-green-950 p-4 min-h-[480px]">
  ...rows of player circles...
  ...bench row below...
</div>
```

- Background: `bg-green-950` (always, no dark: override — pitch is always dark green by FPL convention)
- Border radius: `rounded-lg`
- Padding: `p-4` (16px)
- Min height: `min-h-[480px]` to accommodate 4 rows of starters + bench

#### FPL Orientation

- GK row: bottom of pitch (last flex row inside pitch container)
- Defenders: second from bottom
- Midfielders: second from top
- Forwards: top row

CSS approach: flex column with `flex-col-reverse` OR explicit ordering via array sort. Recommended: render rows in order [FWD, MID, DEF, GK] top to bottom (forwards visually at top = top of DOM, GK at bottom = bottom of DOM). No `flex-col-reverse` needed — natural DOM order matches visual top-to-bottom.

#### Player Row Layout

Each row is a flex container centred horizontally:

```
<div className="flex justify-center gap-3 mb-3">
  {/* player circles */}
</div>
```

Gap between circles: `gap-3` (12px). Row bottom margin: `mb-3` (12px).

#### Player Circle Anatomy

```
<div className="flex flex-col items-center w-16">
  {/* Circle */}
  <div className="w-12 h-12 rounded-full bg-zinc-100 dark:bg-zinc-700 flex items-center justify-center relative">
    {/* Status dot — top right */}
    <span className="absolute top-0 right-0 w-2 h-2 rounded-full bg-green-500" />
    {/* Initials / web_name first 6 chars */}
    <span className="text-[10px] font-semibold text-zinc-900 dark:text-zinc-100 text-center leading-tight px-0.5 truncate max-w-[44px]">
      {web_name truncated to 6 chars}
    </span>
  </div>
  {/* xPts value */}
  <span className="text-[10px] text-green-300 mt-1">
    {xPts.toFixed(1)}
  </span>
  {/* C/VC badge — only shown when applicable */}
  {isCaptain && (
    <span className="text-[10px] font-semibold text-amber-400">(C)</span>
  )}
  {isVC && (
    <span className="text-[10px] font-semibold text-zinc-400">(VC)</span>
  )}
</div>
```

Specification details:
- Circle: `w-12 h-12` (48px) rounded-full. Fill: `bg-zinc-100 dark:bg-zinc-700`.
- web_name: truncated to 7 characters max with CSS `truncate` + `max-w-[44px]`. Font: `text-[10px] font-semibold` (600). Color: `text-zinc-900 dark:text-zinc-100`.
- xPts: shown below circle. Format: `{N.N}` (1 decimal place). Color: `text-green-300` (readable on green-950 background). Font: `text-[10px]` weight 400 (no font-weight class, inherits regular).
- (C) label: `text-[10px] font-semibold text-amber-400` — amber to match existing SquadView.tsx captain style.
- (VC) label: `text-[10px] font-semibold text-zinc-400` — matches existing SquadView.tsx VC style.
- Position label (GK/DEF/MID/FWD): not shown inside the circle. Position is implied by row placement on the pitch.
- Touch target wrapper: `w-16` (64px) total clickable width — adequate for finger tap.

### 6. Bench Row (D-04, OPT-04)

**Source:** D-04, OPT-04.

The bench is a horizontal row of 4 slots rendered below the pitch div, separated by a divider:

```
<div className="mt-3 pt-3 border-t border-green-900">
  <p className="text-xs font-semibold text-green-400 mb-2">Bench</p>
  <div className="flex justify-center gap-3">
    {/* Slot 0: GK bench — visually separated */}
    <div className="flex flex-col items-center">
      <span className="text-[10px] text-green-500 mb-1">GK</span>
      {/* player circle */}
    </div>
    {/* Slots 1-3: outfield bench — ordered xPts descending */}
    <div className="w-px bg-green-900 self-stretch mx-1" /> {/* divider between GK and outfield */}
    {benchOutfield.map((player, i) => (
      <div key={i} className="flex flex-col items-center">
        {/* player circle — same anatomy as starter but opacity-75 */}
      </div>
    ))}
  </div>
</div>
```

Bench slot visual differences vs starter circles:
- Opacity: `opacity-75` on bench player circles (visually de-emphasised vs starters).
- No (C)/(VC) badge on bench players.
- xPts shown in same format as starters.
- GK bench slot has a "GK" label above the circle in `text-[10px] text-green-500` (weight 400 — presentational label only).
- A 1px vertical divider (`w-px bg-green-900`) separates the GK bench slot from the 3 outfield bench slots.
- Bench section header: "Bench" in `text-xs font-semibold text-green-400`.

### 7. BGW Amber Banner (D-16, OPT-05)

**Source:** D-16, OPT-05, LastUpdated.tsx amber pattern.

Rendered above the pitch (after the formation/horizon row, before the pitch div). Shown only when `eligibleStarters < 11`.

```
<div className="rounded border border-amber-400 bg-amber-50 dark:bg-amber-950 px-3 py-2 text-sm text-amber-800 dark:text-amber-200 mb-3">
  <span className="font-semibold">Blank gameweek warning:</span>{' '}
  only {eligibleCount} of your players have a fixture this gameweek.
  {eligibleCount < 11 && (
    <> Fewer than 11 eligible starters — bench players may be required to fill the starting XI.</>
  )}
</div>
```

Color spec (exact class names, matching LastUpdated.tsx + TransferPanel.tsx amber pattern):
- Border: `border-amber-400`
- Background: `bg-amber-50 dark:bg-amber-950`
- Text: `text-amber-800 dark:text-amber-200`
- Bold prefix: `font-semibold`
- Placement: between the formation/horizon row and the pitch div, with `mb-3` below it.

Conditions:
- BGW proxy: `xPts_1gw === 0` (D-15). Players with `xPts_1gw === 0` are BGW-excluded from starting XI.
- Banner shown when: `eligibleStarters.length < 11` after BGW exclusion.
- Banner NOT shown when all 11+ starters have a fixture.

### 9. OptimiserPanel Component Structure
