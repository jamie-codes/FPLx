## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-09 | Spoofing | useMyTeam fetch | accept | Existing /api/fpl/my-team route validates session cookies upstream. Plan 45 only consumes the typed response. |
| T-45-10 | Tampering | client-side selling_price | accept | selling_price is read from the authenticated FPL response. Tampering with it via DevTools only affects the local user's optimiser display — no server impact, no privilege escalation. |
| T-45-11 | Information Disclosure | exactSellPrices Map in client memory | accept | Same data the user already sees on FPL's own /transfers page. No third-party exposure (Map is component-local). |
| T-45-12 | Denial of Service | useMemo recompute storm | mitigate | All memos have stable dep arrays: [squadData, playersData, lineup, horizon, ftCount, exactSellPrices]. Engine completes <10ms. ftCount toggle triggers single re-render + single engine run. |
| T-45-13 | Elevation of Privilege | useAuthStatus client trust | accept | useAuthStatus is advisory only — it gates whether to CALL useMyTeam, but the API route itself enforces auth. A malicious client setting `isAuthenticated: true` locally just causes a 401 fetch failure (and the engine falls back to now_cost). |
| T-45-14 | Information Disclosure | TransferSuggestion in DOM | accept | All values rendered (web_name, xPts gain, sell/buy IDs) are already public via the /api/players endpoint. No PII added. |
| T-45-15 | Repudiation | suggestTransfers as advisory engine | accept | The UI explicitly does NOT commit transfers to FPL — it is read-only advisory output. User commits transfers on FPL's own site. No repudiation surface. |
