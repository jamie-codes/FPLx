## v1 Requirements

### Monte Carlo Display

- [x] **MC-01**: User can see haul %, blank %, P10 pts, and P90 pts for any player in the xPts hover card via an `MCDistributionBar` component — requires `mc_enabled` gate activation in `accuracy_backtest.json`, `MC_ITERATIONS=10000` and `MC_SEED=42` in GitHub Actions env block, and workflow hygiene fixes (align `anthropic` Python pin to 0.98.1, add explicit numpy 2.2.3)
  - **Outcome:** Validated. `MC_ENABLED = True` constant in `pipeline/run.py`; `MCDistributionBar` teal fill track with P10/P90 labels and conditional amber Haul% ≥40% row. Replaced inline text rows in XPtsCell hover card.
- [x] **MC-02**: User can see P10/P90 pts range on the captain picks card to support Triple Captain and differential captaincy decisions
  - **Outcome:** Validated. Inline `· P10–P90` range span after pts (C) in `CaptainPicksPanel` CandidateRow (raw undoubled, muted zinc-400, gate-off silent).

### Calibration

- [x] **CAL-01**: GK/DEF calibration position tab no longer shows misleading miscalibration signals caused by sparse data — sparse-bucket threshold raised from `sample_n < 5` to `sample_n < 15` for GK/DEF and `sample_n < 8` for MID/FWD in `pipeline/accuracy.py`; chart hidden entirely if position pool total < 50 observations
  - **Outcome:** Validated. Python is now the single gate; TypeScript `sample_n >= 5` double-filters removed from `AccuracyTab`.
- [x] **CAL-02**: User can see a one-sentence calibration health summary on the Decision Summary tab, derived from existing `useAccuracy` data (no new fetch or pipeline work)
  - **Outcome:** Validated. `CalibrationHealthIndicator` component (good/fair/poor tiers, cold-start state, absent-guard) slotted between 4-card grid and `ProseSummaryBlock` in `DecisionSummaryTab`.

### Sensitivity & Rejection Explainer

- [x] **SENS-01**: User can see a fragility indicator on each transfer buy candidate in TransferPanel — robust = silent (no badge), fragile = small amber dot, knife_edge = amber pill — computed by `computeFragility` with `isTransfer: true` context
  - **Outcome:** Validated (FragilityBadge already wired in Phase 93; Phase 104 confirmed call-site complete).
- [x] **WHY-01**: User can expand a transfer sell candidate in TransferPanel to see the top-2 plain-English reasons why that player fell below the recommendation threshold (e.g. "xPts 4.2 < threshold 4.7"), computed by the existing `computeRejection` engine
  - **Outcome:** Validated. `computeRejection` called per `t.sell` in `PlayerMoveCell`; up to 4 reason lines always-visible below sell player name. Strong sells silent.

### Per-Player LLM Insights

- [x] **NLP-02**: User can request an on-demand AI-generated insight for any player from GemTable row expand or TransferPanel via an explicit "Get AI insight" button; insight is generated by `claude-haiku-4-5-20251001` grounded in structured player data (MC fields, rejection reasons, fragility tier); result cached per `(player_id, pipeline_run_date)` in localStorage and Vercel Blob (`player_insights/gw{N}/element_{id}.json`); never auto-generated on row mount; includes two-attempt name-whitelist guardrail with deterministic fallback to structured `reasons[]`
  - **Outcome:** Validated. 43/43 TDD tests GREEN. Human UAT approved (Vercel env + Anthropic cap confirmed).
