# Requirements — FPL Analyst v1.11 Insights & Infrastructure

**Milestone:** v1.11 Insights & Infrastructure
**Started:** 2026-05-04
**Status:** Planned

---

## v1 Requirements

### Natural Language Summaries (NLP)

- [ ] **NLP-01** User can read a weekly plain-English prose summary of the model's top recommendations — generated by Claude API using structured model output as context; no hallucinated player data (model output grounded, not invented)
- [ ] **NLP-02** User can regenerate the prose summary mid-week via a "Refresh summary" button; summary also updates automatically on each pipeline run

### Fixture Heat Map (HEAT)

- [ ] **HEAT-01** User can see a colour-coded fixture grid for all 20 PL teams across the next 8 GWs — green (easy), amber (medium), red (hard) using existing `attacking_difficulty` values
- [ ] **HEAT-02** DGW fixtures are visually highlighted (double-cell or badge); BGW teams show a blank/empty cell for that GW
- [ ] **HEAT-03** Heat map is scannable on a single screen without horizontal scrolling on desktop

### In-App Alert System (ALERT)

- [ ] **ALERT-01** User sees an in-app alert banner or notification badge when any of the following have changed since their last visit: a player price rose or fell, a player's injury/availability status changed, a set-piece taker assignment changed
- [ ] **ALERT-02** Alert banner shows a live countdown to the next GW deadline when a deadline is within 24 hours
- [ ] **ALERT-03** User can dismiss individual alerts; dismissed state persists across visits via localStorage

### Event-Based Pipeline Refresh (REFRESH)

- [ ] **REFRESH-01** User can load fresh data up to 6 hours before each GW deadline — pipeline runs on additional scheduled GitHub Actions triggers at 6h, 2h, and 30 minutes before each GW deadline
- [ ] **REFRESH-02** User can load post-deadline transfer data within 1 hour of each GW deadline passing — pipeline runs automatically after each deadline
- [ ] **REFRESH-03** When the pipeline has not refreshed within the expected window, the app shows a visible warning ("Last successful run: X ago") rather than silently serving stale data

### Post-GW Review (PGW)

- [ ] **PGW-01** After each gameweek settles, user can view an auto-generated GW review: points left on bench, their captain pick vs the optimal captain (points delta), their top scorer, and their GW score vs the top-10k template team
- [ ] **PGW-02** GW review data is written to Vercel Blob by the pipeline after each GW settles and served via a new `/api/gw-review` route

### Decision History & ROI (HIST)

- [ ] **HIST-01** User can log their actual decisions each GW (captain pick, transfers in/out, chip used if any) — stored to Vercel Blob keyed by team ID and GW number
- [ ] **HIST-02** User can view a cumulative Decision Report: captain hit rate (% of GWs where their captain outscored the vice-captain), transfer ROI (total xPts gained on bought players vs total scored by sold players at decision time), and hit break-even success rate

### Transfer Regret Backtester (BACK)

- [ ] **BACK-01** For each logged transfer in HIST-01, user can see a retrospective verdict: actual GW outcome (pts scored by player bought vs pts scored by player sold that GW) and a process grade (Good process = model ranked the buy above the sell at decision time, regardless of actual outcome)
- [ ] **BACK-02** Regret dashboard shows a 2×2 outcome matrix — Good process / Bad outcome, Good process / Good outcome, Bad process / Good outcome, Bad process / Bad outcome — with count and example transfers per quadrant

## Future Requirements (deferred)

- NLP-01 extension: section-by-section breakdown (captain paragraph, transfer paragraph, chip paragraph) rather than a single summary
- ALERT-01 extension: push notifications or email alerts via Resend (requires user opt-in and email infrastructure — deferred to later milestone)
- HIST-01 extension: automatic decision capture via FPL API (pull confirmed captain + transfers from `/api/my-team`) rather than manual entry
- BACK-01 extension: captain regret analysis (my captain vs optimal captain vs actual top scorer per GW)
- Chip features deferred to off-season build: FH-01 (Free Hit full-pool builder), WC-01 (Wildcard structure builder), BB-01 (Bench Boost readiness score), TC-01 (Triple Captain decision engine)

## LINEUP-01: Optimal Starting XI Recommendation

**Phase:** 72
**Priority:** High

Given the user's 15-player squad, recommend the starting XI and bench order that maximises total expected points within FPL formation rules. Show the result as an overridable team sheet.

**Acceptance criteria:**
- Solver respects FPL constraints: exactly 1 GK, 3–5 DEF, 2–5 MID, 1–3 FWD, total = 11
- Scores players by `xPts_1gw × start_prob`; selects the legal XI with highest total
- Bench ordered by same metric descending (best cover first)
- UI renders a team sheet; user can swap a benched player with a starter (position-compatible only)
- Requires squad to be loaded (disabled otherwise)

## Out of Scope

- Push notifications or email alerts (in-app only for v1.11)
- Multi-device sync for decision history beyond Vercel Blob (keyed by team ID — same device pattern as existing auth)
- LLM-generated player analysis beyond structured model output (hallucination risk)
- Real-time within-GW probability updates
