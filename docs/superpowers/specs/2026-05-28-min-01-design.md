# MIN-01: Minutes Confidence Engine — Design

## Goal

Surface three minutes-confidence signals in GemTable: upgrade the existing `mins_risk` badge to use the richer `sub_risk_label` classification (which adds a 'Sub risk' category for players who start but exit before 60 mins), and add two new sortable numeric columns — `Start%` (start probability) and `60+%` (probability of playing 60+ minutes when named in XI).

## Background

The pipeline already computes everything MIN-01 needs:

| Field | Where | Current UI exposure |
|---|---|---|
| `sub_risk_label` | `xmins.py` → `merge.py` | Not shown anywhere |
| `start_prob` | `xmins.py` → `merge.py` | xPts hover card only |
| `mins_60_prob` | `xmins.py` → `merge.py` | xPts hover card tooltip only |
| `mins_risk` | `xmins.py` → `merge.py` | GemTable badge (not sortable) |

`sub_risk_label` classifies as 'nailed' | 'sub_risk' | 'rotation_risk' | 'cameo' | 'injured'. It adds the crucial 'sub_risk' case — players who are likely to start but regularly exit before 60 minutes (and therefore cannot score clean-sheet or appearance bonus). This is the key gap `mins_risk` ('nailed' | 'likely_start' | 'rotation_risk' | 'cameo' | 'injured') cannot capture.

MIN-01 is a **surface** problem, not an algorithm problem. No pipeline changes are needed.

## Architecture

Five files changed:

| File | Action |
|------|--------|
| `src/components/shared/MinsRiskBadge.tsx` | Add 'sub_risk' badge config (orange); widen accepted type to `MinsRisk \| SubRiskLabel` |
| `src/components/gem-table/columns.tsx` | Switch `mins_risk` column to `sub_risk_label`; add `start_prob` and `mins_60_prob` inline accessor columns |

No pipeline changes. No new component files.

### Data flow

```
pipeline/xmins.py (already computes):
  sub_risk_label → 'nailed' | 'sub_risk' | 'rotation_risk' | 'cameo' | 'injured'
  start_prob     → 0.0–1.0
  mins_60_prob   → 0.0–1.0

columns.tsx:
  mins_risk col    → MinsRiskBadge(sub_risk_label)     [badge, display col, not sortable]
  start_prob col   → "{Math.round(v * 100)}%"           [accessor col, sortable]
  mins_60_prob col → "{Math.round(v * 100)}%"           [accessor col, sortable]
```

## Badge Upgrade

### `src/components/shared/MinsRiskBadge.tsx`

Add one entry to `BADGE_MAP`:

```typescript
sub_risk: {
  bg: 'bg-orange-100 dark:bg-orange-900',
  text: 'text-orange-800 dark:text-orange-200',
  label: 'Sub risk',
  title: 'Sub risk: likely to start but exits before 60 min',
},
```

Widen the `BADGE_MAP` key type from `Exclude<MinsRisk, 'injured'>` to `Exclude<MinsRisk | SubRiskLabel, 'injured'>`. Import `SubRiskLabel` from `@/lib/types`.

Update the function signature:

```typescript
export function MinsRiskBadge({
  minsRisk,
  mins60Prob,
}: {
  minsRisk: MinsRisk | SubRiskLabel | undefined
  mins60Prob?: number
})
```

`getMinsRiskConfig` and the `injured` null path remain unchanged. Existing consumers passing `mins_risk` (which includes 'likely_start' but not 'sub_risk') continue to work — 'likely_start' stays in `BADGE_MAP` for backward compatibility.

### `src/components/gem-table/columns.tsx`

Switch the `mins_risk` display column cell from `mins_risk` to `sub_risk_label`:

```typescript
// Before:
cell: ({ row }) => <MinsRiskBadge minsRisk={row.original.mins_risk} />

// After:
cell: ({ row }) => <MinsRiskBadge minsRisk={row.original.sub_risk_label} />
```

## Column Rendering

### `Start%` column

```typescript
col.accessor('start_prob', {
  header: H('Start%', 'Probability of starting the next match (0–100%). Based on last 10 GW start rate × availability.'),
  cell: (info) => {
    const v = info.getValue()
    if (v == null) return <span className="text-zinc-400">—</span>
    return <span className="text-zinc-100">{Math.round(v * 100)}%</span>
  },
  enableSorting: true,
}),
```

`0` is a valid value (player unlikely to start) — renders as `"0%"`, not em-dash. Only `null`/`undefined` renders `—`.

### `60+%` column

```typescript
col.accessor('mins_60_prob', {
  header: H('60+%', 'Probability of playing 60+ minutes when starting. Low = sub risk even when named in XI.'),
  cell: (info) => {
    const v = info.getValue()
    if (v == null) return <span className="text-zinc-400">—</span>
    return <span className="text-zinc-100">{Math.round(v * 100)}%</span>
  },
  enableSorting: true,
}),
```

Same null/zero handling as `Start%`. Both columns hidden on mobile and in compact preset.
