# BPS-01: Bonus Point Predictor — Design

## Goal

Enable the per-player bonus EV predictor (Phase 53 algorithm, currently gated OFF) and surface `bonus_ev` as a sortable numeric column in GemTable, with muted styling for players whose estimate is prior-based rather than data-driven.

## Background

Phase 53 built a shrinkage-estimated bonus predictor in `pipeline/bonus.py`: it computes a per-player expected bonus points per game start using `w * empirical_mean + (1-w) * prior` where `w = min(1, n/12)`. GK/DEF bonus is residualised against clean-sheet rate to avoid double-counting (Pitfall M3). The algorithm and its `run.py` / `merge.py` wiring are fully implemented but the gate (`bonus_predictor_enabled`) defaults to `False`. `bonus_ev` is used internally in xPts computation but is never written to the player output dict, so the frontend has no visibility into it.

BPS-01 hard-enables the gate and surfaces the signal.

## Architecture

Five files changed:

| File | Action |
|------|--------|
| `pipeline/run.py` | Hard-enable gate: `bonus_predictor_enabled = True` |
| `pipeline/merge.py` | Write `bonus_ev` and `bonus_source` onto each player dict |
| `src/lib/types.ts` | Add `bonus_ev?` and `bonus_source?` to `ScoredPlayer` |
| `src/components/gem-table/BonusEvCell.tsx` | New pure display component |
| `src/components/gem-table/columns.tsx` | Add Bonus EV column |

### Data flow

```
bonus.py → compute_bonus_predictions() → {bonus_ev, n_starts, source} per player
merge.py → writes bonus_ev + bonus_source onto player dict → merged_players.json
src/lib/types.ts → ScoredPlayer gains bonus_ev? / bonus_source?
columns.tsx → BonusEvCell renders value (muted for flat_default)
```

## Pipeline Changes

### `pipeline/run.py` (1 line)

```python
# Before
bonus_predictor_enabled = False  # Phase 53 BPS-01 — default OFF; flips ON after non-regression shadow run

# After
bonus_predictor_enabled = True   # Phase 53 BPS-01 — hard-enabled (BPS-01 implementation)
```

The `accuracy_backtest.json` read that follows can still override this value — the shadow-run path is preserved for future use.

### `pipeline/merge.py` (~3 lines)

In the player-building loop, after `player_bonus_ev` is resolved from `bonus_stats` (at line ~1047):

```python
player_bonus_source = bonus_stats[fpl_id].get('source') if bonus_stats and fpl_id in bonus_stats else None

# Write to player dict (new):
player['bonus_ev'] = player_bonus_ev        # float | None
player['bonus_source'] = player_bonus_source  # 'learned' | 'flat_default' | None
```

Both fields are `None` when `bonus_stats` is absent or the player is not in it.

## Frontend Changes

### `src/lib/types.ts`

Added to `ScoredPlayer`:

```typescript
bonus_ev?: number                           // Per-game bonus EV (shrinkage-estimated)
bonus_source?: 'learned' | 'flat_default'  // Data quality: learned from history vs. position prior
```

### `src/components/gem-table/BonusEvCell.tsx` (new)

```tsx
interface BonusEvCellProps {
  value: number | null | undefined
  source: 'learned' | 'flat_default' | null | undefined
}

export function BonusEvCell({ value, source }: BonusEvCellProps) {
  if (value == null) return <span className="text-zinc-400">—</span>
  const muted = source === 'flat_default'
  return (
    <span className={muted ? 'text-zinc-500' : 'text-zinc-100'}>
      {value.toFixed(2)}
    </span>
  )
}
```

`flat_default` → `text-zinc-500` (muted). Learned → `text-zinc-100` (normal body text). `null` source treated as learned. Null/missing value → em-dash.

### `src/components/gem-table/columns.tsx` (addition)

```typescript
import { BonusEvCell } from '@/components/gem-table/BonusEvCell'

// In createColumns:
col.accessor('bonus_ev', {
  header: H('Bonus EV', 'Expected bonus points per game start. Shrinkage-estimated from recent history — muted values use the position prior (insufficient data).'),
  cell: (info) => (
    <BonusEvCell
      value={info.getValue()}
      source={info.row.original.bonus_source}
    />
  ),
  enableSorting: true,
})
```

Sorts by raw `bonus_ev` value.

## Testing

### `pipeline/tests/test_merge_bonus.py` (additions)

- `merge_players` with `bonus_stats` containing a player → that player's dict has `bonus_ev` and `bonus_source` set correctly
- `merge_players` with `bonus_stats=None` → all players have `bonus_ev: None` and `bonus_source: None`
- `merge_players` with a player absent from `bonus_stats` → that player has `bonus_ev: None` and `bonus_source: None`

### `src/components/gem-table/BonusEvCell.test.tsx` (new)

- `value=0.72, source='learned'` → renders `"0.72"` with `text-zinc-100` class
- `value=0.70, source='flat_default'` → renders `"0.70"` with `text-zinc-500` class
- `value=null` → renders `"—"`, no numeric text
- `value=undefined` → renders `"—"`
- `value=0.30, source=null` → renders `"0.30"` with `text-zinc-100` (null source treated as learned)

### `src/components/gem-table/columns.test.tsx` (addition)

- `createColumns` called with a player having `bonus_ev=0.85, bonus_source='learned'` → Bonus EV cell renders `"0.85"`
